# 알고리즘 학습 대시보드

## 기준선

- 언어: Java
- 과거 수준: 백준 Gold 1
- 현재 체감 수준: 프로그래머스 Lv.2 초반
- 목표: 12주 동안 국내 백엔드 코딩테스트 실력 회복 및 유형 정복
- 빈도: 월요일~토요일, 하루 2문제
- 시작일: 첫 실제 풀이 기록일

## 누적 지표

- 총 풀이 수: 10 (평가 확정 10, 동일 문제 재도전 1회 포함)
- 첫 시도 성공률: 75% (6/8, `주식가격` 1건 미확인)
- 목표 시간 달성률: 50% (5/10)
- 실제 풀이 시간 중앙값: 30분
- 힌트·해설 의존률: 30% (3/10)
- 인식 실패: 2
- 설계 실패: 2
- 구현 실패: 3
- 시간 관리 실패: 5
- A등급: 1문제 (10%)
- B등급: 7문제 (70%)
- C등급: 2문제 (20%)
- 출제 의도 알고리즘 사전 인식률: 100% (1/1)
- Codex 목표 알고리즘 사전 인식률: 100% (1/1)
- 유효한 대안 풀이 비율: 100% (2/2)
- 의도 알고리즘 보완 완료율: 75% (3/4, `다리를 지나는 트럭` 독립 재현 완료·`주식가격` 예정)

등급 분포만으로 실력을 평가하지 않습니다. 첫 시도 성공률, 목표 시간 달성률, 힌트·해설 의존률, 오류 유형과 D+7 변형 문제 전이 성공률을 함께 평가합니다.

## 지표 산정 기준

- 첫 시도 성공률: 신규 문제 중 첫 공식 제출이 통과한 문제 수 / 신규 문제 수
- 목표 시간 달성률: 성공하면서 실제 풀이 시간이 목표 시간 이하인 문제 수 / 실제 풀이 시간이 기록된 문제 수
- 힌트·해설 의존률: 작은 힌트·핵심 힌트·해설·정답 코드를 하나라도 사용한 문제 수 / 전체 풀이 수
- 오류 유형 비율: 해당 오류가 기록된 문제 수 / 전체 풀이 수. 한 문제에 여러 오류가 있으면 각 오류에 모두 반영합니다.
- D+7 변형 전이 성공률: 핵심 힌트·해설·정답 코드 없이 성공한 D+7 변형 수 / 실제로 풀이한 D+7 변형 수
- 같은 실수 재발률: 과거에 기록된 동일 오류가 다시 발생한 문제 수 / 이전 오류 이력이 있는 문제 수
- 출제 의도 알고리즘 사전 인식률: Codex 피드백 전에 작성한 추측이 공식 의도와 일치한 문제 수 / 공식 의도가 명시되고 추측이 기록된 문제 수
- Codex 목표 알고리즘 사전 인식률: Codex 피드백 전에 작성한 추측이 Codex 목표와 일치한 문제 수 / 목표가 정해지고 추측이 기록된 문제 수
- 유효한 대안 풀이 비율: 의도와 다른 알고리즘 중 정확하고 제한을 충분히 만족한 문제 수 / 의도와 다른 알고리즘으로 푼 문제 수
- 의도 알고리즘 보완 완료율: 설명·의사코드·변형 문제 등 지정된 보완을 완료한 문제 수 / 보완이 필요하다고 판정된 문제 수

## 유형별 현황

- 공식 해시 유형: 3문제, 성공 3, 첫 제출 성공 2
- 해시·조합 직접 적용: 1문제, 풀이 시간 23분
- 정렬 유효 대안 적용: 2문제, 풀이 시간 30분·36분
- 접두사·문자열: 1문제, 성공 1, 작은 힌트 사용, 첫 제출 런타임 오류 1회
- 스택·큐·순서 처리: 1문제, 성공 1, 첫 제출 성공 1, 풀이 시간 25분
- 해시·슬라이딩 윈도우: 1문제, 성공 1, 첫 제출 성공 1, 풀이 시간 40분
- 큐·이벤트 시뮬레이션: 2회, 최초 독립 설계 실패·정답 코드 참고 1회, 재도전 독립 성공 1회, 재도전 30분·10분 설계 확정·첫 제출 통과
- 큐·우선순위·상태 추적: 1문제, 성공 1, 첫 제출 성공 1, 목표 시간 달성, 풀이 시간 20분, 정확성 불변식 설명 보완 필요
- 단조 스택·인덱스 상태: 1문제, 독립 설계 실패 1, 정답 코드 학습 후 제출 통과, 풀이 시간 60분
- 스택·접두사 불변식: 1문제, 성공 1, 첫 제출 성공 1, 목표 시간 달성, 풀이 시간 10분, 정수 카운터 `O(1)` 공간 대안 학습

## 최근 평가

총 10회 풀이 기록 중 8회는 독립적으로 최종 성공했습니다. `다리를 지나는 트럭`은 최초 C등급 이후 이전 코드·해설을 보지 않고 10분 만에 `(무게, 출차 시각)` 큐 설계를 다시 만들어 30분에 첫 제출로 통과했습니다. 시간·이벤트 상태 설계는 독립 재현 단계로 개선됐지만 빈 큐 `peek()` 오류와 지연 제거 상태의 정확성 설명은 보완해야 합니다. `올바른 괄호`도 10분에 통과했으므로 현재 강점은 입력 제한으로 허용 복잡도를 판단하고 필요한 상태를 빠르게 구현하는 능력입니다. 우선 보완점은 ① 복잡도와 정답성 불변식을 분리해 설명하기, ② 큐 연산 전 빈 상태 확인하기, ③ `오른쪽의 첫 조건 만족 위치` 문제에서 현재 값이 과거 후보를 확정하는 역방향 관점 떠올리기입니다. 10월 2일 `주식가격` 재도전으로 단조 스택 독립 재현 여부를 확인합니다.
