# 알고리즘 학습 프로젝트 인수인계

이 문서는 기존 Codex 대화에서 합의한 알고리즘 학습 계획과 운영 방식을 새 Codex 작업에서도 동일하게 이어가기 위한 기준 문서다.

새 작업에서는 먼저 다음 파일을 읽는다.

1. `algorithm-study/CONTEXT.md`
2. `algorithm-study/AGENTS.md`
3. `algorithm-study/dashboard.md`
4. `algorithm-study/metrics.csv`

## 1. 학습자 정보와 목표

- 준비 분야: 국내 백엔드 개발자 채용 코딩테스트
- 사용 언어: Java
- 과거 수준: 백준 Gold 1
- 현재 체감 수준: 긴 공백 이후 프로그래머스 Lv.2 초반
- 목표 기간: 12주
- 학습 빈도: 월요일~토요일, 주 6일
- 하루 학습량: 정확히 2문제
- 일요일: 휴식
- 핵심 목표: 문제 수를 늘리는 것보다 유형 인식, 설계, 구현 정확도와 풀이 속도를 빠르게 회복한다.

## 2. 역할 분담

### ChatGPT 예약 작업

- 매주 월요일~토요일 오전 7시 30분, `Asia/Seoul` 기준으로 아이폰 알림을 보낸다.
- 매일 문제 2개와 5~10분 분량의 짧은 복습을 제공한다.
- 문제 페이지 접근 가능 여부와 직접 링크를 확인한다.
- 최신 `[Codex 학습 요약]`을 다음 추천과 난이도 조절에 반영한다.
- 상세 회고 작성, 노션 문서 생성, 장기 지표 계산은 하지 않는다.

### Codex

- 이 Git 저장소에서 Java 코드와 회고 문서를 관리한다.
- 문제 파일을 준비할 때 문제 난이도·유형·구현량과 학습자의 최근 지표를 반영해 문제별 목표 풀이 시간을 정한다.
- 코드, 회고, 시간, 결과와 복습 이력을 함께 분석한다.
- 객관적 지표와 대시보드를 갱신한다.
- D+1·D+3·D+7 및 실패 문제 재도전 일정을 관리한다.
- 매일 ChatGPT에 전달할 짧은 `[Codex 학습 요약]`을 만든다.
- 매주 누적 기록을 바탕으로 주간 실력 평가를 작성한다.

### 사용자

- ChatGPT 알림에서 오늘의 문제와 복습 항목을 확인한다.
- `review.md`의 단계별 시간과 경량 접근 항목을 보며 문제를 푼다.
- Java 코드를 이 저장소의 날짜별 문제 폴더에 저장한다.
- 풀이 전 핵심 기록과 풀이 후 결과를 해당 문제의 `review.md`에 짧게 작성하고 Codex에 완료를 알린다.
- Codex가 만든 `[Codex 학습 요약]`만 ChatGPT 예약 작업 대화에 붙여 넣는다.

## 3. 문제 추천 원칙

- 하루 총 문제는 2개로 유지한다.
- 일반적으로 1번은 복습 또는 핵심 유형, 2번은 같은 주제의 응용이나 한 단계 어려운 문제로 구성한다.
- 실패했거나 해설을 본 문제는 2~3일 뒤 2문제 중 하나로 재편성한다.
- 백준은 현재 추천 대상에서 제외한다.
- 플랫폼 우선순위는 프로그래머스, LeetCode, 코드트리, SW Expert Academy 순이다.
- 신규 문제는 중복 추천하지 않고, 명시적인 재도전일 때만 같은 문제를 다시 제시한다.
- 정답, 핵심 풀이법과 사용할 알고리즘을 문제 추천 단계에서 직접 노출하지 않는다.
- 힌트 요청 시 정답 코드가 아닌 다음 사고를 유도하는 최소 힌트부터 제공한다.

각 추천 문제에는 다음을 포함한다.

- 플랫폼과 난이도
- 알고리즘을 노출하지 않는 추천 이유
- 목표 풀이 시간
- 풀이 전 확인할 질문 2~3개

핵심 유형, 공식 출제 의도와 Codex 목표 알고리즘은 풀이 완료 후 기록한다. 풀이 전에 이를 알려주면 사실상 힌트가 되는 경우가 있으므로 보이는 문서에 미리 채우지 않는다.

## 4. 12주 진도

- 1~2주: Java 코딩테스트 문법 복구, 구현, 문자열, 해시, 정렬, 스택, 큐, 힙
- 3~4주: 완전탐색, 백트래킹, BFS, DFS
- 5~6주: 누적합, 투 포인터, 슬라이딩 윈도우, 그리디, 이분 탐색
- 7~8주: 기본 DP, 다익스트라, Union-Find, 위상정렬
- 9~10주: 프로그래머스 Lv.2 풀이 속도 향상, Lv.3 입문, 혼합 유형
- 11~12주: 기업형 실전 세트, 취약 유형 보완

매주 토요일에는 그 주의 유형을 섞은 2문제 실전 세트로 진행하고 전체 제한 시간을 기록한다.

첫 실제 풀이 날짜를 12주 과정의 Day 1로 사용한다. 미리보기나 설정 확인은 진도에 포함하지 않는다.

## 5. 문제 접근 순서

문제를 풀 때 다음 순서를 따른다.

1. 문제를 내 말로 한 문장으로 재정의한다.
2. 입력 크기, 값 범위와 제한사항을 확인한다.
3. 허용 가능한 목표 시간복잡도를 추정한다.
4. 작은 예제를 손으로 따라간다.
5. 가장 단순한 풀이와 그 시간복잡도를 적는다.
6. 단순 풀이의 병목과 반복 계산을 찾는다.
7. 알고리즘과 자료구조 후보를 근거와 함께 비교한다.
8. 선택한 알고리즘에 맞게 입력을 어떤 순서로 처리해 답을 만드는지 풀이 흐름을 정리한다. DP의 상태·점화식, 그래프의 방문·이동, 그리디의 선택 기준처럼 필요한 세부 요소는 유형에 맞게 사용한다.
9. 정답을 보장하는 이유를 확인한다.
10. 엣지 케이스와 직접 만든 반례를 점검한다.
11. 의사코드를 작성한 뒤 Java로 구현한다.

최소한 문제 정의, 목표 복잡도, 단순 풀이의 병목, 알고리즘 선택 근거, 풀이 흐름, 정확성 근거와 엣지 케이스는 구현 전에 확인한다.

### 초기 경량 기록 방식

- 처음부터 과도하게 문서화해 학습 지속성을 해치지 않도록, 사용자는 `review.md`에 각 항목을 한두 문장으로만 작성한다.
- 풀이 전 필수 기록은 `문제 한 문장`, `제한과 목표 복잡도`, `단순 풀이와 병목`, `선택한 접근과 이유`, `풀이 흐름`, `정확성 근거와 핵심 엣지 케이스`다.
- 출제 의도 알고리즘 추측은 선택 항목이며, 기록하려면 Codex 피드백 전에 작성한다.
- 풀이 후에는 실제 풀이 시간, 제외 시간, 결과, 제출 결과, 힌트 수준, 설계 확정 시간, 구현 실수와 막힌 지점·배운 점만 기록한다.
- 상세 복잡도 분석, 공식·추천 의도 비교, 오류 분류, 등급, 복습 일정과 대시보드 지표는 Codex가 코드와 사용자 기록을 바탕으로 작성한다.
- 템플릿의 예시 답변은 작성 형식을 익히기 위한 참고이며 새 문제의 답으로 복사하지 않는다. 사용자가 익숙해지면 예시를 생략할 수 있다.

### 목표 시간 배분

- 1단계 문제 이해·제한 확인: 목표 시간의 20%
- 2단계 단순 풀이·병목 찾기: 목표 시간의 20%
- 3단계 접근 선택·풀이 흐름·정확성 확인: 목표 시간의 20%
- 4단계 Java 구현: 목표 시간의 25%
- 5단계 예제·엣지 케이스 검증 및 제출: 목표 시간의 15%
- Codex는 문제 파일을 만들 때 비율을 분 단위로 반올림하고 합계가 목표 시간과 같도록 마지막 단계를 조정해 `review.md`에 채운다.
- 목표 시간의 60% 시점까지 접근을 확정하고 구현을 시작하며, 85% 시점에는 검증과 제출 단계로 넘어간다.

## 6. 반복 복습 규칙

정답 여부만으로 복습 강도를 정하지 않고 풀이의 안정성을 A·B·C로 분류한다.

### A등급: 안정적으로 성공

- 조건: 목표 시간 안에 성공, 힌트·해설 없음, 알고리즘 선택 근거가 명확하고 중대한 구현 실수나 반복적인 오답 제출이 없음. 모든 조건을 만족해야 한다.
- D+1: 생략
- D+3: 핵심 신호·복잡도·엣지 케이스를 2~3분 회상
- D+7: 핵심 유형이거나 최근 취약 유형일 때만 새로운 변형 문제 풀이
- 동일 문제 재도전: 하지 않음

### B등급: 성공했지만 불안정

- 조건: 성공했지만 목표 시간을 크게 초과, 접근을 오래 헤맴, 구현 실수나 오답 제출, 작은 힌트 확인, 또는 알고리즘 선택 근거나 정확성 설명이 불명확한 항목 중 하나 이상에 해당함
- D+1: 사용한 알고리즘에 맞는 핵심 구조·풀이 흐름·정답 조건 설명
- D+3: 핵심 신호·알고리즘·복잡도·엣지 케이스 회상
- D+7: 같은 유형의 새로운 변형 문제 풀이
- 동일 문제 재도전: 중대한 구현 실수가 있었을 때 추가 가능

### C등급: 실패 또는 해설 확인

- 조건: 실패·부분 성공, 핵심 힌트나 해설 확인, 정답 코드 참고, 또는 유형을 알았더라도 상태나 설계를 완성하지 못한 항목 중 하나 이상에 해당함
- 2~3일 뒤: 동일 문제를 정답 코드 없이 처음부터 재도전
- 재도전 후 D+7: 같은 유형의 새로운 변형 문제 풀이
- 같은 실패가 반복되면 더 쉬운 문제로 유형을 다시 학습

### 공통 운영 규칙

- 동일 문제 재도전과 D+7 변형은 오늘의 2문제 안에 포함한다.
- 문제 2개 외의 짧은 회상 복습은 하루 최대 2개, 총 5~10분으로 제한한다.
- 우선순위: C등급 재도전 → B·C등급 D+7 변형 → B등급 D+3 → B등급 D+1 → A등급 D+3
- 맞힌 문제를 모두 동일 문제로 다시 풀게 하지 않는다. A등급은 동일 문제를 재도전하지 않고 짧은 회상과 필요한 변형 문제로만 복습한다.
- 등급 판단에 필요한 정보가 부족하거나 모호하면 임의로 판정하지 않는다. 누락된 질문을 한 번에 모아 사용자에게 확인한 뒤 등급을 확정한다.

### 객관적 판정 기준

- 실제 풀이 시간은 문제를 처음 읽은 시점부터 제출 성공 또는 풀이 종료까지의 경과 시간에서 1분 이상의 휴식, IDE·환경 설정과 다른 용무 시간을 뺀 값이다. 제외 시간이 있으면 분 단위로 별도 기록한다.
- 목표 시간 달성은 성공한 문제의 실제 풀이 시간이 목표 시간 이하일 때만 인정한다. 목표 시간을 넘긴 성공은 A등급이 될 수 없으며, C등급 사유가 없으면 B등급으로 판정한다.
- 큰 시간 초과는 초과분이 `목표 시간의 25%`와 `10분` 중 더 큰 값 이상인 경우다. 큰 시간 초과에는 시간 관리 오류를 기록한다. 그보다 작은 초과도 B등급이지만 시간 관리 오류는 다른 증거와 함께 판단한다.
- 첫 시도 성공은 신규 문제의 첫 공식 제출이 채점 통과한 경우다. 제출하지 못했거나 첫 공식 제출이 오답·시간 초과·런타임 오류·컴파일 오류이면 첫 시도 성공이 아니다.
- 오답 제출 횟수는 첫 통과 전 공식 제출에서 오답·시간 초과·런타임 오류·컴파일 오류가 난 횟수다. 로컬 실행 실패는 오답 제출 수에 넣지 않고 구현 실수에 기록한다.
- 구현 실수는 로컬 또는 제출 과정에서 확인된 인덱스·조건·자료형·API·초기화·엣지 케이스 오류다. 핵심 흐름이나 자료구조를 다시 작성했거나 오답·예외를 유발했다면 중대한 구현 실수로 기록한다. 단순 타이핑 실수를 실행 전에 바로 고친 경우는 제외한다.
- 접근을 오래 헤맨 경우는 구현 가능한 설계를 잡기 전에 목표 시간의 50% 이상을 사용했거나, 근거 없이 완성된 접근을 두 번 이상 폐기한 경우다.
- 힌트 수준은 `없음 / 작은 힌트 / 핵심 힌트 / 해설 / 정답 코드`로 기록한다. 작은 힌트는 알고리즘·상태·핵심 식을 직접 알려주지 않는 다음 사고 유도이며 B등급 사유다. 알고리즘·자료구조·상태·핵심 식을 알려주면 핵심 힌트로 보고 C등급으로 판정한다. 해설 또는 정답 코드 확인도 C등급이다.
- 알고리즘 선택 근거는 입력 신호와 제한, 단순 풀이의 병목, 선택한 알고리즘이 제한을 만족하는 이유를 설명할 수 있을 때 명확한 것으로 본다.
- 정확성 설명은 사용한 알고리즘에 맞는 근거를 제시해야 한다. 예를 들어 DP는 상태·점화식·초기값, 그래프 탐색은 방문·이동·종료 조건, 그리디는 선택의 안전성, 이분 탐색은 판정 조건과 범위 축소, 일반 반복은 핵심 불변식과 반환 조건을 설명하고 중요한 엣지 케이스를 확인한다.
- A등급 조건을 모두 충족하지 못한 성공 문제는 C등급 사유가 없는 한 B등급으로 판정한다. 따라서 A·B·C 사이에 미분류 구간을 두지 않는다.
- D+7 변형 전이 성공은 연결된 원본과 같은 핵심 유형의 처음 보는 문제를 핵심 힌트·해설·정답 코드 없이 성공한 경우다. 작은 힌트를 사용한 성공은 별도로 기록하되 전이 성공률의 성공 건수에는 포함하지 않는다.

### 출제 의도와 실제 풀이 비교

- 정답 안정성 A·B·C 등급과 출제 의도 알고리즘 학습 여부는 분리해서 평가한다. 공식·추천 의도와 다른 방법을 사용했다는 사실만으로 등급을 낮추지 않는다.
- Codex는 문제를 추천할 때 목표 알고리즘을 정할 수 있지만 풀이 전에는 공식 출제 의도와 Codex 목표 알고리즘을 사용자에게 노출하거나 보이는 `review.md`에 미리 채우지 않는다.
- 사용자는 풀이 직후 Codex의 설명을 보기 전에 `실제 사용 알고리즘`과 `출제 의도라고 생각한 알고리즘`을 작성한다.
- 풀이가 끝난 뒤 Codex는 `공식 출제 의도 알고리즘`, `Codex 추천 목표 알고리즘`, 실제 사용 알고리즘을 비교한다. 플랫폼이 의도를 명시하지 않았다면 추측하지 않고 `공식 의도 명시 없음`으로 기록한다.
- 공식 의도 일치 여부와 Codex 목표 일치 여부를 각각 `일치 / 유효한 대안 / 보완 필요 / 의도·목표 명시 없음`으로 기록한다.
- 의도와 같고 근거가 명확하면 추가 학습을 하지 않는다.
- 다른 방법이지만 정확하고 제한을 충분히 만족하면 유효한 대안으로 인정하고, 의도 알고리즘의 핵심 신호와 복잡도만 3~5분 확인한다.
- 정답이지만 현재 진도의 핵심 유형을 놓쳤다면 의도 알고리즘의 의사코드와 예제 추적을 짧은 복습에 추가한다.
- 현재 방법이 제한에 간신히 통과하거나 의도 알고리즘보다 뚜렷하게 비효율적이면 D+3에 두 방법을 비교하고, 핵심 유형 또는 최근 취약 유형이라면 D+7에 새로운 변형 문제를 편성한다.
- 현재 방법이 제한을 만족하지 못하면 결과와 A·B·C 기준에 따라 판정하고 해당 유형을 다시 학습한다.
- A등급 문제는 의도와 다른 유효한 대안으로 풀었더라도 동일 문제를 다시 구현하지 않는다. 필요한 학습은 짧은 설명·의사코드 또는 D+7의 새 변형으로 진행한다.
- 대안 학습 상태는 `불필요 / 설명 필요 / 의사코드 필요 / 변형 문제 필요 / 완료`로 기록한다.

## 7. 실패 분류와 다음 추천

- 인식 실패: 적절한 알고리즘이나 자료구조를 떠올리지 못함
  - 같은 유형의 쉬운 변형을 우선 추천한다.
- 설계 실패: 유형은 알았지만 상태, 점화식 또는 자료구조 설계를 잘못함
  - 상태 정의 연습 문제를 우선 추천한다.
- 구현 실패: 인덱스, 조건문, 자료형, Java API 또는 엣지 케이스 실수
  - 비슷한 난이도의 정확성 중심 문제를 우선 추천한다.
- 시간 관리 실패: 올바른 방향으로 접근했지만 제한시간 운영에 실패함
  - 같은 난이도의 시간 제한 연습과 중단 기준을 적용한다.

정답률만으로 실력 향상을 판단하지 않는다. 유형 인식, 설계 정확도, 구현 안정성, 풀이 속도와 새로운 변형으로의 전이를 함께 평가한다.

### 프로그래머스 문제 파일 사전 생성

- 사용자가 당일 프로그래머스 문제명과 링크를 전달하면 풀이 전에 `algorithm-study/daily/YYYY-MM-DD/문제명/` 폴더를 생성한다.
- 문제 폴더에 프로그래머스 초기 `solution` 메서드 시그니처를 가진 `문제명.java`와 미작성 `review.md`를 둔다.
- `review.md`는 Codex가 미리 채우는 문제 정보·시간 배분, 사용자가 짧게 채우는 풀이 전 핵심 기록·풀이 후 결과, Codex가 기록을 마무리하는 분석으로 구분한다.
- 사용자는 풀이 전 핵심 여섯 항목을 각 한두 문장으로 쓰고, 풀이 후에는 시간·결과·제출·힌트·설계 확정 시간·구현 실수·막힌 점만 기록한다.
- Java 파일은 문제명의 공백을 밑줄로 바꾼 파일명과 동일한 `public class 문제명`을 사용하고, 상단에 `// 프로그래머스 Lv.N` 형식의 난이도 주석과 로컬 실행용 `main` 메서드를 둔다.
- `main`에는 문제에 공개된 입출력 예시를 호출하는 코드만 넣고, 정답·알고리즘·힌트는 미리 작성하지 않는다.
- Codex가 현재 체감 실력, 해당 문제의 레벨·유형·구현량, 1번·2번 문제의 역할, 최근 성공률·중앙 풀이 시간·실패 유형을 종합해 목표 시간을 정하고 `review.md`에 미리 기록한다.
- Codex는 목표 시간을 문제 이해·제한 20%, 단순 풀이·병목 20%, 접근 선택·풀이 흐름·정확성 20%, 구현 25%, 검증·제출 15%로 나눠 단계별 분량과 누적 종료 시점을 `review.md`에 미리 기록한다.
- 목표 시간은 문제를 처음 읽기 시작한 시점부터 제출 성공까지로 측정하며, 누적 결과에 따라 5분 단위로 조정한다.
- IntelliJ에서는 `algorithm-study` Java 모듈 하나만 사용하고, 새 문제 폴더를 `.idea/algorithm-study.iml`의 소스 루트로 추가한다. 모듈은 프로젝트 SDK `temurin-21`을 상속한다.
- 같은 문제 폴더나 파일이 이미 존재하면 덮어쓰거나 수정하지 않고 사용자에게 알린다.
- ChatGPT 예약 작업과 Codex는 자동 동기화되지 않으므로 사용자가 문제명과 링크를 Codex에도 전달해야 한다.

## 9. 매일 필요한 정보

사용자가 직접 작성할 최소 정보는 다음과 같다.

- 풀이 전: 문제 한 문장, 제한과 목표 복잡도, 단순 풀이와 병목, 선택한 접근과 이유, 이 문제에 맞는 풀이 흐름, 정확성 근거와 핵심 엣지 케이스
- 풀이 후: 실제 풀이 시간과 제외 시간, 성공 여부, 제출 결과와 오답 횟수, 힌트 수준, 설계 확정 시간, 구현 실수, 막힌 지점·배운 점
- 선택 정보: Codex 피드백 전 출제 의도 알고리즘 추측

문제명·링크·난이도·목표 시간·풀이 구분·코드 경로와 상세 분석은 Codex가 관리한다. 코드나 작성된 내용으로 확인 가능한 사항을 사용자에게 다시 묻지 않는다.

등급 판정이나 객관 지표 계산에 반드시 필요한 정보가 빠졌거나 모호할 때만 추측하지 않고 누락 질문을 한 번에 모아 확인한다. 선택 항목이나 Codex가 분석할 항목의 빈칸만으로 기록 완료를 막지 않는다.

## 10. Codex의 일일 처리 절차

1. 해당 날짜의 Java 코드와 사용자 회고를 확인한다.
2. 필수 정보가 모두 있는지 검사한다.
3. 누락되거나 모호한 정보를 사용자에게 한 번에 질문한다.
4. 사용자 답변을 받은 뒤 문제별 `review.md`를 완성한다.
5. 사용자가 피드백 전에 작성한 의도 알고리즘 추측과 실제 사용 알고리즘을 확인한다.
6. 공식 출제 의도·Codex 목표·실제 풀이를 비교하고 필요한 대안 학습을 정한다.
7. 각 문제를 A·B·C로 판정하고 판정 근거를 기록한다.
8. `metrics.csv`에 문제별 정량 정보를 추가한다.
9. `dashboard.md`의 누적 지표와 취약 유형을 갱신한다.
10. 등급과 의도 알고리즘 학습 상태에 따라 D+1·D+3·D+7 및 재도전 일정을 갱신한다.
11. 사용자에게 당일 피드백을 제공한다.
12. 날짜 폴더의 `README.md`에 당일 결과·평가·복습 일정과 ChatGPT 전달용 `[Codex 학습 요약]`을 기록한다.

사용자가 요청하지 않는 한 Java 원본 코드는 수정하지 않는다. 사용자 회고 원문과 Codex의 분석은 문서에서 명확하게 분리한다.

## 11. 객관적 평가 지표

- 총 풀이 수
- 첫 시도 성공률
- 목표 시간 달성률
- 실제 풀이 시간 중앙값
- 힌트·해설 의존률
- 인식·설계·구현·시간 관리 실패 비율
- 유형별 성공률과 풀이 시간
- D+3 재구현 성공률
- D+7 변형 문제 전이 성공률
- 같은 실수의 재발률
- A·B·C 등급별 누적 문제 수와 비율
- 출제 의도 알고리즘 사전 인식률
- Codex 목표 알고리즘 사전 인식률
- 유효한 대안 풀이 비율
- 의도 알고리즘 보완 완료율

등급 분포만으로 실력을 평가하지 않는다. 첫 시도 성공률, 목표 시간 달성률, 힌트·해설 의존률, 오류 유형과 D+7 변형 문제 전이 성공률을 함께 평가한다.

매주 6회 학습이 끝나면 다음을 포함한 주간 평가를 작성한다.

- 가장 향상된 유형
- 가장 취약한 유형
- 반복된 실패 원인
- 지난주 대비 변화
- 다음 주 우선 보완 항목
- 난이도 유지·상향·하향 의견

## 13. 자동화 상태

- ChatGPT의 `백엔드 코딩테스트 매일 2문제` 예약 작업이 아이폰 알림과 문제 추천을 담당한다.
- 기존 Codex 자동화는 중복 알림 방지를 위해 일시 정지 상태로 유지한다.
- ChatGPT와 Codex의 기록은 자동 동기화되지 않으므로 `[Codex 학습 요약]`을 사용자가 직접 전달한다.

## 14. 새 Codex 작업 시작 문구

새 로컬 프로젝트 작업에서는 다음과 같이 시작한다.

```text
algorithm-study/CONTEXT.md와 algorithm-study/AGENTS.md를 모두 읽고, 기존 알고리즘 학습 관리 작업을 이어가 줘. 필요한 정보가 빠졌다면 추측하지 말고 나에게 한 번에 질문해 줘.
```
