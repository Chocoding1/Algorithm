# Algorithm Study

Codex는 월요일~금요일에는 알고리즘 2문제와 SQL 1문제, 일요일에는 알고리즘 3문제 120분 실전 세트와 SQL 주간 혼합 1문제를 오전 7시 30분에 추천합니다. 토요일은 고정 휴식일이며, 이 폴더에서 Java·SQL 코드, 회고, 지표와 복습 일정을 함께 관리합니다.

## 날짜별 저장 구조

```text
daily/
└── YYYY-MM-DD/
    ├── README.md
    ├── problem-1/
    │   ├── 문제명.java
    │   └── review.md
    ├── problem-2/
    │   ├── 문제명.java
    │   └── review.md
    └── sql/
        └── 문제명/
            ├── solution.sql
            └── review.md
```

문제 폴더는 문제 제목을 사용하고, Java 파일명과 `public class`는 문제명의 공백을 밑줄로 바꾼 동일한 이름을 사용합니다. 기존 플랫폼별 코드 위치를 계속 사용하고 싶다면 `review.md`에 원본 코드 경로를 기록합니다.

## 매일 사용 방법

1. 사용자에게 문제명과 링크를 받으면 Codex가 날짜별 문제 폴더(평일 알고리즘 2문제, 일요일 실전 3문제, SQL 1문제), 초기 코드, `review.md`, 목표 시간과 단계별 시간 배분을 준비합니다.
2. 풀이 전에는 공식 출제 의도·핵심 유형·Codex 목표 알고리즘을 공개하지 않습니다. 추천 이유와 질문에도 특정 자료구조나 알고리즘을 암시하지 않습니다.
3. 사용자는 `review.md`에 문제와 제한·목표 복잡도, 단순 풀이와 병목, 확정한 설계와 처리 흐름, 정답 근거와 핵심 엣지 케이스를 각각 한두 문장으로 적습니다.
4. 사용자가 알고리즘은 Java로 구현해 로컬 예제 실행과 플랫폼 제출을 하고, SQL은 MySQL로 작성해 플랫폼에서 실행·제출한 뒤 시간·결과·제출·오류 기록을 짧게 적습니다. 힌트 수준은 Codex가 실제 대화 내용을 기준으로 판정합니다.
5. 사용자가 `문제 풀었어` 또는 `오늘 기록해 줘`라고 알리면 Codex가 코드와 회고를 확인합니다. 코드나 기록으로 알 수 없는 필수 정보만 한 번에 질문합니다.
6. Codex가 풀이 전 메모와 제출 코드를 비교해 잘 이어진 사고와 놓친 신호를 찾고, 정답성·복잡도를 검증합니다.
7. 문제 의도와 다른 알고리즘, 더 나은 복잡도·자료구조·Java API·안전성 개선 중 중요한 학습점 1~3개를 풀이 직후 원리와 함께 가르칩니다. 코드만 제시하지 않고 왜 동작하는지, 현재 풀이와 무엇이 다른지, 다음에 어떤 신호로 떠올릴지까지 설명합니다.
8. 새로 배운 내용은 `review.md`에 기록하고 D+1·D+3·D+7 복습에 연결합니다. D+3에는 처음 설명하는 대신 이미 배운 접근을 코드 없이 회상·비교합니다.
9. Codex가 A/B/C 등급을 판정하고 `metrics.csv`, `dashboard.md`, 복습 일정과 `[Codex 학습 요약]`을 갱신합니다.
10. `[Codex 학습 요약]`은 인수인계 기록으로 저장하며, 예약 작업은 저장소를 직접 읽으므로 별도 대화에 복사하지 않습니다.

사용자 기록은 지속성을 위해 짧게 유지하고, 상세 분석과 장기 지표 관리는 Codex가 담당합니다. 사용자가 요청하지 않는 한 Java 원본 코드는 수정하지 않습니다.

## 주요 파일

- `dashboard.md`: 누적 실력과 취약 유형
- `metrics.csv`: 알고리즘 문제별 정량 기록
- `sql-metrics.csv`: SQL 문제별 정량 기록
- `weekly/`: 주간 평가
- `templates/`: 회고와 ChatGPT 동기화 양식
- `SQL_PLAN.md`: SQL 4주 입문 계획과 운영 기준
