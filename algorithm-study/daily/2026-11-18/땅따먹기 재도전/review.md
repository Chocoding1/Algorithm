## Codex 분석

- 힌트 수준(Codex 판정): 작은 힌트 — 반례를 요청했고, Codex가 현재 코드에서 상태 인덱스가 어긋나는 줄과 `temp[j]`에 저장해야 하는 이유를 알려줌. 핵심 DP 상태와 반복 구조는 사용자가 독립 설계함
- 복습 등급: B
- 등급 판정 근거: 이전 코드·회고 없이 7분에 DP 설계를 확정하고 목표 30분 안인 20분에 최종 통과했다. 다만 첫 제출에서 이전 열 `k`와 현재 도착 열 `j`를 혼동해 모든 테스트가 실패했고, 반례와 오류 위치에 대한 작은 힌트를 받은 뒤 수정했으므로 독립 재현이 완전히 안정적이지는 않다.
- 목표 시간 달성: 달성 — 20분 / 30분
- 첫 시도 성공: 대상 아님 — 동일 문제 재도전
- 풀이 전 사고와 실제 코드의 차이: 이전 행 결과를 복사한 별도 배열에 현재 행 결과를 계산해 덮어쓰기 문제를 피하는 큰 구조는 정확했다. 하지만 `results[k] + land[i][j]`가 현재 `j`열에 도착한 경로라는 점을 놓치고 처음에는 `temp[k]`에 저장했다.
- 풀이 후 새로 배운 점: DP 배열의 인덱스는 단순한 반복문 위치가 아니라 상태의 의미다. `results[k]`는 이전 행에서 `k`열로 끝난 최댓값이고, 여기에 현재 `j`열 점수를 더했다면 새 상태는 반드시 `j`열로 끝난 값이다.
- 오류 분류: 구현 — 상태 전이 방향은 맞았으나 저장 인덱스가 상태 의미와 불일치
- 잘한 점: 이전 행과 현재 행 배열을 분리했고, 모든 `k != j` 전이를 검사하는 `O(N)` 설계를 7분에 독립적으로 복구했다. 반례를 확인한 뒤 상태 의미에 맞게 한 줄을 수정해 최종 통과했다.
- 개선할 점: `temp = results.clone()`은 이전 행의 값을 현재 행 후보처럼 남겨 상태 의미를 흐린다. 현재 행의 결과는 `new int[4]`로 시작하고, `previousCol`과 `currentCol`처럼 역할이 드러나는 변수명을 쓰는 편이 안전하다.
- 시간복잡도: 행 수를 `N`이라 할 때 각 행에서 4×4 전이를 확인하므로 `O(16N) = O(N)`
- 공간복잡도: 길이 4인 이전·현재 배열만 유지하므로 입력을 제외하면 `O(1)`

## Codex 코드 리뷰

현재 코드는 정답이며 제한을 충분히 만족한다. 다음 코드는 상태의 의미를 변수명과 초기화 방식에 더 직접적으로 드러낸 형태다.

```java
public int solution(int[][] land) {
    int[] previous = land[0].clone();

    for (int row = 1; row < land.length; row++) {
        int[] current = new int[4];

        for (int currentCol = 0; currentCol < 4; currentCol++) {
            for (int previousCol = 0; previousCol < 4; previousCol++) {
                if (previousCol == currentCol) {
                    continue;
                }

                current[currentCol] = Math.max(
                        current[currentCol],
                        previous[previousCol] + land[row][currentCol]
                );
            }
        }

        previous = current;
    }

    int answer = 0;
    for (int score : previous) {
        answer = Math.max(answer, score);
    }
    return answer;
}
```

원본 Java는 사용자의 최종 통과 풀이를 보존하기 위해 수정하지 않았다.
