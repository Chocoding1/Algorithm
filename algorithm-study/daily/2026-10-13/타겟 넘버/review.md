- 공식 의도 일치 여부: 일치
- Codex 목표 일치 여부: 일치
- 실제 풀이와 의도 알고리즘 비교: `idx`를 깊이, `sum`을 현재 누적값으로 두고 각 깊이에서 덧셈과 뺄셈 두 경로를 모두 호출하는 정석 DFS다. 깊이가 `numbers.length`에 도달했을 때만 목표값과 비교하므로 각 부호 조합을 정확히 한 번씩 센다.
- 풀이 전 사고와 실제 코드의 차이: 설계한 DFS를 그대로 구현했다. 다만 풀이 전에는 `O(N²)` 가능 여부만 언급했지만 실제 선택한 탐색은 매 숫자마다 경우가 두 배가 되는 `O(2^N)`이며, `N ≤ 20`이라 최대 약 100만 개의 리프를 확인해도 충분하다.
- 코드 개선 포인트: **상수 비용·가독성 개선** — `"+"`, `"-"` 문자열 배열과 문자열 비교 반복은 필요하지 않다. 두 재귀 호출을 직접 더하면 선택지가 명확해지고 전역 `answer`·`n`도 제거해 재호출 안전성을 높일 수 있다. 점근 복잡도는 동일하다.
- 클린 코드 예시:

```java
// 프로그래머스 Lv.2
public class 타겟_넘버 {

    public int solution(int[] numbers, int target) {
        return dfs(numbers, target, 0, 0);
    }

    private int dfs(int[] numbers, int target, int index, int sum) {
        if (index == numbers.length) {
            return sum == target ? 1 : 0;
        }

        return dfs(numbers, target, index + 1, sum + numbers[index])
                + dfs(numbers, target, index + 1, sum - numbers[index]);
    }

    public static void main(String[] args) {
        타겟_넘버 solution = new 타겟_넘버();

        System.out.println(solution.solution(new int[]{1, 1, 1, 1, 1}, 3));
        System.out.println(solution.solution(new int[]{4, 1, 2, 1}, 4));
    }
}
```

- 풀이 후 새로 배운 점: 재귀 깊이가 `N`이어도 각 단계의 분기 수가 2개이면 전체 경우의 수는 `N²`이 아니라 `2^N`이다. 재귀 시간복잡도는 깊이만 보지 않고 `분기 수^깊이`와 각 노드의 작업량을 함께 본다.
- 다음 문제에 적용할 한 문장 규칙: **각 원소마다 독립적인 선택지가 `B`개이고 깊이가 `N`이면 먼저 `B^N`개의 상태를 의심한다.**
- 복습에 포함할 학습 포인트: `idx`·`sum` 상태 정의, 모든 부호 조합과 리프의 일대일 대응, `O(2^N)` 계산 근거
- 오류 분류: 없음
- 시간복잡도: `O(2^N)` — 깊이 `N`에서 각 단계마다 `+`·`-` 두 분기로 나뉨
- 공간복잡도: `O(N)` — 재귀 호출 스택의 최대 깊이
