## Codex 분석

- 힌트 수준(Codex 판정): 정답 쿼리 — 사용자가 `SELECT`·`COUNT`·날짜 필터·`GROUP BY`까지 구성한 뒤, 별칭 정렬과 `LIKE` 문법을 질문하는 과정에서 완성 쿼리를 확인함
- 복습 등급: C
- 등급 판정 근거: 25분 목표 내 15분에 최종 통과했고 집계 구조와 다중 정렬 기준은 스스로 찾았지만, 첫 제출 전에 별칭을 이용한 정렬·날짜 조건의 정확한 문법과 완성 쿼리를 확인함
- 목표 시간 달성: 예 (15분 / 25분)
- 첫 시도 성공: 아니오 (첫 통과 전 오답 1회)
- 핵심 문법: 날짜 범위 조건, `GROUP BY`, `COUNT(*)`, 다중 `ORDER BY`, 별칭
- 결과 한 행의 단위: 2022년 5월에 예약이 존재하는 진료과 하나와 그 진료과의 예약 건수
- 쿼리 데이터 흐름: `APPOINTMENT`에서 2022년 5월 예약 행만 먼저 남기고, 진료과 코드별로 그룹화해 예약 행 수를 센 뒤 예약 건수와 진료과 코드 순서로 정렬함
- 중복·NULL·JOIN 카디널리티 확인: 환자 수가 아니라 예약 건수를 요구하므로 예약 한 건을 나타내는 원본 행을 `COUNT(*)`로 센다. JOIN이 없어 행 증가는 없으며, 날짜 범위 밖의 행은 그룹화 전에 제외된다.
- 정답 검증: 별칭 참조 문법으로 첫 제출에서 오답이 발생했고, 백틱과 날짜 범위 조건을 적용한 뒤 프로그래머스 통과
- 코드 개선 포인트: **가독성 개선** — 별칭 선언과 참조에 모두 백틱을 사용하고, 날짜 컬럼을 왼쪽에 둔 반개방 범위로 작성하면 의도가 더 명확하다. 현재 원본 쿼리는 수정하지 않는다.
- 클린 쿼리 예시:

```sql
SELECT
    MCDP_CD AS `진료과코드`,
    COUNT(*) AS `5월예약건수`
FROM APPOINTMENT
WHERE APNT_YMD >= '2022-05-01'
  AND APNT_YMD < '2022-06-01'
GROUP BY MCDP_CD
ORDER BY `5월예약건수`, `진료과코드`;
```

- 풀이 후 새로 배운 점: `SELECT` 별칭은 논리적으로 그 뒤에 처리되는 `ORDER BY`에서 사용할 수 있고, 한글 별칭은 백틱으로 감싸는 것이 안전하다. `TIMESTAMP`의 월 조건은 문자열 패턴보다 해당 월 시작 이상·다음 달 시작 미만의 범위로 표현하는 것이 명확하고 인덱스 활용에도 유리하다.
- 오류 분류: 식별자 인용·날짜 필터 문법
- 다음에 적용할 규칙: **값은 작은따옴표, 식별자는 백틱을 사용하고, 날짜·시간의 월 조회는 반개방 범위로 작성한다.**
