- 조회할 테이블과 한 행의 의미: `USED_GOODS_BOARD`의 한 행과 `USED_GOODS_FILE`의 한 행은 각각 무엇을 나타내며, 두 테이블을 연결하면 결과 한 행은 무엇을 나타내는가?
- 행을 바꾸는 조건과 최종 정렬: 어느 게시물의 첨부파일만 남겨야 하며, 첨부파일이 여러 개일 때 어떤 값을 기준으로 어느 방향으로 정렬하는가?

## 풀이 후 결과 - 사용자 작성

## Codex 분석

- 힌트 수준(Codex 판정): 작은 힌트 — 여러 컬럼과 문자열 리터럴을 연결하는 `CONCAT()` 문법을 질문해 확인함
- 복습 등급: B
- 등급 판정 근거: 30분 목표 안인 6분에 최종 성공했지만 첫 통과 전 오답 제출이 3회 있었고, 출력 경로를 조립하는 핵심 SQL 문법을 확인한 뒤 완성했다. 최고 조회수 선택과 JOIN 구조는 최종 쿼리에서 정확하다.
- 목표 시간 달성: 달성 — 6분 / 30분
- 첫 시도 성공: 아니요 — 첫 통과 전 오답 3회
- 핵심 문법: 스칼라 서브쿼리·`MAX`·`INNER JOIN`·`CONCAT`·`ORDER BY DESC`
- 결과 한 행의 단위: 조회수가 가장 높은 게시글에 연결된 첨부파일 한 개
- 쿼리 데이터 흐름: 게시글과 첨부파일을 `BOARD_ID`로 연결한다 → 전체 게시글의 최대 조회수와 같은 게시글만 남긴다 → 첨부파일별 경로 문자열을 만든다 → 파일 ID 내림차순으로 정렬한다.
- 중복·NULL·JOIN 카디널리티 확인: 게시글 한 개에 첨부파일이 여러 개 있으므로 JOIN 후 게시글 한 행이 첨부파일 수만큼 늘어난다. 이것이 요구된 결과 단위이므로 `DISTINCT`나 `GROUP BY`로 줄이면 안 된다. 경로 구성 컬럼이 `NULL`이면 MySQL `CONCAT` 결과도 `NULL`이 되지만 문제 데이터에서는 필수 파일 정보가 제공된다.
- 정답 검증: 플랫폼 최종 통과. 경로 형식 `/home/grep/src/{BOARD_ID}/{FILE_ID}{FILE_NAME}{FILE_EXT}`와 `FILE_ID DESC` 정렬이 요구사항과 일치한다.
- 코드 개선 포인트: 최종 쿼리는 충분히 간결하고 정확하다. 최고 조회수 게시글이 문제 조건상 하나이므로 `VIEWS = (SELECT MAX(VIEWS) ...)`도 적절하다.
- 풀이 후 새로 배운 점: MySQL에서는 문자열 리터럴과 여러 컬럼을 `+`가 아니라 `CONCAT(값1, 값2, ...)`으로 연결한다.
- 오류 분류: 출력 문자열 구성 문법·제출 전 결과 검증
- 다음에 적용할 규칙: 경로처럼 고정 문자열과 컬럼을 섞어 출력할 때 필요한 구분자까지 문제 예시와 한 글자씩 대조하고, 마지막 정렬 컬럼과 방향도 제출 전에 확인한다.
