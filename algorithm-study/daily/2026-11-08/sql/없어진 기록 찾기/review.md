  - OUTS 테이블에는 있는데 INS 테이블에 없는 기록만 남기고, ID 순으로 정렬한다.

## Codex 분석

- 힌트 수준(Codex 판정): 없음
- 복습 등급: B
- 등급 판정 근거: 목표 20분 안인 5분 45초에 외부 조인의 보존 방향과 `NULL` 필터를 독립적으로 구성해 첫 제출로 통과했다. 다만 `WHERE AI.ANIMAL_ID IS NULL` 이후 모든 결과 행에서 `AI.ANIMAL_ID`가 `NULL`인데 이를 정렬 기준으로 사용해 요구된 ID 오름차순을 보장하지 못했다.
- 목표 시간 달성: 달성 — 20분 목표, 실제 5분 45초
- 첫 시도 성공: 성공 — 첫 공식 제출 통과
- 핵심 문법: `RIGHT JOIN`·`ON`·외부 조인으로 생성된 `NULL`·`IS NULL`·`ORDER BY`
- 결과 한 행의 단위: `ANIMAL_OUTS`에는 존재하지만 같은 `ANIMAL_ID`의 `ANIMAL_INS` 기록이 없는 입양 동물 한 마리
- 쿼리 데이터 흐름: `ANIMAL_OUTS`의 모든 입양 기록을 보존하면서 `ANIMAL_INS`를 ID로 연결하고, 매칭되지 않아 `AI` 컬럼이 `NULL`인 행만 남긴 뒤 입양 기록의 ID와 이름을 출력한다.
- 중복·NULL·JOIN 카디널리티 확인: 두 테이블에서 `ANIMAL_ID`가 기본 키이므로 ID 기준 연결은 최대 1:1이며 JOIN 때문에 행이 증식하지 않는다. 여기서 `AI.ANIMAL_ID IS NULL`은 원본 ID가 NULL이라는 뜻이 아니라 대응하는 입소 행이 없어 외부 조인이 만든 NULL이라는 뜻이다.
- 정답 검증: 출력 컬럼과 누락 기록 판정은 정확하다. 하지만 필터 후 `AI.ANIMAL_ID`는 전부 NULL이므로 `ORDER BY AI.ANIMAL_ID`는 동물 ID 순서를 보장하지 않는다. `AO.ANIMAL_ID`로 정렬해야 한다.
- 코드 개선 포인트: 현재 `RIGHT JOIN`도 정확한 대안이지만, 결과 후보를 반드시 남겨야 하는 `ANIMAL_OUTS`를 왼쪽에 놓고 `LEFT JOIN`하면 “입양 기록은 모두 보존하고 입소 기록이 없는 행을 찾는다”는 흐름이 읽기 쉽다. 빅오 차이가 아니라 정확성·가독성 개선이다.
- 클린 쿼리 예시:

```sql
SELECT AO.ANIMAL_ID, AO.NAME
FROM ANIMAL_OUTS AS AO
LEFT JOIN ANIMAL_INS AS AI
    ON AO.ANIMAL_ID = AI.ANIMAL_ID
WHERE AI.ANIMAL_ID IS NULL
ORDER BY AO.ANIMAL_ID;
```

- 풀이 후 새로 배운 점: 외부 조인에서 매칭 실패를 확인하려고 `IS NULL`로 검사한 컬럼은 필터 이후 모든 결과에서 NULL이다. 따라서 그 컬럼이 아니라 보존된 테이블의 실제 출력 키로 정렬해야 한다.
- 오류 분류: 정렬 대상 컬럼
- 다음에 적용할 규칙: 외부 조인 쿼리는 먼저 반드시 남겨야 하는 테이블을 정하고, 필터 후에도 실제 값이 남아 있는 테이블의 컬럼으로 출력·정렬한다.
