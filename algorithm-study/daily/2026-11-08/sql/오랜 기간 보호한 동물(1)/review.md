## Codex 분석

- 힌트 수준(Codex 판정): 없음
- 복습 등급: A
- 등급 판정 근거: 목표 20분 안인 3분 55초에 보존할 테이블, 매칭 실패 판정, 보호 시작일 정렬과 상위 3개 제한을 모두 정확하게 작성해 오류 없이 첫 제출로 통과했다.
- 목표 시간 달성: 달성 — 20분 목표, 실제 3분 55초
- 첫 시도 성공: 성공 — 첫 공식 제출 통과
- 핵심 문법: `LEFT JOIN`·`ON`·외부 조인으로 생성된 `NULL`·`IS NULL`·`ORDER BY`·`LIMIT`
- 결과 한 행의 단위: 보호소에 들어왔지만 아직 입양 기록이 없는 동물 한 마리
- 쿼리 데이터 흐름: 모든 입소 기록을 보존하면서 입양 기록을 ID로 연결하고, 대응하는 입양 기록이 없어 `AO.ANIMAL_ID`가 NULL인 행만 남긴다. 그 결과를 보호 시작일이 빠른 순서로 정렬한 뒤 앞의 3행만 출력한다.
- 중복·NULL·JOIN 카디널리티 확인: 두 테이블의 `ANIMAL_ID`가 기본 키이므로 ID 연결은 최대 1:1이고 행이 증식하지 않는다. `AO.ANIMAL_ID IS NULL`은 원래 ID가 NULL이라는 뜻이 아니라 대응하는 입양 행이 없어 외부 조인이 만든 NULL이다.
- 정답 검증: 출력 컬럼, 미입양 조건, 보호 시작일 오름차순, `LIMIT 3`을 모두 정확히 반영했다. 회고의 “입양일이 가장 빠른 순서”는 표현상 오류이며, 입양 기록이 없는 동물이므로 실제 비교 기준은 코드에 사용한 입소일 `AI.DATETIME`이다.
- 코드 개선 포인트: 현재 쿼리가 문제의 데이터 흐름을 가장 직접적으로 표현하고 있어 의미 있는 개선이 필요하지 않다. `ASC`를 명시하는 것은 가독성 선택 사항이며 결과는 동일하다.
- 클린 쿼리 예시: 현재 제출 쿼리가 충분히 깔끔하며 별도의 대체 쿼리가 필요하지 않다.
- 풀이 후 새로 배운 점: `LIMIT`은 정렬 후 적용되어야 “가장 오래 보호 중인 3마리”가 된다. 먼저 3행을 고른 뒤 정렬하는 의미가 아니다.
- 오류 분류: 없음
- 다음에 적용할 규칙: 상위 N개를 요구하면 먼저 후보 행을 필터링하고, 순위를 결정하는 컬럼으로 정렬한 뒤 마지막에 `LIMIT N`을 적용한다.
