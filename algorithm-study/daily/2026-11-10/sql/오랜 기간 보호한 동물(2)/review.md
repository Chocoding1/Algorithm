## Codex 분석

- 힌트 수준(Codex 판정): 정답 쿼리 — 날짜 차이 함수 문법을 질문한 뒤 `ANIMAL_ID`를 인자로 사용한 오류를 확인하는 과정에서 `TIMESTAMPDIFF`를 사용한 완성 쿼리와 `DATEDIFF(AO.DATETIME, AI.DATETIME)` 수정 방향을 확인함
- 복습 등급: C
- 등급 판정 근거: 목표 20분 안인 8분 30초에 최종 성공했지만 첫 통과 전 오답 1회가 있었고, 날짜 차이 함수의 올바른 인자와 완성 쿼리를 확인한 뒤 통과했다.
- 목표 시간 달성: 달성 — 20분 목표, 실제 8분 30초
- 첫 시도 성공: 실패 — 첫 통과 전 오답 1회
- 핵심 문법: `INNER JOIN`·날짜 차이 계산·계산식 정렬·`LIMIT`
- 결과 한 행의 단위: 입소 기록과 입양 기록이 `ANIMAL_ID`로 연결된, 실제로 입양된 동물 한 마리. 회고의 질문은 특정 동물을 고르라는 뜻이 아니라 JOIN 후 한 줄이 무엇을 나타내는지 확인하려는 질문이었다.
- 쿼리 데이터 흐름: `ANIMAL_INS`와 `ANIMAL_OUTS`를 `ANIMAL_ID`로 연결해 입양된 동물만 남기고, 각 동물의 입양 시각과 입소 시각 차이를 계산해 긴 순서로 정렬한 뒤 상위 2행의 ID와 이름을 출력한다.
- 중복·NULL·JOIN 카디널리티 확인: 두 테이블에서 `ANIMAL_ID`는 동물 한 마리를 식별하고 입양 정보가 한 건이므로 JOIN 후에도 동물 한 마리당 한 행이다. `INNER JOIN` 자체가 양쪽에 모두 있는 동물만 남기고 `ANIMAL_OUTS.DATETIME`도 NULL 불가이므로 별도의 `WHERE AO.DATETIME IS NOT NULL`은 필요 없다.
- 정답 검증: 최종 쿼리는 올바른 두 `DATETIME` 컬럼의 날짜 차이를 내림차순 정렬하고 `LIMIT 2`를 적용해 플랫폼 제출에 통과했다.
- 코드 개선 포인트: `DATEDIFF`는 시각 부분을 무시하고 날짜 단위 차이만 반환한다. 제출 쿼리는 통과했지만 보호 기간을 초 단위까지 정확히 비교하려면 `TIMESTAMPDIFF(SECOND, AI.DATETIME, AO.DATETIME)`가 더 안전하다. 데이터 크기에서 점근 복잡도 개선은 아니며 정확성 안전성 개선이다.
- 클린 쿼리 예시:

```sql
SELECT AI.ANIMAL_ID, AI.NAME
FROM ANIMAL_INS AS AI
JOIN ANIMAL_OUTS AS AO
    ON AI.ANIMAL_ID = AO.ANIMAL_ID
ORDER BY TIMESTAMPDIFF(SECOND, AI.DATETIME, AO.DATETIME) DESC
LIMIT 2;
```

- 풀이 후 새로 배운 점: 날짜 차이 함수에는 식별자 컬럼이 아니라 실제 시작·종료 날짜 컬럼을 전달해야 한다. `DATEDIFF(종료일, 시작일)`은 날짜 수만 필요할 때, `TIMESTAMPDIFF(단위, 시작일, 종료일)`은 시간까지 포함한 차이가 필요할 때 사용한다.
- 오류 분류: 날짜 함수 인자·정렬 계산식
- 다음에 적용할 규칙: 계산 함수나 정렬식에 컬럼을 넣기 전에 각 컬럼의 값이 식별자인지 실제 계산 대상인지 다시 확인한다.
