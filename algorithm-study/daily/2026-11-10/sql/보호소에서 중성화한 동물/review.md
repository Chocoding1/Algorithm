## Codex 분석

- 힌트 수준(Codex 판정): 없음 — 풀이 중 SQL 문법·JOIN 조건·상태 비교에 관한 도움을 요청하지 않고 독립 작성함
- 복습 등급: A
- 등급 판정 근거: 목표 20분 안인 7분 20초에 입소·입양 상태를 정확히 비교하는 JOIN 쿼리를 독립 작성했고, 힌트와 오류 없이 첫 제출로 통과했다.
- 목표 시간 달성: 달성 — 20분 목표, 실제 7분 20초
- 첫 시도 성공: 성공 — 첫 공식 제출 통과
- 핵심 문법: `INNER JOIN`·JOIN 전후 컬럼 비교·`AND`/`OR` 연산자 우선순위·오름차순 정렬
- 결과 한 행의 단위: 입소 기록과 입양 기록이 `ANIMAL_ID`로 연결된 동물 한 마리
- 쿼리 데이터 흐름: 입소·입양 테이블을 동물 ID로 연결하고, 입소 시 `Intact`였지만 입양 시 성별에 맞게 `Neutered` 또는 `Spayed`로 바뀐 행만 남긴 뒤 동물 ID 오름차순으로 출력한다.
- 중복·NULL·JOIN 카디널리티 확인: 두 테이블의 동물 ID가 한 동물을 식별하므로 JOIN 후에도 동물 한 마리당 한 행이다. 비교하는 상태 컬럼은 NULL 불가이며 이 문제에서 중복 제거는 필요 없다.
- 정답 검증: 코드가 `Intact Male → Neutered Male`과 `Intact Female → Spayed Female` 두 경우를 모두 포함하고 출력 컬럼과 ID 오름차순 정렬도 정확히 반영해 첫 제출에 통과했다. 풀이 전 기록의 “각 테이블의 `SEX_UPON_OUTCOME`”은 표현상 오류이고, 실제 입소 컬럼은 `SEX_UPON_INTAKE`이며 제출 코드는 올바르다.
- 코드 개선 포인트: SQL에서 `AND`가 `OR`보다 먼저 계산되므로 현재 조건은 정확하다. 다만 두 전환 조건을 괄호로 묶으면 연산자 우선순위에 의존한다는 사실을 독자가 다시 계산할 필요가 없어져 가독성과 수정 안전성이 좋아진다. 빅오 개선은 아니다.
- 클린 쿼리 예시:

```sql
SELECT AI.ANIMAL_ID, AI.ANIMAL_TYPE, AI.NAME
FROM ANIMAL_INS AS AI
JOIN ANIMAL_OUTS AS AO
    ON AI.ANIMAL_ID = AO.ANIMAL_ID
WHERE (AI.SEX_UPON_INTAKE = 'Intact Male'
       AND AO.SEX_UPON_OUTCOME = 'Neutered Male')
   OR (AI.SEX_UPON_INTAKE = 'Intact Female'
       AND AO.SEX_UPON_OUTCOME = 'Spayed Female')
ORDER BY AI.ANIMAL_ID;
```

- 풀이 후 새로 배운 점: `AND`와 `OR`가 섞인 조건은 현재 우선순위상 맞더라도, 하나의 의미 단위를 이루는 조건끼리 괄호로 묶으면 이후 조건을 추가하거나 수정할 때 논리 오류를 예방할 수 있다.
- 오류 분류: 없음 — 회고의 컬럼명 표현만 보정
- 다음에 적용할 규칙: `AND`와 `OR`가 한 `WHERE`에 함께 나오면 요구사항의 한 경우를 이루는 조건들을 괄호로 묶어 읽는 단위와 실행 조건을 일치시킨다.
