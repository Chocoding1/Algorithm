## Codex 분석

- 힌트 수준(Codex 판정): 정답 코드 — 합승 종료 지점별 반복 탐색을 `s`, `a`, `b`의 세 거리 배열로 바꾸는 핵심 구조, 우선순위 큐·배열 다익스트라와 플로이드–워셜 전체 코드까지 확인함
- 복습 등급: C
- 등급 판정 근거: 목표 50분을 10분 초과한 60분 동안 다익스트라 후보와 반복 탐색 병목은 인식했지만 구현 가능한 설계를 완성하지 못해 미제출로 종료했고, 이후 핵심 구조와 정답 코드를 학습했다.
- 목표 시간 달성: 미달성 — 50분 목표, 독립 고민 60분
- 첫 시도 성공: 실패 — 공식 제출 없이 정답 코드 학습
- 공식 출제 의도 알고리즘: 카카오 공식 해설은 그래프 최단거리 문제로 다익스트라 또는 플로이드–워셜을 제시하고, 대표 풀이로 모든 지점 쌍의 최소 비용을 구하는 플로이드–워셜을 전개한다.
- Codex 추천 목표 알고리즘: 양방향 그래프에서 `s`, `a`, `b`를 출발점으로 우선순위 큐 다익스트라를 각각 한 번 실행하고, 모든 합승 종료 지점 `k`의 `distS[k] + distA[k] + distB[k]` 최솟값 계산
- 실제 풀이와 의도 알고리즘 비교: 다익스트라를 사용해야 한다는 유형 인식은 맞았고 `s`에서 먼저 도달하는 지점을 합승 후보로 보는 방향도 유효했다. 그러나 후보마다 `k → a`, `k → b`를 다시 탐색하려 해 반복 비용을 해결하지 못했다. 학습 코드는 세 출발점의 전체 거리 배열을 한 번씩 만든 뒤 모든 후보에서 재사용한다.
- 풀이 전 사고와 실제 코드의 차이: 풀이 전에는 합승 비용을 단순히 합한다는 수준에서 구간을 수식으로 분리하지 못했고, 같은 두 지점의 최소 비용을 다시 계산할 수 있다는 병목까지 확인한 뒤 설계가 멈췄다. 최종 학습에서는 합승 종료 지점 `k`를 고정하면 총비용이 `s → k`, `k → a`, `k → b`라는 세 독립 최단거리의 합이 된다는 식으로 문제를 변환했다. 첫 시간대 질문은 이 세 구간을 직접 적도록 묻는 의도였으나 표현이 추상적이었으며, 사용자의 이해 부족으로 평가하지 않는다.
- 코드 개선 포인트: 현재 학습 코드는 인접 리스트, 오래된 큐 항목 건너뛰기, 세 거리 배열, 도달 불가 후보 제외를 명확히 분리해 충분히 깔끔하다. 제한상 세 거리 합은 `int` 범위지만 합산부를 `long`으로 두면 제한 변경에도 안전해지는 정도의 선택적 개선만 가능하다.
- 풀이 후 새로 배운 점: 합승 종료 후보를 전부 확인해야 해도 후보마다 최단거리 탐색을 반복할 필요는 없다. 양방향 그래프에서는 `k → a`가 `a → k`와 같으므로 `s`, `a`, `b` 세 출발점에서 한 번씩 구한 결과를 재사용할 수 있다. 플로이드–워셜은 모든 지점 쌍을 `O(V³)`에 구하고, 다익스트라 3회는 필요한 세 출발점만 구한다.
- 다음 문제에 적용할 한 문장 규칙: 여러 후보마다 같은 최단거리 질의를 반복하게 되면 필요한 출발점이 몇 개인지 먼저 세고, 출발점별 결과 배열이나 모든 쌍 거리 행렬을 미리 계산해 재사용한다.
- 복습에 포함할 학습 포인트: 합승 종료 지점 `k`의 세 구간 합, 양방향 거리 대칭성, 다익스트라 3회와 플로이드–워셜 비교, 우선순위 큐 다익스트라 `O((V+E) log V)`, 플로이드 점화식의 중간 지점 누적 의미
- 오류 분류: 인식·설계·시간 관리 — 최단거리 유형은 인식했지만 반복 탐색을 사전 계산으로 바꾸지 못함
- 시간복잡도: 현재 우선순위 큐 학습 코드는 다익스트라 3회와 후보 순회로 `O((V+E) log V)`, 플로이드–워셜 대안은 `O(V³)`
- 공간복잡도: 인접 리스트·세 거리 배열·우선순위 큐를 합쳐 `O(V+E)`
