## Codex 분석

- 힌트 수준(Codex 판정): 작은 힌트 — 최소 비용 간선 선택과 Union-Find 적용은 독립적으로 완성했고, Codex는 두 오답 구현에 대한 반례와 `union`에서 대표끼리 연결해야 한다는 수정 지점만 제공함
- 복습 등급: B
- 등급 판정 근거: 목표 45분 안인 30분에 최종 성공하고 15분 만에 최소 비용 간선과 Union-Find 설계를 확정했지만, 첫 통과 전 오답 2회와 의미 있는 집합 상태 구현 오류가 있었고 반례 기반 도움을 받아 수정했다.
- 목표 시간 달성: 달성 — 45분 목표, 실제 30분
- 첫 시도 성공: 실패 — 첫 통과 전 오답 2회
- 공식 출제 의도 알고리즘: 프로그래머스 고득점 Kit의 탐욕법 문제로, 일반적으로 최소 비용 간선을 순서대로 선택하되 사이클을 만들지 않는 Kruskal 또는 연결된 영역을 확장하는 Prim으로 최소 신장 트리를 구한다.
- Codex 추천 목표 알고리즘: 비용 오름차순 간선 선택과 Union-Find로 사이클을 판정하는 Kruskal
- 실제 풀이와 의도 알고리즘 비교: 우선순위 큐에 모든 간선을 넣어 비용이 낮은 순서로 꺼내고, 두 정점의 대표가 다를 때만 간선을 선택하고 합쳤으므로 Kruskal과 일치한다.
- 풀이 전 사고와 실제 코드의 차이: 첫 구현은 정점별 `visited`만 확인해 서로 다른 두 연결 요소에 이미 방문한 정점이 하나씩 있는 경우를 구분하지 못했다. Union-Find로 전환한 뒤에는 올바른 집합 상태를 표현했지만, 처음 `union`에서 원래 정점 번호끼리 연결해 기존 집합을 분리하는 오류가 있었고 대표끼리 연결하도록 수정했다.
- 코드 개선 포인트: 현재 코드는 정확하고 `find`의 경로 압축도 적용됐다. 선택한 간선이 `n - 1`개가 되면 모든 섬이 연결됐으므로 남은 우선순위 큐를 확인하지 않고 종료할 수 있다. 또한 이미 구한 두 대표를 `union`에 전달하면 같은 `find` 호출을 반복하지 않는다. 빅오는 같고 상수 비용과 상태 의미가 개선된다.
- 풀이 후 새로 배운 점: `visited`는 정점을 한 번 확인했는지만 표현하지만 Union-Find는 두 정점이 같은 연결 요소에 속하는지를 표현한다. `union`은 원래 정점 번호의 대소가 아니라 `find`로 얻은 대표끼리 연결해야 기존 집합 관계가 유지된다.
- 다음 문제에 적용할 한 문장 규칙: “이미 방문했는가”가 아니라 “현재 같은 그룹인가”를 반복 판정해야 하면 각 정점의 대표를 관리하고 합칠 때는 반드시 대표끼리 연결한다.
- 복습에 포함할 학습 포인트: `visited` 반례, `union`의 대표 연결, 경로 압축, 최소 신장 트리의 간선 수 `n - 1`, `O(E log E)` 근거
- 오류 분류: 구현 — 연결 요소와 방문 상태 혼동, 대표가 아닌 원래 정점 번호를 연결
- 시간복잡도: 간선 `E`개를 우선순위 큐에 넣고 꺼내는 데 `O(E log E)`, 경로 압축 Union-Find는 전체적으로 거의 상수인 `O(E α(V))`이므로 총 `O(E log E)`
- 공간복잡도: 우선순위 큐 `O(E)`와 부모 배열 `O(V)`를 합쳐 `O(E + V)`

### 클린 코드 예시

원본과 같은 Kruskal 방식이다. 비용순 정렬 후 대표를 한 번씩만 찾고, 간선 `n - 1`개를 선택하면 즉시 종료한다. 빅오 개선은 없고 상수 비용·가독성 개선이며 원본 Java에는 적용하지 않는다.

```java
import java.util.Arrays;
import java.util.Comparator;

// 프로그래머스 Lv.3
public class 섬_연결하기 {

    private int[] parent;

    public int solution(int n, int[][] costs) {
        parent = new int[n];
        for (int node = 0; node < n; node++) {
            parent[node] = node;
        }

        Arrays.sort(costs, Comparator.comparingInt(edge -> edge[2]));

        int totalCost = 0;
        int selectedEdges = 0;

        for (int[] edge : costs) {
            int rootA = find(edge[0]);
            int rootB = find(edge[1]);

            if (rootA == rootB) {
                continue;
            }

            parent[rootB] = rootA;
            totalCost += edge[2];
            selectedEdges++;

            if (selectedEdges == n - 1) {
                break;
            }
        }

        return totalCost;
    }

    private int find(int node) {
        if (parent[node] == node) {
            return node;
        }
        return parent[node] = find(parent[node]);
    }
}
```
