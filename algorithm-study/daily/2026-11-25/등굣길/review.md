## Codex 분석

- 힌트 수준(Codex 판정): 작은 힌트. 문제 화면 상단의 `동적계획법` 분류가 접근 선택에 영향을 줬다. 대화에서 제공한 도움은 이미 작성된 코드의 중간값 출력 방법이었다.
- 복습 등급: B
- 등급 판정 근거: 목표 40분 안에 25분으로 통과했다. 8분에 설계를 확정했으며 시작 칸 초기값 누락으로 오답 1회가 있었다. 화면의 유형 분류를 본 사실은 유형 인식 평가에도 반영한다.
- 목표 시간 달성: 예 (25분 / 40분)
- 첫 시도 성공: 아니오 (첫 통과 전 오답 1회)
- 공식 출제 의도 알고리즘: 프로그래머스 공식 분류는 동적계획법
- Codex 추천 목표 알고리즘: `dp[row][col]`에 각 칸까지의 경로 수를 저장하고 위쪽과 왼쪽에서 오는 경로를 더하는 격자 DP
- 실제 풀이와 의도 알고리즘 비교: 상태와 전이가 목표 풀이와 일치한다. 두 방향에서 온 경로는 마지막 이동 방향으로 구분되므로 합쳐도 중복되지 않는다. 웅덩이는 0을 유지하며, `puddles`의 `[x, y]`는 배열의 `[row=y][col=x]`로 정확히 대응했다.
- 코드 개선 포인트: 웅덩이 좌표를 `boolean[][] blocked`에 먼저 표시하면 칸마다 웅덩이 전체를 훑는 `isBlocked()`를 배열 조회로 바꿀 수 있다. 웅덩이가 최대 10개라 기존 풀이도 제한을 만족한다.
- 클린 코드 예시:

```java
public int solution(int m, int n, int[][] puddles) {
    final int MOD = 1_000_000_007;
    boolean[][] blocked = new boolean[n + 1][m + 1];
    for (int[] puddle : puddles) {
        blocked[puddle[1]][puddle[0]] = true;
    }

    int[][] dp = new int[n + 1][m + 1];
    dp[1][1] = 1;
    for (int row = 1; row <= n; row++) {
        for (int col = 1; col <= m; col++) {
            if ((row == 1 && col == 1) || blocked[row][col]) {
                continue;
            }
            dp[row][col] = (dp[row - 1][col] + dp[row][col - 1]) % MOD;
        }
    }
    return dp[n][m];
}
```

- 풀이 후 새로 배운 점: `dp[1][1] = 1`은 이동을 시작하기 전 출발점에 있는 한 가지 경우다. 이 값이 0이면 이후 칸에서 0끼리 더하게 된다.
- 다음 문제에 적용할 한 문장 규칙: 경로 수를 누적할 때 시작 상태가 몇 가지인지 정하고, 바로 다음 한 칸의 값부터 손으로 확인한다.
- 오류 분류: 구현·초기화
- 잘한 점: 행·열과 입력 좌표의 순서를 올바르게 변환했고, 이동할 수 없는 칸과 나머지 연산을 정확히 반영했다.
- 개선할 점: 시작값을 넣은 뒤 첫 이동이 가능한 칸에서 경로 수 1이 전달되는지 확인한다. 저장된 코드로 공식 예제, 가로·세로가 다른 웅덩이 좌표, 한 줄 격자, 첫 두 이동이 모두 막힌 상황을 검증했다.
- 시간복잡도: `P`가 웅덩이 수라면 기존 `O(n × m × (P + 1))`, 웅덩이 사전 표시 개선안 `O(n × m + P)`
- 공간복잡도: 기존과 개선안 모두 `O(n × m)`

## 반복 복습

- D+1: 완료 (2026-11-26). 출발 칸이 0이면 바로 오른쪽도 0이 되므로, 초기 경로 하나를 전달하기 위해 출발 칸을 1로 둔다고 설명했다.
- D+3: 대상 (2026-11-30 최종 점검에 통합). 코드 없이 전이식, 좌표 변환, 한 줄 격자와 웅덩이 처리, 웅덩이 사전 표시의 시간 차이 회상
- D+7: 대상 (2026-12-02 이후). 유형을 가린 새 변형에서 접근 선택과 시작값 검증
- 동일 문제 재도전 예정일: 생략. 시작값을 수정해 통과했으며 짧은 회상과 새 변형에서 확인
- 재도전·변형 결과: 변형 문제 풀이 성공 (오답 1회 후 통과)
- D+7 변형 전이 결과: 부분 성공. 설계와 구현을 완성했으며 화면 유형을 확인한 상태였으므로 무힌트 전이 성공 집계에서는 제외
