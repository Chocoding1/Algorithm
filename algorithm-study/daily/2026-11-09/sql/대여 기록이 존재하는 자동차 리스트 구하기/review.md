## Codex 분석

- 힌트 수준(Codex 판정): 정답 쿼리 — 날짜 리터럴의 작은따옴표와 JOIN 중복 문제를 설명하면서 완성된 `JOIN + DISTINCT` 쿼리와 `EXISTS` 대안 전체를 제공함
- 복습 등급: C
- 등급 판정 근거: 목표 20분 안인 11분에 최종 성공했지만 첫 통과 전 오답 3회가 있었고, 날짜 비교 수정과 중복 제거를 포함한 완성 쿼리를 확인한 뒤 통과했다.
- 목표 시간 달성: 달성 — 20분 목표, 실제 11분
- 첫 시도 성공: 실패 — 첫 통과 전 오답 3회
- 핵심 문법: 날짜 리터럴·반개방 날짜 범위·`INNER JOIN`·1:N 행 증가·`DISTINCT`·`EXISTS`
- 결과 한 행의 단위: 10월 대여 시작 기록이 하나 이상 존재하는 세단 자동차 한 대
- 쿼리 데이터 흐름: 자동차와 대여 기록을 `CAR_ID`로 연결하면 자동차 한 대가 조건에 맞는 대여 기록 수만큼 여러 행으로 늘어난다. 자동차 종류와 시작일을 필터링한 뒤 `DISTINCT`로 자동차 ID를 한 행으로 줄이고 내림차순 정렬한다.
- 중복·NULL·JOIN 카디널리티 확인: 자동차 한 대와 대여 기록은 1:N 관계이므로 같은 자동차가 10월에 여러 번 대여됐다면 JOIN 결과에 동일 `CAR_ID`가 반복된다. 최종 쿼리는 `DISTINCT`로 중복을 제거했으며 NULL은 이 문제의 핵심 조건이 아니다.
- 정답 검증: `CAR_TYPE = '세단'`, 10월 1일 이상·11월 1일 미만의 반개방 범위, 중복 없는 ID, ID 내림차순을 모두 반영해 최종 쿼리는 정확하다. `2022-10-01`처럼 따옴표가 없으면 MySQL이 날짜가 아니라 `2022 - 10 - 1`이라는 산술식으로 해석한다.
- 코드 개선 포인트: `DISTINCT(C.CAR_ID)`도 동작하지만 `DISTINCT`는 함수가 아니라 SELECT 결과 행의 중복을 제거하는 키워드이므로 `SELECT DISTINCT C.CAR_ID`가 의미를 더 정확히 드러낸다. 존재 여부만 필요할 때는 `EXISTS`를 사용하면 자동차 한 행을 유지해 `DISTINCT`가 필요 없다.
- 클린 쿼리 예시:

```sql
SELECT C.CAR_ID
FROM CAR_RENTAL_COMPANY_CAR AS C
WHERE C.CAR_TYPE = '세단'
  AND EXISTS (
      SELECT 1
      FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY AS H
      WHERE H.CAR_ID = C.CAR_ID
        AND H.START_DATE >= '2022-10-01'
        AND H.START_DATE < '2022-11-01'
  )
ORDER BY C.CAR_ID DESC;
```

- 풀이 후 새로 배운 점: 문자열과 날짜 값은 작은따옴표로 감싸고, 백틱은 컬럼·테이블·별칭 같은 식별자에 사용한다. JOIN은 관계 수만큼 행을 늘리지만 `EXISTS`는 일치하는 행이 있는지만 판정해 기준 행 수를 유지한다.
- 오류 분류: 날짜 리터럴·1:N 중복·결과 행 단위
- 다음에 적용할 규칙: 결과가 “대상 한 개당 한 행”이고 다른 테이블의 기록이 있는지만 필요하면 JOIN 전에 `EXISTS`로 기준 행을 유지할 수 있는지 확인한다.
