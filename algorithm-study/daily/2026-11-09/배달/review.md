- 힌트 수준(Codex 판정): 없음 — `PriorityQueue<int[]>` 비교 문법만 질문했으며 알고리즘·상태·진행 규칙은 사용자가 이미 선택한 뒤였다.
- 복습 등급: A
- 등급 판정 근거: 목표 45분 안인 39분 30초에 성공했고 13분 만에 설계를 확정했으며, 풀이 힌트 없이 첫 제출로 통과했다. 인접 리스트 배열 초기화 오류는 로컬 구현 중 발견해 수정했고 핵심 흐름이나 제출 결과에 영향을 주지 않았다.
- 목표 시간 달성: 달성 — 45분 목표, 실제 39분 30초
- 첫 시도 성공: 성공 — 첫 공식 제출 통과
- 공식 출제 의도 알고리즘: 공식 의도 명시 없음. 제한에서 일반적으로 다익스트라 또는 플로이드-워셜로 해결 가능
- Codex 추천 목표 알고리즘: 인접 리스트와 최소 누적 시간을 우선하는 우선순위 큐를 사용한 다익스트라
- 실제 풀이와 의도 알고리즘 비교: Codex 목표와 일치. 누적 시간이 가장 작은 후보부터 꺼내고 처음 확정되는 마을만 방문 처리했으며, `K`를 넘는 후보는 추가하지 않았다.
- 풀이 전 사고와 실제 코드의 차이: 풀이 전에는 같은 마을까지의 누적 시간이 반복 계산된다는 병목을 인식했고, 실제 구현에서는 거리 배열 대신 우선순위 큐와 `visited`를 사용해 가장 먼저 꺼낸 경로를 최소 시간으로 확정했다.
- 코드 개선 포인트: 현재 풀이도 정확하지만 거리 배열이 없어 같은 마을의 더 느린 후보도 큐에 들어갈 수 있다. `dist[next]`보다 짧은 경로만 큐에 추가하면 최소 시간이라는 상태가 코드에 직접 드러나고 불필요한 후보를 줄일 수 있다. 빅오는 같은 수준이며 상수 비용·가독성 개선이다. 사용하지 않는 주석 처리된 초기화 시도도 제거하는 편이 좋다.
- 풀이 후 새로 배운 점: 우선순위 큐에서 누적 시간이 가장 작은 경로부터 꺼내고 모든 도로 시간이 양수이면, 어떤 마을이 처음 꺼내지는 순간의 시간이 그 마을의 최소 시간이다. 그래서 현재 코드도 별도 거리 배열 없이 정답을 만든다.
- 다음 문제에 적용할 한 문장 규칙: 이동 비용이 서로 다르면 후보를 임의 순서로 처리하지 말고, 현재까지 누적 비용이 가장 작은 상태를 먼저 확정할 수 있는지 확인한다.
- 복습에 포함할 학습 포인트: 첫 poll이 최소 시간을 보장하는 이유, `visited` 방식과 `dist` 완화 방식의 차이, `K` 초과 경로를 버려도 되는 양의 가중치 조건, 향상된 for문 변수 대입이 배열 원소를 바꾸지 않는 이유
- 오류 분류: Java 배열 초기화 방식 — 향상된 for문 변수에 새 리스트를 대입해도 원본 배열 칸은 변경되지 않음
- 시간복잡도: 마을 수를 `V`, 도로 수를 `E`라 하면 각 마을을 한 번 확장하고 간선 후보를 우선순위 큐에 넣고 빼므로 `O((V+E) log E)`
- 공간복잡도: 인접 리스트·방문 배열·우선순위 큐를 합쳐 `O(V+E)`

### 클린 코드 예시

원본과 같은 우선순위 기반 최단거리 풀이지만, `dist` 배열을 사용해 더 짧아진 후보만 큐에 추가한다. 빅오 개선보다는 불필요한 큐 원소 감소와 상태 의미의 명확화가 목적이며 원본 Java에는 적용하지 않는다.

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.PriorityQueue;

public class Solution {

    public int solution(int N, int[][] road, int K) {
        List<int[]>[] graph = new ArrayList[N + 1];
        for (int town = 1; town <= N; town++) {
            graph[town] = new ArrayList<>();
        }

        for (int[] edge : road) {
            graph[edge[0]].add(new int[]{edge[1], edge[2]});
            graph[edge[1]].add(new int[]{edge[0], edge[2]});
        }

        int[] minTime = new int[N + 1];
        Arrays.fill(minTime, Integer.MAX_VALUE);
        minTime[1] = 0;

        PriorityQueue<int[]> queue =
                new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        queue.offer(new int[]{0, 1});

        while (!queue.isEmpty()) {
            int[] current = queue.poll();
            int currentTime = current[0];
            int currentTown = current[1];

            if (currentTime > minTime[currentTown]) {
                continue;
            }

            for (int[] nextRoad : graph[currentTown]) {
                int nextTown = nextRoad[0];
                int nextTime = currentTime + nextRoad[1];

                if (nextTime <= K && nextTime < minTime[nextTown]) {
                    minTime[nextTown] = nextTime;
                    queue.offer(new int[]{nextTime, nextTown});
                }
            }
        }

        int answer = 0;
        for (int town = 1; town <= N; town++) {
            if (minTime[town] <= K) {
                answer++;
            }
        }
        return answer;
    }
}
```
