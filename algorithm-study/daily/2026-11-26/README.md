## 짧은 복습 — 2/2 완료

1. **어제 오답 재현 D+1 (3분)** — `서버 증설 횟수`에서 운영 기간이 1시간일 때 다음 시간대 시작에 만료가 어떻게 반영되는지, `등굣길`에서 출발 칸이 0이면 첫 이동 칸에 어떤 값이 나오는지 손으로 확인한다.
2. **프렌즈4블록 D+3 (3분)** — `A · B ·` 한 열을 아래부터 채우며 읽는 칸과 쓰는 칸을 표시한다. 아직 읽지 않은 블록이 덮이지 않는 이유를 한 문장으로 설명한다.

서버는 첫 증설분이 다음 시간대가 시작할 때 만료되어 두 시간 동안 총 2대를 증설한다고 설명했다. 등굣길은 출발 칸이 0이면 오른쪽 칸도 0이 되고, 출발 칸을 1로 두어 경로 수가 전달된다고 설명했다. 프렌즈4블록은 `B`를 맨 아래, `A`를 그 위에 배치하고 아래부터 읽고 쓰는 이유를 설명했다. `writeRow`는 현재 읽는 칸과 같거나 더 아래이므로 아직 읽지 않은 위쪽을 덮지 않는다.

`부대복귀`의 공통 목적지와 FIFO는 11월 30일 최단거리 회상에 함께 넣는다.

## 웹 편집기에서 막힌 문법·API

- `void type not allowed here`는 `Math.min()`에 반환값이 없는 `void` 메서드를 인자로 넘겨서 발생했다. `Math.min()`은 값 두 개를 비교하며, 세 값은 `Math.min(a, Math.min(b, c))`로 비교한다.
- `Integer.MAX_VALUE`는 `java.lang`에 있어 별도 import 없이 쓴다. 미계산과 도달 불가를 같은 값으로 표현할 때는 계산 여부를 별도로 구분한다.
- 큐의 `remove(값)`은 값 하나를 찾아 제거하고 성공 여부를 반환한다. 빈 큐거나 값이 없으면 `false`다. `remove()`는 맨 앞 원소를 반환하며 빈 큐에서는 예외를 던진다. 앞 원소를 꺼낼 때 빈 큐를 `null`로 처리하려면 `poll()`을 사용한다.
- 문자열을 소문자로 바꿀 때 고정된 영문 키 비교에는 `city.toLowerCase(Locale.ROOT)`를 사용한다. `Locale`은 `java.util.Locale`에서 가져온다.
- `Only SELECT statements are allowed`는 채점기가 입력을 허용된 조회 문장으로 인식하지 못했다는 뜻이다. 문장이 여러 개로 쪼개졌는지, 별도 명령이 섞였는지 확인한다. 당시 실행에 사용한 쿼리는 확인되지 않았다.
- MySQL의 `SELECT` 별칭은 같은 쿼리의 `GROUP BY`, `HAVING`, `ORDER BY`에서 사용할 수 있다. 같은 쿼리의 `WHERE`에서는 원본 컬럼이나 계산식을 사용하고, 서브쿼리에서 만든 별칭은 바깥 `WHERE`에서 입력 컬럼으로 참조할 수 있다. [MySQL 공식 문서](https://dev.mysql.com/doc/refman/8.4/en/problems-with-alias.html)

## [Codex 학습 요약]

문제별 실제 풀이 시간은 Java 90분, SQL 23분으로 총 113분이다. Java는 첫 제출 통과 1문제와 미제출 1문제, SQL은 사용자 기록상 두 문제 모두 첫 제출 통과다.

- **숫자 변환하기 — C, 55분 / 목표 30분, 독립 풀이 실패·미제출.** 10분에 재귀 DP 설계를 잡았지만 도달 불가 상태를 재탐색했고 최대 입력에서 재귀 호출이 깊어져 런타임 오류가 났다. 반복문 DP와 역방향 BFS의 정답 코드를 학습했고, 숫자와 연산 횟수를 큐에 함께 저장하는 BFS를 로컬에 작성해 검증했다.
- D+1 생략. D+3 회상은 11월 30일 점검에 통합한다. 동일 문제 독립 재도전은 12월 2일 후보이며, 성공 후 7일 뒤 새 변형을 검토한다.
- **캐시 — B, 35분 / 목표 30분, 첫 제출 통과.** 10분에 LRU 흐름을 설계했다. 큐에서 적중한 도시를 꺼내 뒤로 보내는 구현이 정확했다. 용량 초과와 대소문자 조건을 제출 전에 수정했다. `Locale.ROOT`와 접근 순서 `LinkedHashMap` 개선안을 문제별 리뷰에 기록했다.
- `캐시` 복습은 11월 27일 D+1로 적중 직후 순서를 2분 회상하고, 11월 30일 시험 전 점검에서 용량 0·대소문자 조건과 구현을 비교한다. D+7 새 변형은 12월 3일 후보이며 동일 문제 재도전은 생략한다.
- **대여 횟수가 많은 자동차들의 월별 대여 횟수 구하기 — B, 10분 / 목표 25분.** 첫 제출 통과는 사용자 기록 기준이다. 차량 선정과 월별 건수 계산을 분리한 설계는 맞다. 로컬 저장본은 바깥 집계에 날짜 조건이 빠져 공식 예제의 7월·11월 행을 더 세었다. 개선안은 문제별 리뷰에 기록했다. 11월 29일 3분 회상 후보이며, 모의고사 보완과 겹치면 30일 SQL 점검에 통합한다.
- **조건에 부합하는 중고거래 댓글 조회하기 — A, 13분 / 목표 15분, 무힌트 첫 제출 통과.** 날짜 조건은 게시글 작성일, 출력과 첫 정렬은 댓글 작성일로 정확히 구분했다. 직접 JOIN으로 읽기 쉽게 정리한 쿼리를 리뷰에 남겼다. 동일 문제 재도전과 짧은 재작성은 생략한다.
- **짧은 복습 2/2 완료.** 서버 증설·등굣길 D+1에서 만료 및 시작값을, 프렌즈4블록 D+3에서 열 압축 순서를 회상했다.
