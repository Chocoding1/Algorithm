## Codex 분석

- 힌트 수준(Codex 판정): 작은 힌트. 특정 값에 대한 `Queue.remove(Object)`의 동작과 `String.toLowerCase()` 사용법을 확인했다.
- 복습 등급: B
- 등급 판정 근거: 10분에 설계를 확정했고 첫 제출로 통과했다. 용량 초과 처리와 대소문자 무시 조건을 제출 전에 고쳤고, 풀이 중 API를 확인했다. 실제 35분으로 목표 30분을 5분 초과했다.
- 목표 시간 달성: 아니오 (35분 / 30분)
- 첫 시도 성공: 예 (공식 오답 제출 0회)
- 공식 출제 의도 알고리즘: LRU. 문제에서 가장 오래 전에 사용한 항목을 내보내는 규칙을 지정한다. [프로그래머스 문제](https://school.programmers.co.kr/learn/courses/30/lessons/17680)
- Codex 추천 목표 알고리즘: 가장 오래 사용하지 않은 도시부터 가장 최근에 사용한 도시까지 순서를 유지한다.
- 공식 의도·Codex 목표 일치 여부: 일치. 큐의 맨 앞은 가장 오래 전에 사용한 도시다. 적중하면 기존 위치에서 삭제하고 맨 뒤에 다시 넣어 사용 시점을 갱신한다. 새 도시가 들어와 용량을 넘으면 맨 앞을 제거한다.
- 잘한 점: `remove(city)`의 반환값을 활용해 존재 여부 확인과 삭제를 한 번에 처리했다. 용량이 0이면 새 도시를 넣고 즉시 빼므로 요청마다 5가 더해진다.
- 코드 개선 포인트: `remove(city)`는 빈 큐에서도 `false`를 반환하므로 바깥 `isEmpty()` 검사를 줄일 수 있다. 기본 언어 설정에 상관없이 영문 도시를 비교하려면 `toLowerCase(Locale.ROOT)`를 사용한다. 멤버십 검사와 사용 순서를 함께 관리하는 `LinkedHashMap`으로 바꾸면 선형 탐색 비용도 줄어든다. [ArrayDeque 문서](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/ArrayDeque.html) · [String 문서](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/String.html#toLowerCase())
- 시간·공간복잡도: 도시 수가 `N`, 캐시 용량이 `K`이면 원본은 `remove(city)`가 최대 `K`개를 확인해 `O(N(K + 1))` 시간, 개선안은 해시 연산의 평균 비용 기준 `O(N)` 시간이다. 두 방식 모두 삽입 직후 최대 `K + 1`개를 보관하므로 보조 공간은 `O(K + 1)`이다. 도시명 길이는 최대 20이고 `K ≤ 30`이어서 현재 제한에서는 큐 풀이도 충분하다.
- 오류 분류: 구현·경계 조건·문자열 정규화
- 다음 문제에 적용할 규칙: 용량 제한이 있으면 용량 0, 가득 찼을 때의 적중, 가득 찼을 때의 신규 요청을 한 번씩 따라가 본다. 대소문자를 무시하는 입력은 조회 전 같은 규칙으로 변환한다.
- 로컬 검증: 사용자 코드는 공식 예제 6개를 통과했다. 사용자 코드와 개선안을 경계 입력 3개와 별도 기준 구현으로 계산한 무작위 입력 2,000개에서 비교했다. 터키어 환경에 용량 1과 `[IZMIR, izmir]`를 넣으면 사용자 코드는 10을, `Locale.ROOT` 개선안은 문제에서 요구한 6을 반환했다.

### 클린 코드 예시

```java
import java.util.LinkedHashMap;
import java.util.Locale;

class Solution {
    public int solution(int cacheSize, String[] cities) {
        LinkedHashMap<String, Boolean> cache = new LinkedHashMap<>(16, 0.75f, true);
        int totalTime = 0;

        for (String city : cities) {
            String key = city.toLowerCase(Locale.ROOT);
            boolean hit = cache.put(key, Boolean.TRUE) != null;
            totalTime += hit ? 1 : 5;

            if (cache.size() > cacheSize) {
                String oldest = cache.keySet().iterator().next();
                cache.remove(oldest);
            }
        }

        return totalTime;
    }
}
```

생성자의 마지막 인자 `true`는 접근 순서를 뜻한다. `put()`은 이전 값이 있었는지 알려주고, 기존 키도 가장 최근에 사용한 위치로 옮긴다. 값은 항상 `Boolean.TRUE`만 저장하므로 반환값이 `null`이면 새 도시다. 용량을 넘으면 순서상 첫 키를 제거한다. [LinkedHashMap 문서](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/LinkedHashMap.html)

적중이 교체 순서를 바꾸는 예는 용량 2에서 `[A, B, A, C, A]`다. 두 번째 `A`가 처리되면 순서가 `[B, A]`가 되고, 다음 `C`가 들어올 때 `B`가 빠진다. 마지막 `A`도 적중해 총 `5 + 5 + 1 + 5 + 1 = 17`이다.
