## Codex 분석

- 복습 등급: B
- 등급 판정 근거: 이전 코드·해설을 다시 보지 않고 5분 만에 설계를 확정해 목표 35분 안인 20분에 재도전을 성공했고, 구현 실수 없이 첫 제출로 통과했다. 다만 `정답 근거`에 각 가격이 스택에 한 번 들어가고 나온다는 시간복잡도와 인덱스 저장 이유만 적었고, 스택에 남은 인덱스가 아직 가격 하락을 만나지 않은 상태라는 불변식과 현재 가격이 첫 하락 시점임을 보장하는 이유가 빠졌으므로 B등급이다.
- 목표 시간 달성: 예 (20분 / 35분)
- 첫 시도 성공: 대상 아님 (동일 문제 재도전)
- 공식 출제 의도 알고리즘: 공식 의도 명시 없음
- Codex 추천 목표 알고리즘: 아직 가격 하락을 만나지 않은 인덱스를 단조 스택에 저장하고 현재 가격보다 큰 이전 가격의 지속 시간을 확정하는 `O(N)` 풀이
- 공식 의도 일치 여부: 공식 의도 명시 없음
- Codex 목표 일치 여부: 일치 (정답 코드 없이 독립 재현)
- 실제 풀이와 의도 알고리즘 비교: 현재 코드는 Deque의 뒤쪽을 스택의 top으로 사용한다. 현재 가격보다 큰 가격을 뒤에서부터 꺼내 `현재 인덱스 - 이전 인덱스`로 지속 시간을 확정하고, 끝까지 남은 인덱스는 마지막 시점까지의 시간을 기록하므로 목표 단조 스택 풀이와 일치한다.
- 풀이 전 사고와 실제 코드의 차이: 풀이 전에는 가격과 인덱스를 함께 저장하겠다고 설계했고 실제로 `int[]{가격, 인덱스}`를 저장했다. `offer()`·`peekLast()`·`pollLast()`를 같은 끝에서 사용해 스택 동작을 정확히 구현했다.
- 의도 알고리즘 추가 학습 이유: 핵심 알고리즘은 독립적으로 재현했으므로 새로운 알고리즘 학습은 필요하지 않다. 다만 입력 배열에서 가격을 다시 읽을 수 있으므로 스택에는 인덱스만 저장하면 상태가 더 단순해지고, 단조성·정답 확정 조건도 더 직접적으로 드러난다.
- 풀이 직후 확인한 의도 알고리즘: 스택에는 아직 더 낮은 가격을 만나지 않은 인덱스만 저장한다. 현재 가격보다 스택 위 인덱스의 가격이 큰 동안 꺼내 지속 시간을 확정한다. 현재 가격보다 작거나 같은 가격을 만나면 그 아래 가격들도 현재 값으로는 하락이 확정되지 않으므로 검사를 멈춘다. 끝까지 남은 인덱스는 마지막 인덱스까지의 시간을 기록한다.
- 대안 학습 상태: 완료 (2026-10-05 정답 코드 없이 독립 재현)
- 코드 개선 포인트: **상수 메모리·가독성 개선** — `int[]`마다 가격과 인덱스를 새로 만들 필요 없이 인덱스만 `Deque<Integer>`에 저장하고 가격은 `prices[index]`로 조회할 수 있다. 시간·공간의 점근 복잡도는 그대로 `O(N)`이지만 작은 배열 객체 생성을 없애고 스택의 목적을 명확하게 만든다.
- 클린 코드 예시:

```java
public int[] solution(int[] prices) {
    int[] answer = new int[prices.length];
    Deque<Integer> stack = new ArrayDeque<>();

    for (int current = 0; current < prices.length; current++) {
        while (!stack.isEmpty()
                && prices[stack.peek()] > prices[current]) {
            int previous = stack.pop();
            answer[previous] = current - previous;
        }

        stack.push(current);
    }

    int lastIndex = prices.length - 1;
    while (!stack.isEmpty()) {
        int index = stack.pop();
        answer[index] = lastIndex - index;
    }

    return answer;
}
```

- 풀이 후 새로 배운 점: ① `offer()`·`peekLast()`·`pollLast()`로 뒤쪽을 top으로 사용해도 올바른 스택이며, `push()`·`peek()`·`pop()`으로 앞쪽을 top으로 써도 된다. ② 입력 배열에 값이 남아 있으면 답 계산에 필요한 인덱스만 저장해 중복 데이터를 줄일 수 있다. ③ 복잡도와 별개로 스택에는 아직 첫 하락을 만나지 않은 인덱스만 남는다는 불변식이 정답성을 보장한다.
- 다음 문제에 적용할 한 문장 규칙: 오른쪽의 첫 조건 만족 위치를 찾을 때 현재 값이 과거 후보를 확정할 수 있다면, 답 계산에 필요한 인덱스만 단조 스택에 저장한다.
- 복습에 포함할 학습 포인트: 현재 가격보다 큰 인덱스만 제거하는 이유, 더 작거나 같은 가격에서 멈춰도 되는 단조성, 가격 대신 인덱스만 저장하는 이유, 각 인덱스가 한 번 들어가고 나와 `O(N)`인 이유.
- 오류 분류: 없음 (정확성 설명 보완)
- 잘한 점: 최초 풀이에서 떠올리지 못했던 역방향 관점과 단조 스택을 이전 코드 없이 5분 만에 설계했고, 20분 안에 구현해 첫 제출로 통과했다. Deque의 뒤쪽 API도 일관되게 사용했다.
- 개선할 점: 정답 근거에는 `O(N)`뿐 아니라 스택에 남아 있는 원소의 의미, 현재 가격이 제거되는 원소의 첫 하락인 이유와 남은 원소의 종료 처리를 설명한다.
- 유형 인식 신호: 각 원소의 오른쪽에서 처음 더 작은 값을 찾음, 현재 값 하나가 여러 이전 원소의 답을 확정함, 아직 답이 없는 후보들이 단조 관계를 이룸.
- 다음에 적용할 규칙: 미래를 각 시작점에서 반복 탐색하지 말고 현재 원소가 이전 미확정 후보를 제거할 수 있는지 확인한다.
- 시간복잡도: `O(N)` — 각 인덱스가 스택에 한 번 들어가고 최대 한 번 제거된다.
- 공간복잡도: `O(N)` — 가격이 떨어지지 않으면 모든 인덱스가 스택에 남을 수 있다.
- 정답 검증: Java 21에서 컴파일했고 공개 예제가 `[4, 3, 1, 1, 0]`으로 일치했다. 길이 2~8, 가격 1~5의 488,275개 입력을 `O(N²)` 단순 풀이와 비교해 결과가 모두 일치했다.
