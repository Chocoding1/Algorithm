## 풀이 전 핵심 기록 - 사용자 작성

- 문제와 제한·목표 복잡도: 숫자는 최대 1000000자리. 따라서 O(N), O(NlogN) 가능할 것으로 예상
- 가장 단순한 풀이와 병목: 모든 경우의 수를 완전 탐색으로 k만큼 빼면서 비교. O(N^2)으로 실패할 것으로 예상
- 확정한 설계와 처리 흐름: 스택을 활용하여 각 자리의 숫자를 스택에 넣고 다음 숫자가 더 크다면 삭제. k개를 삭제한 경우의 숫자를 반환
- 정답 근거와 핵심 엣지 케이스: 스택을 활용하면 각 숫자들이 한 번씩만 스택에 들어갔다 나오기 때문에 O(N)으로 처리가능. 스택에 들어가 있는 숫자는 앞의 숫자보다는 무조건 작기 때문에 맨 앞의 숫자가 가장 크다. 따라서 가장 큰 수를 보장한다.
- 출제 의도 알고리즘 추측: 재도전이므로 생략 가능

- 풀이 전 사고와 실제 코드의 차이: 설계한 흐름이 코드에 그대로 반영됐다. 완전탐색이 불가능하다는 결론은 맞지만, 모든 삭제 조합의 수는 일반적으로 `O(N²)`가 아니라 `C(N, k)`이며 각 결과 구성·비교 비용까지 고려해야 한다. 선택한 스택 풀이는 최대 길이 1,000,000에서도 `O(N)`이다.
- 코드 개선 포인트: **상수 비용·가독성 개선** — 숫자 문자의 순서는 문자 코드 순서와 같으므로 `- '0'` 변환 없이 `stack.peekLast() < current`로 비교할 수 있다. `ArrayDeque<Character>`의 박싱까지 줄이려면 `char[]`을 스택처럼 사용할 수 있다. 빅오 변화는 없다.
- 클린 코드 예시:

```java
// 프로그래머스 Lv.2
public class 큰_수_만들기_재도전 {

    public String solution(String number, int k) {
        char[] selected = new char[number.length()];
        int size = 0;
        int removed = 0;

        for (int i = 0; i < number.length(); i++) {
            char current = number.charAt(i);

            while (size > 0
                    && removed < k
                    && selected[size - 1] < current) {
                size--;
                removed++;
            }

            selected[size++] = current;
        }

        return new String(selected, 0, number.length() - k);
    }
}
```

- 풀이 후 새로 배운 점: 현재 숫자보다 작은 직전 후보를 제거하면 결과의 더 앞자리가 커지므로 같은 길이의 다른 결과보다 작아질 수 없다. 정답을 보장하는 핵심은 덱의 맨 앞 숫자가 전체에서 가장 크다는 것이 아니라, **같은 길이의 후보를 앞자리부터 비교할 때 가능한 가장 큰 숫자를 가장 이른 위치에 남긴다**는 점이다. 삭제 횟수를 모두 사용한 뒤에는 뒤에 더 큰 숫자가 추가될 수 있어 덱 전체의 단조성은 보장되지 않는다. 입력이 내림차순이거나 같은 숫자만 있어 순회 중 충분히 제거하지 못하면 뒤에서 남은 개수를 제거한다.
- 다음 문제에 적용할 한 문장 규칙: **길이가 고정된 결과의 크기가 앞자리부터 결정된다면, 제한된 횟수 안에서 현재 값보다 작은 직전 후보를 버릴 수 있는지 확인한다.**
- 복습에 포함할 학습 포인트: 앞자리 교체가 안전한 이유, 내림차순·동일 숫자에서 뒤를 제거하는 이유, 각 문자가 최대 한 번 들어가고 나와 `O(N)`인 근거, 완전탐색의 조합 복잡도
- 오류 분류: 정답성 근거 — 덱 전체의 단조성과 맨 앞 숫자만으로 전체 최댓값을 설명함; 완전탐색 복잡도 표기도 함께 보완
- 시간복잡도: `O(N)` — 각 문자는 한 번 추가되고 최대 한 번 제거됨
- 공간복잡도: `O(N)` — 선택한 숫자를 덱에 저장
