## Codex 분석

- 힌트 수준(Codex 판정): 없음 — 정답 제출 후 실행 순서와 `COUNT(NAME)`의 `NULL` 처리를 설명했으므로 풀이 힌트로 집계하지 않음
- 복습 등급: A
- 등급 판정 근거: 25분 목표 안인 4분에 `GROUP BY`·`HAVING`·정렬을 독립적으로 구성하고 문법·결과 오류 없이 첫 제출로 통과함
- 목표 시간 달성: 예 (4분 / 25분)
- 첫 시도 성공: 예
- 핵심 문법: `GROUP BY`, `COUNT(column)`, `HAVING`, `ORDER BY`
- 결과 한 행의 단위: 두 번 이상 사용된 동물 이름 하나와 그 이름을 가진 동물의 수
- 쿼리 데이터 흐름: `FROM ANIMAL_INS`의 동물별 행을 `NAME`별로 묶고, `HAVING COUNT(NAME) >= 2`로 이름이 두 번 이상 등장한 그룹만 남긴 뒤 이름과 개수를 출력하고 이름순으로 정렬함
- 중복·NULL·JOIN 카디널리티 확인: 같은 이름의 여러 동물 행은 이름 그룹 하나로 축약된다. `NAME IS NULL`인 그룹에서 `COUNT(NAME)`은 0이므로 `HAVING`을 통과하지 못한다. JOIN은 없다.
- 정답 검증: 프로그래머스 첫 제출 통과
- 코드 개선 포인트: 개선 불필요 — `COUNT(NAME)`을 사용해 `NULL` 그룹을 별도 `WHERE` 없이 제외하는 현재 쿼리가 정확하고 간결하다.
- 클린 쿼리 예시: 현재 원본 쿼리와 동일하므로 생략
- 풀이 후 새로 배운 점: 논리적 실행 순서는 `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`이며, `WHERE`는 원본 행을, `HAVING`은 집계된 그룹을 거른다. `COUNT(NAME)`은 `NULL`을 세지 않지만 `COUNT(*)`는 `NULL` 이름 그룹의 행도 센다.
- 오류 분류: 없음
- 다음에 적용할 규칙: **집계값을 조건으로 그룹을 거를 때는 `HAVING`을 사용하고, `COUNT(column)`과 `COUNT(*)` 중 `NULL`을 셀 것인지 먼저 결정한다.**
