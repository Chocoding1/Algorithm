## Codex 분석

- 힌트 수준(Codex 판정): 없음 — 정답 제출 후 `COUNT(DISTINCT NAME)`과 `GROUP BY`의 결과 행 차이를 설명했으므로 풀이 힌트로 집계하지 않음
- 복습 등급: B
- 등급 판정 근거: 이전 쿼리를 다시 확인하지 않고 5분 안에 `COUNT(DISTINCT NAME)`을 작성해 첫 제출로 통과했지만, 제출 후 `DISTINCT`가 필요한 이유와 `GROUP BY`로 풀 때 외부 집계가 필요한 이유를 다시 확인해 결과 행 단위에 대한 개념 복습이 필요함
- 목표 시간 달성: 예 (5분 / 5분)
- 첫 시도 성공: 대상 아님
- 핵심 문법: `COUNT(DISTINCT column)`
- 결과 한 행의 단위: `ANIMAL_INS` 전체에서 `NULL`을 제외한 서로 다른 동물 이름의 개수 하나
- 쿼리 데이터 흐름: `FROM ANIMAL_INS`의 전체 입소 행에서 `COUNT(DISTINCT NAME)`이 `NAME`의 `NULL`을 제외하고 중복 값을 하나로 합쳐 단일 집계 결과를 만듦
- 중복·NULL·JOIN 카디널리티 확인: `DISTINCT`가 같은 이름을 한 번만 세고, `COUNT(column)` 규칙에 따라 `NAME IS NULL`인 행은 세지 않는다. JOIN이 없어 원본 행 증가는 없다.
- 정답 검증: 프로그래머스 첫 제출 통과
- 코드 개선 포인트: 개선 불필요 — 문제의 단일 집계값을 가장 직접적으로 표현한 쿼리다.
- 클린 쿼리 예시: 현재 원본 쿼리와 동일하므로 생략
- 풀이 후 새로 배운 점: `GROUP BY NAME`은 이름마다 여러 결과 행을 만들고, `COUNT(DISTINCT NAME)`은 서로 다른 이름의 총개수를 한 행으로 반환한다. `GROUP BY`로 같은 결과를 내려면 이름별 하위 결과를 만든 뒤 바깥 쿼리에서 다시 `COUNT(*)` 해야 한다.
- 오류 분류: 개념 설명 보완 — 쿼리는 정확했지만 `DISTINCT`와 그룹 결과 행 단위의 차이를 제출 후 재확인
- 다음에 적용할 규칙: **종류별 여러 행이 필요한지, 서로 다른 종류의 총개수 한 행이 필요한지 먼저 결정한 뒤 `GROUP BY`와 `COUNT(DISTINCT ...)`를 선택한다.**
