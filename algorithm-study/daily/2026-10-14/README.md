## 짧은 복습 — 총 5~10분

- `두 큐 합 같게 만들기` D+3: 완료(2026-10-15) — 목표 합과의 대소에 따른 이동 방향을 설명했고, 반복 상한은 불가능한 경우의 상태 반복을 막는 종료 기준임을 확인했다. 합계를 `long`으로 계산하는 이유는 타입 오류가 아니라 정수 오버플로 방지로 바로잡았다.
- `네트워크` D+3: 완료(2026-10-15) — `1-3-2` 반례로 DFS가 더 작은 번호의 이웃도 확인해야 함을 설명했고, 인접 행렬의 모든 행과 열을 확인하므로 `O(N²)`임을 설명했다.

## 중간 평가

- `큰 수 만들기`는 이전 풀이에 관한 추가 힌트 없이 3분 만에 선택 규칙을 재현하고 17분에 첫 제출로 통과했다. 핵심 구현은 독립 재현했지만 덱 전체가 항상 단조롭고 맨 앞 숫자가 가장 크기 때문에 정답이라는 근거는 정확하지 않아 재도전 B등급이다.
- 현재 덱 풀이는 정확한 `O(N)`이다. 문자에 `- '0'`을 적용하지 않고 직접 비교할 수 있으며, `char[]` 스택으로 박싱을 없앤 클린 코드 예시는 문제별 `review.md`에 기록했다. 원본 Java는 수정하지 않았다.
- 정답성의 핵심은 같은 길이의 후보를 앞자리부터 비교할 때 가능한 큰 숫자를 더 이른 위치에 남기는 것이다. 이를 10월 15일 D+1에서 먼저 설명하고, 완전탐색의 `C(N, k)` 복잡도와 함께 10월 17일 D+3에서 다시 회상한 뒤 10월 21일 신규 변형으로 전이를 확인한다.
- `소수 찾기`는 7분 만에 순열 DFS를 독립 설계했지만 35분 목표를 1분 초과했고, 소수 판정에서 제곱근과 같은 약수를 제외해 오답 1회 후 작은 힌트로 수정했으므로 B등급이다. 기존 상태 공간 탐색의 신규 전이는 부분 성공으로 기록한다.
- 재귀 중간의 `normalize()`와 길이별 DFS는 정답 통과에는 성공했지만 상태의 길이와 사용한 조각 수를 다르게 만든다. 선행 0은 정수 변환과 `Set<Integer>`로 처리하고, 한 번의 DFS에서 각 깊이의 정수를 후보로 저장하는 클린 코드를 문제별 `review.md`에 기록했다. 원본 Java는 수정하지 않았다.
- SQL `중복 제거하기`는 이전 쿼리 없이 5분에 `COUNT(DISTINCT NAME)`을 재현해 첫 제출로 통과했다. 다만 제출 후 `GROUP BY`와 단일 집계 결과의 차이를 다시 확인했으므로 재도전 B등급이며 10월 17일에 5분 이내로 짧게 설명·재작성한다.
- SQL `동명 동물 수 찾기`는 `GROUP BY → HAVING → SELECT → ORDER BY` 흐름과 `COUNT(NAME)`의 `NULL` 제외를 정확히 적용해 4분에 첫 제출로 통과했으므로 A등급이다. 제출 후 실행 순서와 `COALESCE`를 질문한 내용은 풀이 힌트가 아닌 추가 학습으로 기록했다.
