- 핵심 문법: 필요한 컬럼 `SELECT`, `WHERE ... LIKE`, `ORDER BY` 오름차순
- 결과 한 행의 단위: 주소가 강원도 조건을 만족하는 식품공장 한 곳
- 쿼리 데이터 흐름: `FOOD_FACTORY`의 공장 행을 읽고 → 주소에 강원도가 포함된 행만 남기고 → 필요한 세 컬럼을 선택한 뒤 → 공장 ID 오름차순으로 정렬
- 중복·NULL·JOIN 카디널리티 확인: 조인·그룹화가 없어 공장 행이 추가되거나 축약되지 않는다. `ADDRESS`는 문제 스키마에서 `NULL`이 아니므로 `LIKE`의 `NULL` 결과를 따로 처리할 필요가 없다.
- 정답 검증: 선택 컬럼과 정렬 방향이 요구사항과 일치하고, 제출 결과로 현재 데이터에서 문자열 조건도 검증됨
- 코드 개선 포인트: 주소 체계상 강원도 주소는 `강원도`로 시작하므로 `LIKE '%강원도%'`보다 `LIKE '강원도%'`가 조건을 더 정확히 표현한다. 선행 `%`가 없으면 일반적인 B-tree 인덱스의 접두 범위 탐색 가능성도 생긴다. 점근 복잡도 보장 변경이 아니라 의미 정확성과 실행 계획 가능성 개선이다.
- 클린 쿼리 예시:

```sql
SELECT FACTORY_ID, FACTORY_NAME, ADDRESS
FROM FOOD_FACTORY
WHERE ADDRESS LIKE '강원도%'
ORDER BY FACTORY_ID ASC;
```

- 풀이 후 새로 배운 점: `%값%`은 어디에든 포함, `값%`은 해당 값으로 시작, `%값`은 해당 값으로 끝나는 문자열을 찾는다. 조건이 접두사라면 선행 `%`를 붙이지 않는다.
- 오류 분류: 없음 — 원본 쿼리는 제출 통과했으며 패턴을 더 정확히 표현할 개선점만 있음
- 다음에 적용할 규칙: 문자열 조건을 읽을 때 포함·시작·끝 중 무엇인지 먼저 구분하고 그에 맞는 위치에만 `%`를 둔다.
