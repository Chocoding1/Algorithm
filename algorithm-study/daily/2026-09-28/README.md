## 오늘의 평가

- 두 문제 모두 최종 성공했다. `기능개발`은 목표 시간과 설계 확정 시점을 지켰고, `전화번호 목록`은 모든 쌍 비교의 병목을 찾았지만 작은 힌트와 문자열 정렬 성질 확인이 필요했다.
- `전화번호 목록`은 사전순 정렬 후 인접 비교라는 유효한 대안으로 해결했다. 해시 진접두사 조회와 `startsWith()`를 풀이 직후 추가로 학습했다.
- `기능개발`은 입력 크기를 근거로 `O(N²)` 풀이가 가능함을 정확히 판단했다. 작업별 완료일을 한 번만 계산하고 배포 기준일로 묶는 `O(N)` 방식, 정수 올림 나눗셈과 순서 보장 불변식을 추가로 학습했다.
- 다음 과제는 복잡도가 제한을 만족한다는 설명과 정답을 보장하는 이유를 분리하고, 전체 상태를 반복 갱신하기 전에 각 원소의 완료 시점을 직접 계산할 수 있는지 확인하는 것이다.

## 풀이 후 새로 배운 점

### 전화번호 목록

- 사전순 정렬은 길이순이 아니지만 접두사 관계의 문자열을 같은 구간에 모으므로 인접 비교가 가능하다.
- 해시 집합에 전체 번호를 저장하고 각 번호의 진접두사를 조회하는 방법도 있다.
- `startsWith()`를 사용하면 `substring()` 임시 문자열과 길이 범위 오류 가능성을 줄일 수 있다.

### 기능개발

- 작업별 완료일을 한 번 계산해 배포 기준일과 비교하면 `O(N²)` 진행률 갱신을 `O(N)`으로 줄일 수 있다.
- 큐 유형이라도 배열을 앞에서부터 처리하면 별도의 `Queue` 객체가 반드시 필요한 것은 아니다.
- 양의 정수 올림 나눗셈은 `(a + b - 1) / b`로 계산할 수 있다.
- 다음 작업의 완료일이 현재 배포 기준일 이하이면 같은 배포 묶음이라는 불변식이 순서를 보장한다.
