## 풀이 전 핵심 기록 - 사용자 작성

- 문제와 제한·목표 복잡도: 배열의 최대 길이가 1000000이므로 O(N), O(NlogN)이 가능할 것으로 판단
- 가장 단순한 풀이와 병목: 인덱스 두 개를 사용해서 두 인덱스 범위에 있는 수들의 합이 k보다 작으면 right + 1, 크면 left + 1을 하며 슬라이딩 윈도우처럼 이동한다. 그러면서 k와 동일한 경우 길이를 체크하고, 길이가 작으면 초기화 및 인덱스 저장, 같을 경우 시작인덱스가 더 작은 경우에만 수정, 크면 수정 없이 진행. 각 숫자는 딱 한 번만 탐색하므로 O(N)으로 예상하고 병목은 없을 것으로 예상
- 확정한 설계와 처리 흐름: 위의 설명과 동일
- 정답 근거와 핵심 엣지 케이스: 모든 수들을 탐색하고, 두 인덱스 사이의 모든 수들을 더하기 때문에 항상 부분 수열을 만족하며, 두 인덱스를 통해 가장 작은 인덱스와 가장 짧은 부분수열을 체크할 수 있다.
- 출제 의도 알고리즘 추측: 선택 항목, Codex 피드백 전에 작성

- 실제 풀이와 의도 알고리즘 비교: `left`와 `right` 사이의 합을 유지하고, 합이 `k`보다 작을 때 오른쪽 경계를 늘리고 크거나 같을 때 왼쪽 경계를 줄였다. 모든 원소가 양수이므로 경계 이동에 따른 합의 방향이 정해져 있고, 두 경계가 뒤로 돌아가지 않아 전체를 선형 시간에 탐색한다.
- 풀이 전 사고와 실제 코드의 차이: 설계한 흐름을 그대로 구현했다. 회고에는 같은 길이면 시작 인덱스가 더 작은 경우 갱신한다고 적었지만 실제 코드는 더 짧을 때만 갱신한다. 구간을 시작 인덱스 순서로 발견하므로 같은 길이의 첫 후보가 이미 가장 앞선 후보여서 현재 구현도 정확하다.
- 코드 개선 포인트: **가독성 개선** — 현재 코드의 복잡도와 정확성은 충분하다. `right`를 `for`문으로 증가시키고 합이 `k`보다 큰 동안만 `left`를 이동하면 경계 검사와 `continue`를 줄일 수 있다. 빅오 개선은 아니며 `bestLength`를 별도로 두면 길이 비교의 의미도 더 분명해진다.
- 클린 코드 예시:

```java
// 프로그래머스 Lv.2
public class 연속된_부분_수열의_합 {

    public int[] solution(int[] sequence, int k) {
        int left = 0;
        int sum = 0;
        int bestStart = 0;
        int bestEnd = sequence.length - 1;

        for (int right = 0; right < sequence.length; right++) {
            sum += sequence[right];

            while (sum > k) {
                sum -= sequence[left++];
            }

            if (sum == k && right - left < bestEnd - bestStart) {
                bestStart = left;
                bestEnd = right;
            }
        }

        return new int[]{bestStart, bestEnd};
    }
}
```

- 풀이 후 새로 배운 점: `O(N)`의 정확한 근거는 각 숫자를 단순히 한 번 본다는 표현보다, 오른쪽 경계가 각 원소를 한 번 포함하고 왼쪽 경계가 각 원소를 최대 한 번 제외해 두 경계의 총 이동 횟수가 `2N` 이하라는 것이다. 이 이동 규칙은 원소가 모두 양수여서 오른쪽을 늘리면 합이 증가하고 왼쪽을 늘리면 합이 감소하기 때문에 성립한다.
- 다음 문제에 적용할 한 문장 규칙: **양수 연속 구간에서 합을 맞춰야 하면 두 경계가 합을 어느 방향으로 바꾸는지 확인하고, 각 경계가 뒤로 가지 않으면 `O(N)` 투 포인터를 검토한다.**
- 복습에 포함할 학습 포인트: 양수 조건이 경계 이동을 보장하는 이유, 두 경계의 총 이동 횟수로 설명하는 `O(N)`, 같은 길이에서 먼저 발견한 구간이 가장 앞선 이유
- 오류 분류: 없음
- 시간복잡도: `O(N)` — `right`와 `left`가 각각 배열 끝까지 최대 한 번 이동함
- 공간복잡도: `O(1)` — 입력과 반환 배열 외에 합계와 인덱스 변수만 사용함
