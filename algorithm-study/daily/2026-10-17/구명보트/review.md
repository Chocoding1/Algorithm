- 실제 풀이와 의도 알고리즘 비교: 오름차순 정렬 후 매 반복에서 가장 무거운 사람은 반드시 태우고, 가장 가벼운 사람과 합이 제한 이하면 둘을 함께 처리했다. 합이 제한을 넘으면 다른 모든 사람은 가장 가벼운 사람 이상이므로 누구도 가장 무거운 사람과 함께 탈 수 없다. 따라서 가장 무거운 사람을 혼자 보내는 선택이 강제된다는 안전성을 이용한다.
- 풀이 전 사고와 실제 코드의 차이: 처음에는 가벼운 사람부터 무게 합이 찰 때까지 한 보트에 계속 넣었지만, 이는 최대 2명 제약을 위반하고 가벼운 사람끼리 먼저 묶어 무거운 사람과 함께 탈 기회를 없앨 수 있었다. 힌트 후에는 가장 무거운 사람을 매번 확정하는 양 끝 선택으로 전환했다.
- 코드 개선 포인트: **가독성 개선** — 현재 코드는 정확하고 충분히 효율적이다. 다만 조건식 안에서 `right--`를 수행하면 평가 순서를 따라가야 하므로, 두 인덱스의 이동을 조건문 밖에 분리하고 `left <= right`인 동안 보트 한 대를 처리하면 남은 한 명을 위한 별도 조건도 제거할 수 있다. 빅오 개선은 아니다.
- 클린 코드 예시:

```java
import java.util.Arrays;

// 프로그래머스 Lv.2
public class 구명보트 {

    public int solution(int[] people, int limit) {
        Arrays.sort(people);

        int left = 0;
        int right = people.length - 1;
        int boats = 0;

        while (left <= right) {
            if (left < right && people[left] + people[right] <= limit) {
                left++;
            }
            right--;
            boats++;
        }

        return boats;
    }
}
```

- 풀이 후 새로 배운 점: 최소 보트 수를 만들려면 한 보트의 무게를 단순히 최대한 채우는 것이 아니라, 반드시 처리해야 하는 가장 무거운 사람의 짝을 결정해야 한다. 가장 가벼운 사람과도 함께 탈 수 없다면 누구와도 함께 탈 수 없으므로 혼자 보내는 선택이 강제된다. 함께 탈 수 있다면 가장 가벼운 사람을 붙여 더 무거운 사람을 이후 조합 가능성으로 남기는 것이 안전하다.
- 다음 문제에 적용할 한 문장 규칙: **한 번에 태울 수 있는 수가 제한된 최소 묶음 문제에서는 가장 제약이 큰 대상을 먼저 확정하고, 가장 여유로운 대상과 함께 처리할 수 있는지 확인한다.**
- 복습에 포함할 학습 포인트: 최대 2명 제약, 가장 무거운 사람이 혼자 타야 하는 조건, 가장 가벼운 사람과 짝짓는 선택의 안전성, 정렬 때문에 생기는 `O(N log N)`
- 오류 분류: 인식·설계 — 최대 탑승 인원 제약 누락과 가벼운 사람부터 누적하는 잘못된 묶음 기준
- 시간복잡도: `O(N log N)` — 정렬이 지배하고, 정렬 후 두 인덱스 순회는 `O(N)`
- 공간복잡도: `O(log N)` — Java의 기본형 배열 정렬이 사용하는 호출 스택 기준이며 별도 자료구조는 없음
