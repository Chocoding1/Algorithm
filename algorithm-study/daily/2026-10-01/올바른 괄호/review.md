## Codex 분석

- 복습 등급: B
- 등급 판정 근거: 목표 20분 안인 10분에 힌트·오답·구현 실수 없이 첫 제출로 통과했고, 2분 30초 만에 스택 설계를 확정했다. 다만 `정답 근거`에 각 괄호가 한 번 삽입·삭제되어 `O(N)`이라는 복잡도만 적고, 모든 접두사에서 닫는 괄호가 여는 괄호보다 많아지면 안 되며 마지막에 미결 여는 괄호가 없어야 한다는 정확성 불변식이 빠졌으므로 B등급이다.
- 목표 시간 달성: 예 (10분 / 20분)
- 첫 시도 성공: 예
- 공식 출제 의도 알고리즘: 공식 의도 명시 없음
- Codex 추천 목표 알고리즘: 왼쪽부터 순회하며 아직 닫히지 않은 여는 괄호의 수를 상태로 유지하고, 음수가 되는 접두사를 즉시 실패 처리
- 공식 의도 일치 여부: 공식 의도 명시 없음
- Codex 목표 일치 여부: 일치 (스택으로 같은 상태를 명시적으로 표현)
- 실제 풀이와 의도 알고리즘 비교: 현재 코드는 `(`를 스택에 넣고 `)`를 만날 때 하나를 제거한다. 빈 스택에서 `)`를 만나면 즉시 실패하고, 순회가 끝났을 때 스택이 비어 있어야 성공하므로 문제 조건을 정확히 구현했다. 다만 괄호 종류가 하나뿐이라 스택의 문자 자체는 필요하지 않고 미결 여는 괄호 개수만 유지해도 된다.
- 풀이 전 사고와 실제 코드의 차이: 풀이 전 2분 30초 만에 정한 스택 설계를 그대로 구현했다. 메모에서는 `O(N)`이라는 성능 근거만 확인했지만 실제 코드에는 빈 스택 조기 실패와 마지막 빈 스택 검사라는 정확성 조건도 올바르게 들어갔다.
- 의도 알고리즘 추가 학습 이유: 사용한 스택 풀이는 정확하지만, 저장된 모든 문자가 동일한 `(`이므로 자료구조 대신 정수 상태 하나로 단순화할 수 있다. 이 변환을 통해 문제에 필요한 최소 상태와 정확성 불변식을 더 선명하게 볼 수 있다.
- 풀이 직후 확인한 의도 알고리즘: `opened`는 지금까지 처리한 접두사에서 아직 짝을 찾지 못한 `(`의 개수다. `(`이면 증가시키고, `)`일 때 0이면 즉시 실패하며 아니면 감소시킨다. 모든 문자를 처리한 뒤 0일 때만 전체 괄호가 올바르다.
- 대안 학습 상태: 완료 (스택 풀이와 `O(1)` 카운터 풀이 비교)
- 코드 개선 포인트: **공간·가독성 개선** — `Stack<Character>`에 같은 문자만 저장하지 않고 정수 카운터 하나로 미결 여는 괄호 수를 표현하면 공간복잡도가 `O(N)`에서 `O(1)`로 줄고 불변식도 코드에 직접 드러난다. 실제 스택이 필요한 문제라면 레거시 `Stack`보다 `ArrayDeque`를 우선 사용한다.
- 클린 코드 예시:

```java
boolean solution(String s) {
    int opened = 0;

    for (int i = 0; i < s.length(); i++) {
        if (s.charAt(i) == '(') {
            opened++;
        } else if (opened == 0) {
            return false;
        } else {
            opened--;
        }
    }

    return opened == 0;
}
```

- 풀이 후 새로 배운 점: ① 자료구조에 저장되는 값이 모두 같고 개수만 필요하면 카운터로 상태를 축약할 수 있다. ② 올바른 괄호의 핵심은 모든 접두사에서 미결 여는 괄호 수가 음수가 되지 않고 최종값이 0인 것이다. ③ 복잡도는 실행 가능성을 설명하고 불변식은 정답성을 설명한다.
- 다음 문제에 적용할 한 문장 규칙: 스택에 저장하는 값의 종류와 순서가 실제로 필요한지 확인하고, 개수만 필요하다면 정수 상태로 축약한다.
- 복습에 포함할 학습 포인트: 모든 접두사에서 `opened >= 0`이어야 하는 이유, 마지막 `opened == 0`이 필요한 이유, 스택과 카운터 풀이의 공간복잡도 차이를 코드 없이 설명한다.
- 오류 분류: 없음 (정확성 설명 보완)
- 잘한 점: 입력 길이 100,000을 보고 처음부터 `O(N)` 풀이를 선택했고, 2분 30초 만에 설계를 확정했다. 닫는 괄호를 만났을 때 빈 스택을 먼저 검사해 잘못된 접두사를 조기에 종료했고, 마지막에 남은 여는 괄호까지 정확히 검증해 첫 제출로 통과했다.
- 개선할 점: 정답 근거에는 연산 횟수가 아니라 처리한 접두사에서 유지되는 상태와 성공·실패 조건을 적는다. 이 문제에서는 `미결 여는 괄호 수는 음수가 될 수 없고 마지막에는 0이어야 한다`가 핵심이다.
- 유형 인식 신호: 왼쪽부터 처리하는 짝 맞추기, 닫는 기호가 앞선 여는 기호를 소비함, 중간 접두사에서 즉시 실패 가능, 끝에 미결 상태가 남으면 실패.
- 다음에 적용할 규칙: 괄호·짝 맞추기 문제에서는 접두사 불변식과 마지막 잔여 상태를 별도로 확인한다.
- 시간복잡도: `O(N)` — 문자열을 한 번 순회한다.
- 공간복잡도: 현재 스택 코드는 최악 `O(N)`, 카운터 개선 코드는 `O(1)`.
- 정답 검증: Java 21에서 컴파일했고 공개 예제 4개가 `true`, `true`, `false`, `false`로 일치했다. `)`로 시작하는 경우는 즉시 실패하고, `(`가 남는 경우는 마지막 검사에서 실패한다.
