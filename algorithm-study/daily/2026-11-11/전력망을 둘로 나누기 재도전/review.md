## Codex 분석

- 힌트 수준(Codex 판정): 없음
- 복습 등급: B
- 등급 판정 근거: 이전 코드·회고를 보지 않고 간선 제외 → DFS 연결 요소 크기 반환 → 두 크기의 차 계산을 독립적으로 재현해 첫 제출로 통과했다. 다만 30분 목표를 15분 초과했고, DFS 반환 후 방문 해제를 누락한 구현 실수가 있어 안정적 성공인 A가 아닌 B로 판정한다.
- 목표 시간 달성: 미달성(30분 목표, 45분 사용)
- 첫 시도 성공: 재도전 문제로 대상 아님
- 공식 출제 의도 알고리즘: 모든 전선을 하나씩 끊어 보고 DFS/BFS로 두 전력망의 크기를 계산하는 완전탐색
- Codex 추천 목표 알고리즘: 간선 하나를 제외한 트리에서 DFS로 한쪽 연결 요소 크기를 구하는 방법
- 실제 풀이와 의도 알고리즘 비교: 일치. 모든 전선을 후보로 제외하고 1번 송전탑에서 도달하는 정점 수를 재귀적으로 합산했다.
- 풀이 전 사고와 실제 코드의 차이: 설계 기록은 비어 있지만, 실제 코드에서는 이전 실패지점이던 “재귀 깊이”가 아닌 “하위 탐색이 반환한 전체 정점 수”를 `count` 에 누적했다.
- 시간복잡도: `O(N²)` — `N-1`개의 전선을 하나씩 제외하고, 매번 DFS로 최대 `N`개 송전탑과 `N-1`개 전선을 확인한다.
- 공간복잡도: `O(N)` — 인접 리스트, 방문 배열, 재귀 호출 스택을 사용한다.
- 풀이 후 새로 배운 점: 트리에서는 어떤 전선이든 하나 끊으면 반드시 두 연결 요소로 나뉘다. 한쪽 크기만 DFS로 구하면 다른 쪽은 `n - count`, 차이는 `Math.abs(n - 2 * count)`로 바로 계산할 수 있다.
- 다음 문제에 적용할 한 문장 규칙: “간선 하나를 제외했을 때의 두 그룹 크기”를 물으면, 후보를 하나씩 제외하고 한쪽 크기만 탐색한 뒤 전체에서 빼는 방법을 먼저 검토한다.
- 복습에 포함할 학습 포인트: DFS 반환값으로 서브트리 크기 합산, 한쪽 크기로 다른 쪽 계산, 후보별 `visited` 초기화, `O(N²)` 근거
- 오류 분류: 구현·시간 관리

### 코드 리뷰

- 현재 코드는 제거할 전선을 양방향으로 비교하고, DFS가 현재 정점을 포함한 연결 요소 크기를 반환하므로 정확하다.
- `visited` 하나를 모든 전선 후보에 재사용하면 재귀 복귀 시 방문 해제를 반드시 맞춰야 한다. 이 문제는 트리라서 수정한 코드가 올바르지만, 전선 후보마다 새 `visited`를 만들고 DFS 안에서는 방문을 해제하지 않는 편이 더 안전하고 의미가 직접적이다.

```java
public int solution(int n, int[][] wires) {
    buildGraph(n, wires);
    int minDifference = n;

    for (int[] removedWire : wires) {
        visited = new boolean[n + 1];
        int connectedCount = countConnectedTowers(1, removedWire);
        minDifference = Math.min(
                minDifference,
                Math.abs(n - 2 * connectedCount)
        );
    }

    return minDifference;
}

private int countConnectedTowers(int current, int[] removedWire) {
    visited[current] = true;
    int count = 1;

    for (int next : graph[current]) {
        if (visited[next] || isRemoved(current, next, removedWire)) {
            continue;
        }
        count += countConnectedTowers(next, removedWire);
    }

    return count;
}

private boolean isRemoved(int from, int to, int[] wire) {
    return (from == wire[0] && to == wire[1])
            || (from == wire[1] && to == wire[0]);
}
```

- 위 코드는 각 후보 탐색이 서로 완전히 독립이고 `countConnectedTowers`가 “현재 정점에서 도달 가능한 송전탑 수”만 책임진다. 복잡도는 기존 코드와 같은 `O(N²)`이다.
