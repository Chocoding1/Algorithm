## Codex 분석

- 힌트 수준(Codex 판정): 없음 — 재도전 중 문법·쿼리 구조·중복 처리에 대한 추가 도움 없이 작성함
- 복습 등급: A
- 등급 판정 근거: 15분 목표 안인 3분 40초에 날짜 반개방 범위·1:N 중복 제거·내림차순 정렬을 오류 없이 재현해 첫 제출로 통과했다. 목표했던 `EXISTS`가 아닌 `JOIN + DISTINCT`를 사용했지만 제한을 충분히 만족하는 정확한 대안이므로 등급을 낮추지 않는다.
- 목표 시간 달성: 달성 — 15분 목표, 실제 3분 40초
- 재도전 독립 성공: 성공 — 힌트 없이 첫 제출 통과
- 핵심 문법: `INNER JOIN`·`DISTINCT`·반개방 날짜 범위·`ORDER BY DESC`
- 결과 한 행의 단위: 2022년 10월에 대여를 시작한 기록이 하나 이상 있는 세단 자동차 한 대
- 쿼리 데이터 흐름: 자동차와 대여 기록을 `CAR_ID`로 연결해 대여 기록 단위로 행을 늘린다. 세단과 10월 대여 시작 조건을 만족하는 행만 남기고, `DISTINCT`로 자동차 ID를 한 행씩으로 줄인 뒤 내림차순 정렬한다.
- 중복·NULL·JOIN 카디널리티 확인: 자동차와 대여 기록은 1:N이므로 같은 자동차가 10월에 여러 번 대여됐다면 JOIN 후 ID가 반복된다. `DISTINCT`가 이 중복을 제거하며, 필수 컬럼만 비교하므로 NULL은 핵심 위험이 아니다.
- 코드 개선 포인트: 현재 쿼리는 정확하고 충분히 간결하다. 존재 여부만 필요할 때는 `EXISTS`를 사용해 자동차 행을 처음부터 유지하면 `DISTINCT`가 필요 없다. 이는 정확성 수정이 아니라 결과 행 단위를 코드에 더 직접 표현하는 대안이다.

### `EXISTS` 대안 코드

```sql
SELECT C.CAR_ID
FROM CAR_RENTAL_COMPANY_CAR AS C
WHERE C.CAR_TYPE = '세단'
  AND EXISTS (
      SELECT 1
      FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY AS H
      WHERE H.CAR_ID = C.CAR_ID
        AND H.START_DATE >= '2022-10-01'
        AND H.START_DATE < '2022-11-01'
  )
ORDER BY C.CAR_ID DESC;
```

`EXISTS` 안쪽 서브쿼리는 바깥쪽의 현재 자동차 `C.CAR_ID`와 일치하면서 10월에 대여를 시작한 기록이 하나라도 있는지만 판단한다. 대여 기록 컬럼을 출력하지 않고 존재 여부만 필요하므로 `SELECT 1`을 사용한다. 바깥쪽은 자동차 한 행씩 유지되므로 `DISTINCT`가 필요 없다.

- 풀이 후 새로 확인할 점: `JOIN + DISTINCT`는 기록 수만큼 행을 늘린 후 줄이고, `EXISTS`는 일치하는 기록을 하나라도 찾으면 자동차 행을 남긴다. 두 방식 모두 이 문제에서 정확하다.
