## Codex 분석

- 복습 등급: B
- 등급 판정 근거: 힌트 없이 첫 제출에 성공했고 해시와 슬라이딩 윈도우를 올바르게 선택했다. 다만 목표 30분을 큰 시간 초과 기준과 같은 10분 초과했고, 설계를 목표 시점 18분보다 늦은 20분에 확정했으며 로컬 구현 중 `right` 증가 후 배열에 접근해 인덱스 예외가 반복됐다. 정확성 설명도 복잡도 근거에 머물러 윈도우 상태가 정확히 유지되는 이유가 빠졌다.
- 목표 시간 달성: 아니오 (40분 / 30분)
- 첫 시도 성공: 예
- 공식 출제 의도 알고리즘: 공식 의도 명시 없음
- Codex 추천 목표 알고리즘: 해시맵으로 길이 10 구간의 빈도를 유지하는 슬라이딩 윈도우
- 공식 의도 일치 여부: 공식 의도 명시 없음
- Codex 목표 일치 여부: 일치
- 실제 풀이와 의도 알고리즘 비교: 첫 10개 제품의 빈도 맵을 만든 뒤 왼쪽 제품을 빼고 오른쪽 제품을 더해 다음 구간을 구성한다. 매 구간에서 원하는 제품 종류 최대 10개만 확인하므로 제한을 충분히 만족하며 Codex 목표와 일치한다.
- 풀이 전 사고와 실제 코드의 차이: 풀이 전부터 해시와 고정 길이 슬라이딩 윈도우를 정확히 선택했고 실제 코드도 그대로 구현했다. 다만 메모에서는 복잡도만 설명했고, `discountMap`이 항상 현재 `[left, right]` 구간의 정확한 빈도라는 불변식과 합계가 모두 10이라 요구 수량 이상이면 정확히 일치한다는 근거는 놓쳤다.
- 의도 알고리즘 추가 학습 이유: 알고리즘 선택은 이미 적절하므로 새로운 알고리즘보다 윈도우 불변식, 경계 안전한 반복 구조와 맵 비교 단순화를 학습한다.
- 풀이 직후 확인한 의도 알고리즘: 현재 사용한 해시·슬라이딩 윈도우가 적절하다. 시작 인덱스 `start`를 `0`부터 `start + 10 <= discount.length`까지 순회하고, `start > 0`일 때 `discount[start - 1]`을 제거하고 `discount[start + 9]`를 추가하면 모든 유효 구간만 접근하게 된다.
- 대안 학습 상태: 불필요 (사용 알고리즘이 Codex 목표와 일치)
- 코드 개선 포인트: **가독성·안전성 개선** — `left`와 `right`를 둘 다 증가시키고 중간에 `break`하는 대신 시작 인덱스 하나를 `for`문의 조건으로 관리하면 범위 밖 접근을 구조적으로 막을 수 있다. **조건 단순화** — `number`의 합과 윈도우 크기가 모두 10이고 0개 키를 삭제하므로 `wantMap.equals(discountMap)`으로 유효 구간을 확인할 수 있다. 현재 검사 방식을 유지한다면 `productCount == 0`은 `wantEntry.getValue() > productCount`에 포함되므로 제거할 수 있다. `computeIfPresent()`로 감소와 삭제를 합칠 수도 있지만 현재의 명시적 코드는 충분히 읽기 쉽다.
- 개선 예시: `for (int start = 0; start + 10 <= discount.length; start++)`로 유효한 시작점만 순회하고, `start > 0`일 때 나가는 값 `start - 1`과 들어오는 값 `start + 9`만 갱신한다.
- 풀이 후 새로 배운 점: ① 슬라이딩 윈도우의 핵심은 이동할 때 나가는 원소 하나와 들어오는 원소 하나만 갱신해 현재 구간의 빈도라는 불변식을 유지하는 것이다. ② 인덱스를 증가시킨 뒤 검사하는 방식보다 유효한 시작 인덱스 자체를 반복 조건으로 만들면 경계 오류를 줄일 수 있다. ③ 요구 수량 합과 윈도우 크기가 모두 10인 이 문제에서는 0개 키를 제거한 두 빈도 맵의 `equals()`가 조건 충족을 정확히 나타낸다.
- 다음 문제에 적용할 한 문장 규칙: 고정 길이 구간은 시작 인덱스의 유효 범위를 반복 조건에 넣고, 이동할 때 빠지는 원소와 들어오는 원소만 갱신해 구간 상태의 불변식을 유지한다.
- 복습에 포함할 학습 포인트: D+1에 `discountMap`이 현재 10일 구간과 정확히 일치하는 이유를 설명하고, D+3에 안전한 `start` 반복 범위, 나가는·들어오는 인덱스, `Map.equals()`가 가능한 조건을 코드 없이 회상한다.
- 오류 분류: 구현·시간 관리
- 잘한 점: 입력 크기 100,000을 보고 `O(N)` 또는 `O(N log N)` 목표를 세웠고, 처음부터 해시맵과 슬라이딩 윈도우를 선택했다. 각 이동에서 전체 10일 구간을 다시 세지 않고 두 원소만 갱신했으며 첫 공식 제출에 성공했다.
- 개선할 점: 복잡도 설명과 정답성 설명을 분리한다. 포인터를 루프 내부에서 증가시킨 뒤 다시 접근하는 구조는 경계 확인이 누락되기 쉬우므로, 가능한 인덱스 범위를 `for` 조건으로 먼저 고정한다.
- 유형 인식 신호: 고정 길이 10의 모든 연속 구간, 다음 구간과 이전 구간이 9개 원소를 공유함, 문자열별 빈도 비교가 필요함.
- 다음에 적용할 규칙: 고정 길이 윈도우에서는 `start + windowSize <= length`를 먼저 쓰고, 현재 상태가 정확히 어느 구간을 나타내는지 한 문장으로 설명한 뒤 구현한다.
- 시간복잡도: `O(N × W)` — `N`은 `discount` 길이, `W`는 원하는 제품 종류 수로 최대 10이므로 이 문제에서는 `O(N)`이다.
- 공간복잡도: `O(W + 10)` — 원하는 제품과 현재 10일 구간의 서로 다른 제품 빈도를 저장하므로 제한상 `O(1)`로 볼 수 있다.
- 정답 검증: 공개 예제, 할인 기간이 정확히 10일인 경우, 마지막 윈도우만 가능한 경우와 무작위 10,000건을 Java 21에서 완전 비교 기준 풀이와 대조해 모두 통과했다.
