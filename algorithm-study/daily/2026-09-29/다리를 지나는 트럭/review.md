## Codex 분석

- 복습 등급: C
- 등급 판정 근거: 목표 30분을 30분 초과한 60분 동안 독립적으로 설계를 완성하지 못했고, 첫 제출 오답 후 출차 시각을 저장하는 큐 상태와 완성 코드를 확인했다. 논리를 이해하고 코드를 실행했지만 정답 코드 참고는 C등급 사유이다.
- 목표 시간 달성: 아니오 (60분 / 30분)
- 첫 시도 성공: 아니오 (첫 통과 전 오답 1회)
- 공식 출제 의도 알고리즘: 공식 의도 명시 없음
- Codex 추천 목표 알고리즘: 큐에 `(트럭 무게, 출차 시각)`을 저장하고 다음 이벤트 시각으로 이동하는 `O(N)` 시뮬레이션
- 공식 의도 일치 여부: 공식 의도 명시 없음
- Codex 목표 일치 여부: 보완 필요 (풀이 후 코드를 통해 학습)
- 실제 풀이와 의도 알고리즘 비교: 최종 코드는 큐의 맨 앞을 가장 먼저 나갈 트럭으로 두고, 매초 전체 상태를 갱신하지 않은 채 필요할 때만 가장 가까운 출차 시각으로 이동한다. 각 트럭은 큐에 한 번 들어가고 한 번 나오므로 `O(N)`이다.
- 풀이 전 사고와 실제 코드의 차이: 초기에도 잔여 중량이 부족하면 먼저 빠지는 트럭의 시각만큼 건너뛴려고 했지만, 그 시각을 어떻게 알고 유지할지 완성하지 못했다. 풀이 후에는 진입 시각에 다리 길이를 더한 출차 시각을 무게와 함께 큐에 저장했다.
- 의도 알고리즘 추가 학습 이유: 큐 유형을 알아도 `무엇을 저장할지`와 `시간을 언제 증가·이동할지`를 정의하지 못하면 시뮬레이션을 완성할 수 없다. 동일 문제 재도전으로 설계를 스스로 재현해야 한다.
- 풀이 직후 확인한 의도 알고리즘: 시간을 1초 증가시킨 뒤 현재 시각까지 나간 트럭을 제거한다. 새 트럭을 올릴 수 없으면 큐 맨 앞의 출차 시각으로 이동하고 그 시각까지 나간 트럭을 제거한다. 진입하면 `현재 시각 + 다리 길이`를 출차 시각으로 저장한다.
- 대안 학습 상태: 완료 (이벤트 기반 큐 시뮬레이션의 원리·복잡도 설명 후 코드 적용)
- 코드 개선 포인트: **현재 코드가 충분함** — 만료 트럭 제거와 무게 부족 처리를 하나의 반복문으로 합쳐 간결하고, 각 트럭을 한 번씩만 넣고 빼다. 다만 `int[]`의 0·1번 인덱스가 무게·출차 시각임을 주석으로 남기거나 작은 타입으로 표현하면 가독성은 더 나아질 수 있다.
- 개선 예시: 현재의 `while (!bridge.isEmpty() && (bridge.peek()[1] <= time || truckWeight > remainingWeight))`는 “이미 나간 트럭이 있거나 새 트럭을 올릴 중량이 부족하면 맨 앞 트럭을 제거한다”를 한 번에 표현한다. `Math.max(time, bridge.peek()[1])`으로 이미 나간 트럭은 현재 시각을 유지하고, 아직 나가지 않은 트럭은 그 출차 시각으로 건너뛴다.
- 풀이 후 새로 배운 점: ① 시뮬레이션에서는 매 초 전체를 갱신하는 대신 다음에 상태가 변하는 시각을 저장해 이벤트로 건너뛸 수 있다. ② 큐의 맨 앞은 가장 먼저 나갈 트럭이므로 다음 상태 변화 시각을 제공한다. ③ 중첩 `while`이어도 각 트럭이 한 번만 제거되면 전체는 상환 `O(N)`이다.
- 다음 문제에 적용할 한 문장 규칙: 시간이 들어간 시뮬레이션은 `현재 상태`와 `다음으로 상태가 변하는 시각`을 함께 정의하고, 매 단위 시간을 갱신할지 이벤트로 건너뛸지 결정한다.
- 복습에 포함할 학습 포인트: 큐에 저장할 `무게·출차 시각`, 진입 전 만료 트럭 제거, 무게 부족 시 다음 출차 시각으로 이동, 중첩 반복의 상환 `O(N)` 근거.
- 오류 분류: 설계·시간 관리
- 잘한 점: 매 초 다리 전체를 갱신하는 구현에서 멈추지 않고, 무게가 부족할 때 빠지는 트럭의 시각으로 이동하는 방향을 스스로 생각했다. 중첩 반복이 `O(N²)`인지 의심하고 실제 연산 횟수를 확인한 점도 좋다.
- 개선할 점: 시간이 있는 문제에서 현재 시각만 증가시키지 말고, 객체별로 언제 상태가 변하는지를 먼저 정의한다. 목표 시간의 60%에 설계가 미확정이면 작은 힌트를 요청하고, 정답 코드를 확인한 문제는 재도전으로 독립 재현한다.
- 유형 인식 신호: 동일한 속도와 순서로 이동하여 진입 순서가 출차 순서와 같음, 다리 중량 제한, 다음 진입이 가능해지는 시각이 앞 트럭의 출차와 연결됨.
- 다음에 적용할 규칙: 시뮬레이션에서 모든 객체를 매번 갱신하기 전에, 다음 상태 변화 시각을 큐에 저장해 직접 이동할 수 있는지 확인한다.
- 시간복잡도: `O(N)` — 각 트럭이 큐에 한 번 삽입되고 한 번 제거된다.
- 공간복잡도: `O(N)` — 최악의 경우 다리 위 트럭 정보를 큐에 저장한다.
- 정답 검증: Java 21에서 컴파일했고 공개 예제 3개가 각각 `8`, `101`, `110`으로 일치했다. 최종 코드는 진입 전 만료 트럭 제거와 중량 부족 시 출차 이벤트 이동을 모두 처리한다.
