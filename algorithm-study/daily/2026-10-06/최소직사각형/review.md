## Codex 분석 — 풀이 완료 후 작성

- 정답 여부 및 복잡도: 프로그래머스 첫 제출 통과와 공개 예제 `4000`, `120`, `133`의 로컬 실행을 확인했다. 각 명함의 두 변을 고정 횟수로 확인하므로 시간복잡도는 `O(N)`, 별도의 입력 크기 비례 자료구조가 없어 추가 공간복잡도는 `O(1)`이다.
- 문제의 출제 의도와 내 접근 비교: 추천문에서 공개된 완전탐색적 관찰·구현 문제다. 핵심은 가능한 모든 회전 조합을 만드는 대신 각 명함을 `[긴 변, 짧은 변]`으로 정규화하는 것이다. 사용자는 이 핵심 기준을 힌트로 확인한 뒤 같은 방식으로 구현했다.
- 풀이 전 사고와 실제 코드의 차이: 독립적인 접근을 확정하지 못한 상태에서 긴 변과 짧은 변을 같은 방향으로 모으는 핵심 힌트를 받았다. 이후 각 행에서 첫 번째 값이 더 작으면 두 값을 교환하고, 두 열의 최댓값을 곱하는 코드로 정확히 구현했다.
- 정답을 보장하는 이유: 각 명함은 회전할 수 있으므로 긴 변을 지갑의 한 축, 짧은 변을 다른 축으로 통일해도 담을 수 있는지 여부는 변하지 않는다. 정규화 후 모든 명함을 담으려면 첫 축은 모든 긴 변의 최댓값 이상, 둘째 축은 모든 짧은 변의 최댓값 이상이어야 한다. 두 값 중 하나라도 줄이면 그 최댓값을 가진 명함을 담지 못하므로 두 최댓값의 곱이 최소 넓이다.
- 공식 출제 의도 알고리즘: 완전탐색 (프로그래머스 분류); 세부 구현 의도는 명시 없음
- Codex 추천 목표 알고리즘: 각 명함을 긴 변·짧은 변으로 정규화한 뒤 두 방향의 최댓값을 한 번에 집계하는 `O(N)` 풀이
- 실제 사용 알고리즘: 각 명함을 직접 교환해 긴 변을 왼쪽에 배치한 뒤 열별 최댓값을 구하는 `O(N)` 풀이
- 공식 의도 일치 여부: 일치 (핵심 힌트 후)
- Codex 목표 일치 여부: 일치 (핵심 힌트 후)
- 대안 학습 상태: 완료 (핵심 정규화 관찰을 설명받아 구현)
- 더 깔끔하거나 효율적인 코드: 현재 안쪽 `for (j)`는 `j`를 사용하지 않아 각 명함에서 동일한 교환 조건을 두 번 검사한다. 또한 입력 배열을 직접 바꿀 필요가 없다. 각 행의 `Math.max`와 `Math.min`을 바로 전체 최댓값에 반영하면 한 번의 순회로 의도가 더 명확해진다. 점근 복잡도는 그대로 `O(N)`이고, 중복 검사 제거·입력 불변성·가독성이 개선된다.

```java
public int solution(int[][] sizes) {
    int maxLongSide = 0;
    int maxShortSide = 0;

    for (int[] size : sizes) {
        int longSide = Math.max(size[0], size[1]);
        int shortSide = Math.min(size[0], size[1]);

        maxLongSide = Math.max(maxLongSide, longSide);
        maxShortSide = Math.max(maxShortSide, shortSide);
    }

    return maxLongSide * maxShortSide;
}
```

- 이번에 새로 배운 내용: 각 객체가 서로 바꿀 수 있는 두 방향을 가진다면 모든 조합을 열거하기 전에 각 객체를 `[큰 값, 작은 값]`처럼 동일한 기준으로 정규화할 수 있는지 확인한다. 정규화 후 각 축의 필수 최솟값은 그 축에 놓인 값들의 최댓값이다.
- 다음 문제에 적용할 한 문장 규칙: 원소 내부의 순서를 자유롭게 바꿀 수 있으면 먼저 동일한 기준으로 정규화한 뒤 전체 최댓값·최솟값 같은 집계로 줄일 수 있는지 본다.
- 복습에 포함할 내용: 모든 회전 조합 대신 정규화해도 되는 이유, 두 축의 최댓값이 필요하면서 동시에 충분한 이유, 입력을 바꾸지 않는 한 번 순회 구현을 정답 코드 없이 재현한다.
- 오류 분류: 인식·시간 관리 (핵심 관찰을 독립적으로 찾지 못했고 목표 20분을 1분 초과)
- 잘한 점: 핵심 기준을 확인한 뒤 예제의 모든 명함을 정확히 정규화했고, 교환과 열별 최댓값 집계로 첫 제출에 통과했다.
- 개선할 점: `sizes[i].length`만큼 도는 내부 반복은 `j`를 사용하지 않으므로 필요하지 않다. 반복문을 작성할 때 반복 변수가 실제 처리 대상을 바꾸는지 확인한다.
