## Codex 분석 — 풀이 완료 후 작성

- 정답 여부 및 복잡도: 프로그래머스 첫 제출 통과와 공개 예제 로컬 실행을 확인했다. 문제 수를 `N`이라 할 때 세 수포자의 답을 모두 비교하므로 시간복잡도는 `O(3N) = O(N)`, 패턴과 점수 배열은 크기가 고정되어 추가 공간복잡도는 결과 배열을 제외하면 `O(1)`이다.
- 문제의 출제 의도와 내 접근 비교: 추천문에서 공개된 완전탐색·규칙 구현을 그대로 사용했다. 각 수포자의 반복 패턴을 배열로 표현하고 `i % 패턴 길이`로 현재 답을 구한 뒤 모든 문제를 직접 비교했다. 공식 페이지는 완전탐색 분류만 제공하므로 그보다 구체적인 공식 의도는 명시되지 않았다.
- 풀이 전 사고와 실제 코드의 차이: 메모에서 계획한 패턴별 반복 비교와 점수 집계를 그대로 구현했다. 다만 정답 근거에는 복잡도뿐 아니라 모든 문제·모든 수포자를 빠짐없이 비교한다는 점과 동점자를 오름차순으로 반환하는 근거가 추가로 필요하다.
- 정답을 보장하는 이유: 문제 `i`에서 `i % selections[j].length`는 수포자 `j`의 반복 패턴상 정확한 답 위치를 가리킨다. 따라서 모든 `i`와 세 수포자를 비교한 `counts[j]`는 각 수포자의 정확한 점수다. 최댓값과 같은 점수의 번호를 `1 → 2 → 3` 순서로 추가하므로 모든 공동 1등이 누락 없이 오름차순으로 반환된다.
- 공식 출제 의도 알고리즘: 완전탐색 (프로그래머스 분류); 세부 구현 의도는 명시 없음
- Codex 추천 목표 알고리즘: 반복 패턴을 배열로 표현하고 나머지 연산으로 순환하며 `O(N)`에 전수 비교
- 실제 사용 알고리즘: 세 패턴을 `int[][]`로 묶고 모든 문제에서 세 답을 비교하는 `O(N)` 완전탐색
- 공식 의도 일치 여부: 일치
- Codex 목표 일치 여부: 일치
- 대안 학습 상태: 불필요
- 더 깔끔하거나 효율적인 코드: 현재 코드는 제한에서 충분히 빠르고 점근 복잡도도 적절하다. 다만 수포자 번호를 이미 `1 → 2 → 3` 순서로 추가하므로 `Collections.sort(answer)`는 불필요하다. 또한 고정된 세 후보를 필터링해 바로 `int[]`로 만들면 중간 `ArrayList<Integer>`와 박싱도 없앨 수 있다. 이는 빅오 개선이 아니라 상수 비용·가독성 개선이다.

```java
import java.util.Arrays;
import java.util.stream.IntStream;

public int[] solution(int[] answers) {
    int[][] patterns = {
            {1, 2, 3, 4, 5},
            {2, 1, 2, 3, 2, 4, 2, 5},
            {3, 3, 1, 1, 2, 2, 4, 4, 5, 5}
    };
    int[] scores = new int[patterns.length];

    for (int i = 0; i < answers.length; i++) {
        for (int person = 0; person < patterns.length; person++) {
            if (answers[i] == patterns[person][i % patterns[person].length]) {
                scores[person]++;
            }
        }
    }

    int maxScore = Arrays.stream(scores).max().orElse(0);
    return IntStream.range(0, scores.length)
            .filter(person -> scores[person] == maxScore)
            .map(person -> person + 1)
            .toArray();
}
```

- 이번에 새로 배운 내용: 결과가 요구하는 정렬 순서와 후보를 순회하는 순서가 같다면, 그 순서대로 결과를 만들면 별도 정렬이 필요 없다. `int[][]`의 내부 배열 길이는 서로 달라도 되며 각 행의 실제 길이로 나머지 연산을 하면 각기 다른 주기를 안전하게 표현할 수 있다.
- 다음 문제에 적용할 한 문장 규칙: 후보 수가 작고 입력 전체를 직접 검사해도 제한을 만족하면 모든 후보를 검사하되, 반복 규칙은 `인덱스 % 주기 길이`로 표현한다.
- 복습에 포함할 내용: 나머지 연산이 반복 패턴의 현재 위치를 가리키는 이유, `O(3N)`이 `O(N)`인 이유, 동점 결과가 별도 정렬 없이 오름차순인 이유를 회상한다.
- 오류 분류: 없음
- 잘한 점: 최대 입력에서 세 후보만 비교한다는 사실을 이용해 바로 `O(N)` 설계를 확정했고, 5분 만에 설계를 끝낸 뒤 목표 20분 안에 첫 제출로 통과했다.
- 개선할 점: 정확성 근거에는 시간복잡도가 통과한다는 설명과 별개로 점수 집계의 완전성 및 공동 1등의 정렬 보장을 포함한다.
