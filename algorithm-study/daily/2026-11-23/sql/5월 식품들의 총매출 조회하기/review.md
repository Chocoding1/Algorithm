## Codex 분석

- 힌트 수준(Codex 판정): 없음 — 풀이 과정에서 문법·구조·정답 쿼리 도움을 요청하거나 확인하지 않음
- 복습 등급: A
- 등급 판정 근거: 목표 30분보다 빠른 9분 20초에 5월 주문 필터, 상품별 주문량 집계, 상품 정보 연결, 총매출 계산과 다중 정렬을 독립적으로 완성해 첫 제출로 통과함
- 목표 시간 달성: 예
- 첫 시도 성공: 예
- 핵심 문법: 파생 테이블·`INNER JOIN`·반개방 날짜 범위·`SUM`·`GROUP BY`·계산 컬럼 별칭·다중 `ORDER BY`
- 결과 한 행의 단위: 2022년 5월에 생산 주문이 존재하는 식품 한 종류
- 쿼리 데이터 흐름: 안쪽 쿼리에서 `FOOD_ORDER`의 5월 생산 주문만 남긴 뒤 `PRODUCT_ID`별 주문량 합계를 한 행으로 만든다. 바깥 쿼리는 이 결과를 `FOOD_PRODUCT`와 연결해 식품명과 가격을 가져오고, 가격과 총주문량을 곱해 총매출을 만든 뒤 총매출 내림차순·식품 ID 오름차순으로 정렬한다.
- 중복·NULL·JOIN 카디널리티 확인: 파생 테이블은 식품별 한 행이고 `FOOD_PRODUCT.PRODUCT_ID`도 식품별 한 행이므로 JOIN 결과는 식품별 한 행이다. 5월 주문이 없는 식품은 `INNER JOIN` 결과에 포함되지 않는다. 이 문제의 요구에서는 별도의 `NULL` 대체가 필요하지 않다.
- 정답 검증: 한 식품의 가격은 주문마다 동일하므로 `PRICE × SUM(AMOUNT)`는 `SUM(PRICE × AMOUNT)`와 같다. 날짜를 `2022-05-01 이상, 2022-06-01 미만`으로 제한해 5월의 모든 시각을 안전하게 포함했고, 동점 정렬까지 요구사항과 일치한다.
- 코드 개선 포인트: 현재 쿼리는 다수 쪽 주문을 먼저 식품별 한 행으로 축약해 바깥 쿼리에서 추가 `GROUP BY`가 필요 없고, 결과 행의 단위도 분명하므로 의미 있는 수정이 필요 없다. 마지막의 초기 안내 주석은 실행 결과에 영향을 주지 않는다.
- 클린 쿼리 예시: 현재 제출 쿼리가 충분히 간결하고 안전하므로 별도 대체 쿼리를 추가하지 않음
- 풀이 후 새로 배운 점: 1:N JOIN에서 최종 결과가 1 쪽 단위라면 N 쪽을 필요한 단위로 먼저 집계한 뒤 연결하면 중복과 바깥 집계를 단순화할 수 있다.
- 오류 분류: 없음
- 다음에 적용할 규칙: 최종 결과가 식품별 한 행이라면 주문 테이블을 먼저 식품별로 축약할 수 있는지 확인한다.
