## Codex 분석

- 힌트 수준(Codex 판정): 작은 힌트 — 만원 미만 자릿수를 버려 가격대 시작값을 만든다는 설계는 사용자가 이미 알고 있었고, Codex가 `FLOOR(PRICE / 10000) * 10000`과 `DIV` 문법을 제공함
- 복습 등급: B
- 등급 판정 근거: 목표 20분 안인 7분 30초에 오류 없이 첫 제출로 통과했고 그룹 단위·별칭·정렬도 정확했지만, 핵심 계산식을 구현하는 MySQL 문법을 확인한 뒤 완성함
- 목표 시간 달성: 예
- 첫 시도 성공: 예
- 핵심 문법: `FLOOR`·정수 구간 계산·`COUNT(*)`·`GROUP BY`·계산 컬럼 별칭·`ORDER BY`
- 결과 한 행의 단위: 동일한 만원 단위 가격대에 속하는 상품 그룹 하나
- 쿼리 데이터 흐름: 파생 테이블이 각 상품 가격을 가격대 시작값으로 바꾸고, 원본 상품과 `PRODUCT_ID`로 다시 연결한 뒤 가격대별 상품 수를 세어 오름차순으로 정렬한다.
- 중복·NULL·JOIN 카디널리티 확인: `PRODUCT_ID`가 양쪽에서 고유하므로 현재 자기 JOIN은 1:1이고 상품 수를 늘리지는 않는다. `PRICE`는 문제에서 상품 가격으로 제공되므로 별도의 `NULL` 처리는 요구되지 않는다.
- 정답 검증: `FLOOR(PRICE / 10000) * 10000`은 9,000을 0, 15,000을 10,000, 22,000을 20,000으로 바꾼다. 경계값 10,000과 20,000은 각각 그대로 해당 구간의 시작값이 된다. `FLOOR`는 반올림이 아니라 소수점 이하를 버리고 항상 아래 정수로 내린다.
- 코드 개선 포인트: 같은 `PRODUCT`를 두 번 읽어 `PRODUCT_ID`로 다시 JOIN하는 과정은 결과에 필요하지 않다. 가격대 계산식 또는 그 별칭을 바로 그룹 기준으로 사용하면 동일한 `O(N)` 집계이면서 추가 파생 테이블·JOIN·테이블 재조회가 사라진다.
- 클린 쿼리 예시:

```sql
SELECT FLOOR(PRICE / 10000) * 10000 AS PRICE_GROUP,
       COUNT(*) AS PRODUCTS
FROM PRODUCT
GROUP BY PRICE_GROUP
ORDER BY PRICE_GROUP ASC;
```

- 풀이 후 새로 배운 점: MySQL의 `FLOOR(x)`는 `x` 이하의 가장 큰 정수를 반환하며, 같은 테이블에서 계산 컬럼 하나만 추가하려고 자기 JOIN을 만들 필요는 없다.
- 오류 분류: 문법 탐색·불필요한 JOIN
- 다음에 적용할 규칙: 원본 행에서 바로 계산할 수 있는 값은 먼저 `SELECT` 식이나 그룹 기준으로 표현하고, 다른 행이나 테이블 정보가 필요할 때만 JOIN한다.
