## Java 알고리즘 2문제

### 1. 문자열 압축

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/60057
- 플랫폼 / 난이도: 프로그래머스 Lv.2
- 목표 시간: 40분 — **24분(60%)까지 설계 확정**
- 풀이 구분: 신규
- 추천 이유: 제한된 입력 안에서 가능한 선택을 빠짐없이 확인하면서도, 반복되는 처리와 마지막 경계를 정확하게 구현하는지를 측정한다.
- 결과: 성공 — 60분, 설계 15분, 첫 통과 전 오답 5회
- 복습 등급: C
- 핵심 피드백: 단위 길이를 모두 확인하는 방향은 맞았지만 압축 중인 문자열을 직접 바꾸면서 원본의 첫 미처리 위치와 결과 문자열의 다음 위치를 혼용했다. `"a"`, `"aaa"`, 반복 횟수 10 이상의 반례와 핵심 인덱스 식을 확인한 뒤 통과했다.
- 코드 개선 포인트: 원본은 고정하고 압축 결과 길이만 누적하면 위치 관리가 단순해지고 최악 시간복잡도를 `O(N³)` 상한에서 `O(N²)`로 낮출 수 있다.
- 동일 문제 재도전: 11월 26일, 현재 코드·회고 없이 처음부터 구현
- D+7 변형: 11월 30일 유형 비공개 문자열·구현 문제

풀이 전에는 다음만 확인한다.

- 입력 최대 크기에서 생각한 방법의 총 연산량이 허용되는가?
- 가장 단순한 방법에서 같은 문자 구간을 불필요하게 다시 처리하는가?
- 길이가 1이거나 마지막 부분의 길이가 앞부분과 다른 경우에도 반환값이 정확한가?

### 2. 파일명 정렬

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/17686
- 플랫폼 / 난이도: 프로그래머스 Lv.2
- 목표 시간: 45분 — **27분(60%)까지 설계 확정**
- 풀이 구분: 신규
- 추천 이유: 여러 조건의 우선순위와 예외를 코드에 빠뜨리지 않고 반영하고, 입력 순서까지 포함한 출력 계약을 지키는지를 확인한다.
- 결과: 성공 — 실제 완료일 11월 24일, 35분, 첫 통과 전 오답 2회
- 복습 등급: C
- 핵심 피드백: HEAD와 NUMBER를 객체에 한 번만 파싱하는 큰 구조는 정확했다. NUMBER를 연속 구간으로 끝내지 않아 세 자리 숫자와 TAIL 내부 숫자를 잘못 읽었고, NUMBER가 파일 끝에서 끝날 때 빈 문자열을 `parseInt()`해 런타임 오류가 발생했다.
- 코드 개선 포인트: 첫 숫자 위치를 한 번 찾은 뒤 최대 다섯 자리의 연속 숫자만 확인하면 HEAD와 NUMBER를 한 번의 흐름으로 파싱할 수 있다.
- 동일 문제 재도전: 11월 30일 선택 쉬운 문제 슬롯에서 20분 독립 구현

풀이 전에는 다음만 확인한다.

- 두 입력의 순서를 결정하는 조건을 문제에 적힌 순서대로 모두 설명할 수 있는가?
- 비교가 반복될 때 같은 해석 작업을 얼마나 반복하게 되는가?
- 두 기준이 같거나 숫자 앞에 0이 있는 경우를 직접 검증했는가?

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/131530
- 플랫폼 / 난이도: 프로그래머스 SQL Lv.2
- 목표 시간: 20분
- 오늘 연습 범주: 구간별 계산값·그룹 집계·출력 별칭·정렬
- 풀이 구분: 신규 기본·취약점 보정
- 결과: 성공 — 7분 30초, 첫 제출 통과, 문법·결과 오류 없음

- 다음 확인: 11월 26일 자기 JOIN 없이 5분 재작성

### 2. 5월 식품들의 총매출 조회하기

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/131117
- 플랫폼 / 난이도: 프로그래머스 SQL Lv.4
- 목표 시간: 30분
- 오늘 연습 범주: 1:N 테이블 관계·월 조건·그룹 계산·다중 정렬

- 결과: 성공 — 9분 20초, 힌트·오류 없이 첫 제출 통과
