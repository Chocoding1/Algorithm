- 실제 풀이와 의도 알고리즘 비교: 실제 풀이는 반복 구간을 발견할 때마다 `s`를 압축 결과로 교체하고 새 문자열의 위치를 다시 이동했다. 목표 풀이는 원본 `s`의 블록 경계를 끝까지 유지하고 압축했을 때 추가되는 길이만 계산하므로 소비한 원본 위치와 결과 위치가 섞이지 않는다.
- 풀이 전 사고와 실제 코드의 차이: 단위 길이를 1부터 바꾸며 반복 구간을 찾는 설계는 정확했다. 구현에서는 `nxtStartIdx`를 마지막 일치 블록의 시작과 첫 미처리 위치로 함께 사용했고, 압축 결과의 반복 횟수가 항상 한 자리라고 가정해 경계 불변식이 깨졌다.
- 코드 개선 포인트: 원본을 반복해서 `substring + 문자열 연결`로 교체하면 위치 관리가 복잡해지고 반복 구간마다 길이 `O(N)`의 문자열 복사가 발생한다. 원본은 고정하고 압축 길이만 더하면 로직이 단순해지고 최악 시간복잡도를 현재 안전한 상한 `O(N³)`에서 `O(N²)`로 낮출 수 있다.
- 클린 코드 예시:

```java
public class 문자열_압축 {

    public int solution(String s) {
        int minLength = s.length();

        for (int unit = 1; unit <= s.length() / 2; unit++) {
            minLength = Math.min(minLength, compressedLength(s, unit));
        }

        return minLength;
    }

    private int compressedLength(String s, int unit) {
        String previous = s.substring(0, unit);
        int repeatCount = 1;
        int length = 0;

        for (int start = unit; start < s.length(); start += unit) {
            int end = Math.min(start + unit, s.length());
            String current = s.substring(start, end);

            if (previous.equals(current)) {
                repeatCount++;
                continue;
            }

            length += previous.length();
            if (repeatCount > 1) {
                length += String.valueOf(repeatCount).length();
            }

            previous = current;
            repeatCount = 1;
        }

        length += previous.length();
        if (repeatCount > 1) {
            length += String.valueOf(repeatCount).length();
        }

        return length;
    }
}
```

### 처음부터 다시 풀 때의 사고 흐름

1. 바꿀 수 있는 선택은 자르는 단위 길이뿐이다.
2. `N ≤ 1,000`이므로 가능한 단위를 모두 시도하고 각 단위에서 문자열을 한 번 확인하는 `O(N²)` 접근이 가능하다.
3. 단위 하나가 정해지면 맨 앞부터 자르는 위치와 연속된 같은 조각을 묶는 규칙이 고정되므로 압축 결과도 하나로 결정된다.
4. 각 단위에서 `previous`, `repeatCount`, `compressedLength`만 유지한다. 실제 압축 문자열은 정답에 필요하지 않다.
5. 다른 조각을 만났을 때 이전 묶음을 길이에 반영하고, 반복문이 끝난 뒤 아직 반영되지 않은 마지막 묶음을 한 번 더 반영한다.
6. 모든 단위의 결과 중 최솟값을 선택한다. 최적 결과가 사용하는 단위도 확인 대상에 포함되므로 정답을 놓치지 않는다.

### 반복문 불변식과 마지막 처리

- `compressedLength`: 현재 반복 묶음보다 앞에 있는 조각들이 압축된 길이
- `previous`: 확인은 했지만 아직 `compressedLength`에 반영하지 않은 현재 묶음의 조각
- `repeatCount`: `previous`가 연속된 횟수

새로운 다른 조각을 만나야 현재 묶음이 확정되므로, 문자열 끝까지 같은 조각이 반복되면 반복문 안에서 확정 사건이 발생하지 않는다. 이때도 `previous`와 `repeatCount`는 현재 묶음을 그대로 보관하고 있으므로 반복문 밖에서 숫자의 자릿수와 조각 길이를 반영해야 한다.

### 이 문제에서 경계 조건을 뽑는 방법

| 코드·조건의 신호 | 확인할 입력 | 확인 목적 |
|---|---|---|
| 최소 문자열 길이 | `"a"` | 초기화·반복문 0회·반환값 |
| `previous.equals(current)` | 반복 없음 / 한 번 반복 / 끝까지 반복 | 두 분기와 마지막 묶음 반영 |
| `repeatCount > 1` | 1회 / 2회 | 숫자 생략 경계 |
| 반복 횟수 문자열 변환 | 9회 / 10회 | 숫자 자릿수 증가 |
| `Math.min(start + unit, length)` | 정확히 나누어짐 / 짧은 나머지 존재 | 마지막 불완전 조각 |
| 인덱스 갱신 | 첫 조각 / 마지막 조각 | 모든 경로에서 전진하는지 확인 |

범용 규칙은 조건마다 `직전·같음·직후`, 반복문마다 `0회·1회·여러 회·입력 끝까지`, 상태 확정마다 `확정 사건 없이 종료`를 확인하는 것이다.

- 풀이 후 새로 배운 점:
  - 문자열을 변환하면서 순회하면 원본에서 소비한 위치와 변환 결과의 작성 위치를 별도로 관리해야 한다.
  - 연속 구간을 `count`개 소비한 뒤 원본의 첫 미처리 위치는 `start + count × unit`이다.
  - 압축 길이에는 반복 횟수 자체가 아니라 `String.valueOf(count).length()`만큼의 자릿수가 추가된다.
  - 반복문이 끝났을 때 `previous`는 남은 입력이 아니라 아직 결과에 반영하지 않은 현재 묶음을 뜻한다.
  - 경계 조건은 감으로 나열하지 않고 조건문·반복문·인덱스·자료형의 경계에서 기계적으로 만든다.
- 다음 문제에 적용할 한 문장 규칙: 최종 문자열 자체가 필요하지 않고 길이만 요구하면 원본을 변경하지 말고 결과 길이만 누적한다.
- 복습에 포함할 학습 포인트: 원본 위치와 결과 위치의 분리, 마지막 묶음 확정, 마지막 불완전 블록 처리, 반복 횟수의 자릿수, 단위별 결과가 하나로 결정되는 정답 근거, 조건과 반복문에서 반례를 만드는 방법
- 오류 분류: 구현·경계·시간 관리
- 잘한 점: 가능한 단위 길이를 모두 비교해야 한다는 접근을 빠르게 확정했고, 공개 예제를 모두 통과하는 구현까지 독립적으로 작성한 뒤 반례를 통해 수정 내용을 이해하고 최종 제출에 성공했다.
- 개선할 점: 반복문 변수가 가리키는 위치의 의미를 하나로 고정하고, `"a"`, `"aaa"`, 같은 블록 10회처럼 반복 종료 방식과 자릿수가 달라지는 최소 반례를 제출 전에 확인해야 한다.
- 유형 인식 신호: 입력 길이가 작고 가능한 단위가 명확하며, 각 단위로 만든 결과 중 최솟값을 요구하면 모든 단위를 확인하면서 한 후보를 선형으로 계산할 수 있는지 검토한다.
- 다음에 적용할 규칙: 반복문의 모든 경로에서 인덱스가 전진하는지와 현재 인덱스가 `마지막 처리 위치`인지 `첫 미처리 위치`인지 주석 없이도 일관되는지 확인한다.
- 시간복잡도: 현재 코드는 단위 길이 `O(N)`, 블록 비교와 반복적인 문자열 재생성을 포함해 안전한 최악 상한 `O(N³)`; 클린 코드는 각 단위에서 원본을 한 번 훑어 `O(N²)`
- 공간복잡도: 현재 코드와 클린 코드 모두 생성되는 부분 문자열을 고려하면 최대 `O(N)`의 추가 공간
