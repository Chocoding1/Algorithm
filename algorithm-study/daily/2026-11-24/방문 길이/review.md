## Codex 분석

- 힌트 수준(Codex 판정): 핵심 힌트 — `"UD"`가 같은 길을 반대 방향으로 지난 반례와 함께, 방문 상태를 좌표 하나가 아닌 `(출발 좌표, 도착 좌표)`라는 핵심 상태로 직접 제시함
- 복습 등급: C
- 등급 판정 근거: 목표 35분을 25분 초과한 60분에 첫 통과 전 오답 2회 후 성공했고, 도착 좌표와 진행 방향만으로는 반대 방향의 동일한 길을 판별할 수 없는 핵심 문제를 힌트로 확인한 뒤 완성함
- 목표 시간 달성: 아니오 — 35분 목표 / 60분
- 첫 시도 성공: 아니오 — 첫 통과 전 오답 2회
- 공식 출제 의도 알고리즘: 공식 의도 명시 없음
- Codex 추천 목표 알고리즘: 유효한 명령만 좌표에 반영하고, 양 끝점의 순서와 무관한 길 표현을 `HashSet`에 저장하는 한 번의 순회
- 실제 풀이와 의도 알고리즘 비교: 최종 코드는 순방향과 역방향 경로를 둘 다 저장해 무방향 길을 정확히 구분한다. 다만 `ArrayList.contains()`로 이전 길을 매번 선형 탐색하므로 목표의 평균 `O(N)`보다 비효율적이다.
- 코드 개선 포인트: `List<String>`를 `HashSet<String>`으로 바꾸면 이미 지나간 길을 평균 `O(1)`에 확인할 수 있다. 현재는 모든 좌표가 한 자릿수인 `-5~5`이라 구분자 없는 문자열도 통과하지만, 범위가 커지면 `1, 23`과 `12, 3`처럼 충돌할 수 있으므로 구분자를 넣는 표현이 안전하다. `main()`의 `"UD"` 기댓값 주석 `// 7`도 실제 기댓값 `// 1`로 읽어야 한다.
- 클린 코드 예시:

```java
import java.util.HashMap;
import java.util.HashSet;
import java.util.Map;
import java.util.Set;

public class 방문_길이 {

    public int solution(String dirs) {
        Map<Character, int[]> directions = new HashMap<>();
        directions.put('U', new int[]{1, 0});
        directions.put('D', new int[]{-1, 0});
        directions.put('L', new int[]{0, -1});
        directions.put('R', new int[]{0, 1});

        Set<String> visitedRoutes = new HashSet<>();
        int row = 0;
        int col = 0;
        int answer = 0;

        for (char command : dirs.toCharArray()) {
            int[] direction = directions.get(command);
            int nextRow = row + direction[0];
            int nextCol = col + direction[1];

            if (nextRow < -5 || nextRow > 5 || nextCol < -5 || nextCol > 5) {
                continue;
            }

            String route = routeKey(row, col, nextRow, nextCol);
            String reverseRoute = routeKey(nextRow, nextCol, row, col);

            if (visitedRoutes.add(route)) {
                visitedRoutes.add(reverseRoute);
                answer++;
            }

            row = nextRow;
            col = nextCol;
        }

        return answer;
    }

    private String routeKey(int fromRow, int fromCol, int toRow, int toCol) {
        return fromRow + "," + fromCol + "->" + toRow + "," + toCol;
    }
}
```

원본 Java는 사용자의 최종 통과 코드로 보존했다.

- 풀이 후 새로 배운 점: 동일한 간선은 양 끝점을 반대로 적어도 같은 간선이다. 중복 확인이 필요한 값은 `List.contains()`보다 값 기반 `equals()`·`hashCode()`를 사용하는 `HashSet`이 적합하다. 복합 값을 문자열 키로 만들 때는 구분자를 넣어 충돌을 막는다.
- 다음 문제에 적용할 한 문장 규칙: 중복을 제거할 대상이 점인지 선분인지 먼저 정의하고, 순서가 달라도 같은 값이라면 표현을 정규화하거나 양방향을 함께 기록한다.
- 오류 분류: 설계·구현·시간 관리
- 잘한 점: 경계 밖 명령을 정확히 무시했고, 핵심 상태를 확인한 뒤에는 순·역방향을 함께 저장해 정답을 완성했다.
- 개선할 점: 제출 전에 `UD`, `LR`처럼 같은 두 점을 왕복하는 최소 반례를 만들어 상태 표현이 문제의 동일성 규칙과 맞는지 확인한다.
- 시간복잡도: 현재 코드는 최대 `N` 명령마다 `List.contains()`로 최대 `O(N)`을 탐색하여 `O(N²)`; 클린 코드는 `HashSet` 평균 `O(1)` 조회로 평균 `O(N)`
- 공간복잡도: 순·역방향 길을 저장하므로 `O(N)`
