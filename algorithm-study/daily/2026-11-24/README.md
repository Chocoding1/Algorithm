## MySQL SQL 2문제

### 1. 조건에 맞는 사용자와 총 거래금액 조회하기 재도전

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/164668
- 플랫폼 / 난이도: 프로그래머스 SQL Lv.3
- 목표 시간: **10분**
- 오늘 연습 범주: 행 필터·그룹 조건·사용자별 집계·JOIN
- 추천 이유: 지난 풀이에서 완성 쿼리를 확인했으므로, 이전 자료 없이 개별 행 조건과 집계 그룹 조건을 구분해 재작성한다.
- 결과: 성공 — 12분, 힌트·오류 없이 첫 제출 통과
- 복습 등급: B
- 핵심 피드백: `WHERE`로 완료 거래 행을 먼저 거르고 작성자별로 집계한 뒤 `HAVING`으로 총거래금액 70만 원 이상 그룹을 거르는 구조를 독립 재현했다. 목표 10분은 2분 초과함
- 재도전 결과: 최초 C등급의 SQL 절 순서·행/그룹 필터·JOIN 컬럼 혼동을 회복함
- 다음 확인: 11월 27일 `WHERE`와 `HAVING`의 대상 차이를 3분 설명, 11월 28일 JOIN·집계 혼합 전이

### 2. 년, 월, 성별 별 상품 구매 회원 수 구하기

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/131532
- 플랫폼 / 난이도: 프로그래머스 SQL Lv.4
- 목표 시간: **25분**
- 오늘 연습 범주: 다중 JOIN·날짜 그룹·1:N 중복·NULL 필터·회원 수 집계
- 추천 이유: 여러 판매 행이 하나의 회원으로 연결될 때 결과의 한 행과 세어야 할 대상을 정확히 구분하는지 확인한다.
- 결과: 성공 — 12분, 첫 통과 전 오답 1회, 날짜 함수 API 작은 힌트
- 복습 등급: B
- 핵심 피드백: `COUNT(*)`는 판매 기록 수를 세므로 한 회원의 월내 복수 구매를 중복 집계한다. 구매 회원 수는 `COUNT(DISTINCT UI.USER_ID)`로 세어야 하며, 이 수정은 Codex 답변을 읽기 전에 독립적으로 완료함
- 다음 확인: 11월 27일 `COUNT`와 `DISTINCT` 집계 단위 5분 설명, 11월 28일 JOIN·중복·집계 혼합 전이

SQL은 제출 전에 다음을 확인한다.

1. 출력 컬럼 수·순서·별칭
2. JOIN 후 한 행의 의미와 1:N 중복
3. `WHERE`로 거를 원본 행과 `HAVING`으로 거를 그룹
4. `NULL`이 조건을 통과하는지
5. 정렬 방향과 동점 기준

### 오늘 확인된 강점

- `합승 택시 요금`에서 합승 종료 후보 `k`마다 세 최단거리의 합을 비교해야 한다는 수학적 모델은 독립적으로 찾았다.

- SQL 재도전에서는 이전 C등급의 `WHERE`·`HAVING`·JOIN 컬럼 혼동을 자료 없이 바로잡아 첫 제출로 통과했다.

### 우선 보완할 점

- 하나의 탐색 결과가 모든 정점에 대한 값을 제공하는데도 후보마다 같은 탐색을 반복하는 경향이 있다. 반복 횟수와 탐색 한 번의 복잡도를 설계 단계에서 곱해 본다.
- 중복 상태를 기록할 때 문제에서 같은 것으로 보는 단위가 점인지 간선인지 먼저 확정하고, 최소 왕복 반례로 표현을 검증한다.
- SQL에서는 JOIN 후 한 대상이 여러 행이 되는지 먼저 확인한 뒤 `COUNT(*)`와 `COUNT(DISTINCT id)` 중 무엇이 문제의 대상을 세는지 선택한다.
- 이번 SQL 재도전은 정확성은 회복했지만 10분 목표를 2분 넘겼다. 절의 역할을 빠르게 확정하는 연습이 한 번 더 필요하다.
