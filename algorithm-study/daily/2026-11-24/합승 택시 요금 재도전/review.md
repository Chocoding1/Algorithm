## Codex 분석

- 힌트 수준(Codex 판정): 정답 코드 — 합승 종료 지점 `k`의 비용을 `distS[k] + distA[k] + distB[k]`로 나누는 설계부터, 세 번의 다익스트라와 완성 Java 코드까지 제공함
- 복습 등급: C
- 등급 판정 근거: 재도전에서 17분에 각 후보 지점의 `k → s`, `k → a`, `k → b` 최단거리 합을 하나의 배열에 저장하는 유효한 설계를 세웠지만, 후보마다 다익스트라를 세 번씩 반복하고 도달 불가 후보를 0으로 남기는 정확성·효율성 문제를 수정하지 못했다. 60분에도 미제출로 종료했고 완성 코드를 제공받아 C등급으로 판정함
- 목표 시간 달성: 아니오 — 45분 목표 / 60분
- 첫 시도 성공: 재도전이므로 대상 아님
- 공식 출제 의도 알고리즘: 카카오 공식 해설은 그래프 최단거리 문제로 다익스트라 또는 플로이드–워셜을 제시함
- Codex 추천 목표 알고리즘: `s`, `a`, `b`에서 우선순위 큐 다익스트라를 각각 한 번씩 실행하고, 모든 `k`의 `distS[k] + distA[k] + distB[k]` 최솟값을 비교
- 실제 풀이와 의도 알고리즘 비교: 실제 설계도 각 `k`의 세 거리 합을 비교하므로 수학적 식은 정확했다. 다만 `k`마다 도착지가 다른 다익스트라를 세 번씩 실행해 최대 600회 탐색했고, 양방향 그래프의 `k → s = s → k`를 이용해 세 출발점의 전체 거리를 재사용하지 못했다.
- 풀이 전 사고와 실제 코드의 차이: 17분에 후보 지점별 세 거리를 더한다는 구조는 확정했으나, 탐색 방향을 뒤집어 세 번만 실행하는 최종 최적화를 독립적으로 완성하지 못했다. 사용자 요청으로 이후 원본 Java를 세 번의 다익스트라 학습 코드로 교체함
- 코드 개선 포인트: 완성 코드는 `INF = Integer.MAX_VALUE / 4`로 더셈 오버플로를 방지하고, 우선순위 큐의 오래된 항목을 건너뛰며, 세 거리 중 하나라도 도달 불가면 후보에서 제외한다. 제네릭 배열 경고를 피하려면 `List<List<int[]>>`로 바꿀 수 있지만, 사용자가 처음 작성한 인접 리스트 배열 형태를 유지함
- 클린 코드 예시: `합승_택시_요금_재도전.java`에 전체 학습 코드로 기록. 공개 예제 3개를 로컬에서 `82`, `14`, `18`로 확인함
- 풀이 후 새로 배운 점: 후보 지점별 최단거리 질의가 반복되면 각 후보에서 질의하지 말고, 필요한 출발점 수를 먼저 세어 출발점별 전체 결과를 미리 구한다. 후보 `k`별 세 거리를 하나의 배열에 누적하는 사용자 방식도 가능하지만, 각 탐색의 임시 거리 배열은 분리해야 한다.
- 다음 문제에 적용할 한 문장 규칙: 여러 후보마다 같은 질의를 반복하면, 질의의 방향을 뒤집어 소수의 출발점에서 모든 후보까지의 결과를 한 번씩 구해 재사용한다.
- 복습에 포함할 학습 포인트: `k`별 세 구간 합, 양방향 거리 대칭, 다익스트라 한 번이 모든 정점 거리를 구한다는 의미, `E` 간선에서 큐 연산이 발생해 `O(E log V)`가 되는 이유
- 오류 분류: 설계·정확성·효율성·시간 관리
- 잘한 점: 각 후보의 `k → s + k → a + k → b`를 하나의 합계 배열에 저장하는 수학적 모델과 양방향 인접 리스트를 독립적으로 구현함. 즉 문제를 전혀 이해하지 못한 것이 아니라 결과 재사용을 한 단계 더 적용하지 못한 것이다.
- 개선할 점: 설계에서 `탐색 횟수 × 탐색 한 번의 복잡도`를 수치로 적고, 다익스트라 한 번이 특정 도착지 하나가 아닌 모든 정점의 거리 배열을 만든다는 점을 재사용 근거로 확인한다.
- 시간복잡도: 완성 학습 코드는 우선순위 큐 다익스트라 3회와 후보 순회로 `O((V + E) log V)`; 사용자 최초 방식은 최대 `3V`회 탐색으로 `O(V(V + E) log V)`
- 공간복잡도: 인접 리스트, 세 거리 배열, 우선순위 큐를 합쳐 `O(V + E)`
