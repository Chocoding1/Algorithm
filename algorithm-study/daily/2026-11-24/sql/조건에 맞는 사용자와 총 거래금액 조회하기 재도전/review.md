## Codex 분석

- 힌트 수준(Codex 판정): 없음 — 이번 재도전 중 풀이 힌트나 정답 쿼리를 확인하지 않음
- 복습 등급: B
- 등급 판정 근거: 이전 C등급 문제를 자료 없이 다시 풀어 문법·결과 오류 없이 첫 제출로 통과했으므로 핵심 취약점은 회복했다. 다만 목표 10분을 2분 초과한 12분이어서 A등급의 목표 시간 조건을 충족하지 못해 B등급
- 목표 시간 달성: 아니오 — 12분 / 10분
- 핵심 문법: `INNER JOIN`·파생 테이블·`WHERE`·`GROUP BY`·`SUM()`·`HAVING`·`ORDER BY`
- 결과 한 행의 단위: 완료된 거래 금액의 합이 70만 원 이상인 사용자 한 명과 그 사용자의 ID·닉네임·총거래금액
- 쿼리 데이터 흐름: `USED_GOODS_BOARD`에서 `STATUS = 'DONE'`인 게시글만 남기고 작성자별로 묶어 가격 합계를 계산한다. 합계가 70만 원 이상인 작성자 그룹만 남긴 뒤 사용자 테이블과 연결해 ID·닉네임·총거래금액을 출력하고 총거래금액으로 정렬한다.
- 중복·NULL·JOIN 카디널리티 확인: 파생 테이블은 `WRITER_ID`별 한 행이므로 사용자 테이블과 연결한 뒤에도 사용자 한 명당 한 행이다. 따라서 `DISTINCT`는 필요 없다. 이 문제의 핵심 연결·집계 컬럼은 `NOT NULL` 조건이므로 별도의 NULL 보정도 필요 없다.
- 정답 검증: 최종 쿼리는 개별 게시글을 거르는 `WHERE`와 사용자별 집계 결과를 거르는 `HAVING`을 정확히 구분했고, 올바른 사용자 키로 JOIN해 첫 공식 제출에 통과함
- 코드 개선 포인트: 현재 쿼리의 구조는 정답이다. 집계값 이름을 문제의 출력명인 `TOTAL_SALES`로 통일하고 파생 테이블 별칭을 `S`처럼 짧게 두면 의미가 더 직접적으로 드러난다.
- 클린 쿼리 예시:

```sql
SELECT U.USER_ID,
       U.NICKNAME,
       S.TOTAL_SALES
FROM USED_GOODS_USER AS U
JOIN (
    SELECT WRITER_ID,
           SUM(PRICE) AS TOTAL_SALES
    FROM USED_GOODS_BOARD
    WHERE STATUS = 'DONE'
    GROUP BY WRITER_ID
    HAVING SUM(PRICE) >= 700000
) AS S
    ON U.USER_ID = S.WRITER_ID
ORDER BY S.TOTAL_SALES;
```

원본 SQL은 사용자의 최종 통과 쿼리로 보존했다.

- 오류 분류: 시간 관리
- 다음에 적용할 규칙: `WHERE`는 그룹을 만들기 전의 원본 행을 거르고, `HAVING`은 `GROUP BY`와 집계 함수로 만든 그룹을 거른다.
