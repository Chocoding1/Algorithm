## Codex 분석

- 복습 등급: A
- 독립 재현 결과: 성공 — 이전 코드·회고를 보지 않고 3분 만에 설계를 확정해 5분에 첫 제출로 통과
- 등급 판정 근거: 재도전 목표 15분 안에 힌트·이전 자료 재확인 없이 성공했고 구현 실수도 없다. 긴 변을 한 축으로 통일한 뒤 두 축의 최댓값을 구하는 핵심 설계를 독립적으로 재현했다.
- 목표 시간 달성: 예 (5분 / 15분)
- 첫 시도 성공: 재도전 첫 제출 통과
- 실제 풀이와 원본 학습 비교: 원본에서 힌트로 배웠던 방향 정규화를 독립적으로 다시 떠올렸다. 구현도 각 명함의 큰 값을 한쪽으로 교환한 뒤 축별 최댓값을 구하는 동일한 방식이다.
- 완전탐색 여부: 프로그래머스는 이 문제를 완전탐색 카테고리에 분류하지만, 현재 구현이 모든 `2^N` 회전 조합을 열거하는 전형적인 완전탐색은 아니다. 각 명함의 두 방향 선택을 `[긴 변, 짧은 변]` 하나의 대표 형태로 정규화할 수 있다는 관찰로 조합 탐색을 제거한 뒤 모든 명함을 한 번씩 확인한다. 따라서 실제 구현을 가장 정확히 부르면 `정규화 + O(N) 선형 집계`다.
- 정답 근거: 각 명함은 회전할 수 있으므로 긴 변을 모두 같은 축에 놓아도 수납 가능성은 바뀌지 않는다. 정규화 후 지갑의 두 축은 각각 긴 변들의 최댓값과 짧은 변들의 최댓값 이상이어야 하고, 어느 하나라도 줄이면 해당 최댓값을 가진 명함을 담지 못하므로 그 곱이 최소 넓이다.
- 코드 개선 포인트: 안쪽 `for (j)`에서 `j`를 사용하지 않아 같은 교환 조건을 두 번 확인한다. 입력 배열을 교환하지 않고 `Math.max`·`Math.min`으로 각 명함을 해석하면서 전체 최댓값을 갱신하면 한 번의 순회로 더 명확하게 표현할 수 있다. 빅오는 동일한 `O(N)`이다.
- 클린 코드 예시:

```java
public int solution(int[][] sizes) {
    int maxLongSide = 0;
    int maxShortSide = 0;

    for (int[] size : sizes) {
        maxLongSide = Math.max(
                maxLongSide,
                Math.max(size[0], size[1])
        );
        maxShortSide = Math.max(
                maxShortSide,
                Math.min(size[0], size[1])
        );
    }

    return maxLongSide * maxShortSide;
}
```

- 풀이 후 새로 배운 점: 플랫폼의 문제 카테고리와 실제 최종 구현의 알고리즘 표현은 다를 수 있다. 선택지가 여러 개여도 모든 조합을 열거하기 전에 서로 동등한 선택을 하나의 정규형으로 합칠 수 있는지 확인한다.
- 오류 분류: 없음
- 시간복잡도: `O(N)` — 각 명함을 한 번 확인한다. 현재 중첩 반복도 내부 길이가 항상 2라 `O(2N) = O(N)`이다.
- 공간복잡도: `O(1)` — 입력 크기에 비례하는 추가 자료구조가 없다.
