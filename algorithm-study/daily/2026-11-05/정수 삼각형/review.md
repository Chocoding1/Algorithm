## Codex 분석

- 힌트 수준(Codex 판정): 없음 — 문제 페이지에서 유형을 미리 본 사실은 유형 인식 지표에서는 제외하지만, 구체적인 상태·점화식·메모이제이션 구현은 도움 없이 완성했다.
- 복습 등급: B
- 등급 판정 근거: 목표 40분 안인 24분에 최종 성공했고 7분 만에 재귀 설계를 확정했으나, 첫 제출에서 같은 칸 아래의 최댓값을 반복 계산해 시간 초과가 발생했다. 이후 `(행, 열)`별 결과를 저장하는 메모이제이션을 독립적으로 추가해 통과했다.
- 목표 시간 달성: 예
- 첫 시도 성공: 아니오 — 첫 통과 전 시간 초과 1회
- 공식 출제 의도 알고리즘: 동적계획법
- Codex 추천 목표 알고리즘: 각 칸에서 바닥까지의 최대 합을 상태로 정의한 하향식 메모이제이션 또는 아래 행부터 계산하는 상향식 동적계획법
- 실제 풀이와 의도 알고리즘 비교: 최종 코드는 `search(i, j)`를 `(i, j)`에서 시작해 바닥까지 얻을 수 있는 최대 합으로 정의하고 두 자식 상태의 최댓값을 저장하므로 공식 유형과 일치한다.
- 풀이 전 사고와 실제 코드의 차이: 풀이 전에는 모든 분기를 재귀 호출하면 된다고 판단했지만, 높이 `N`에서 경로 수가 `2^(N-1)`로 증가한다는 비용을 놓쳤다. 첫 시간 초과 후 서로 다른 경로가 같은 `(i, j)`에 도착하면 그 아래 계산이 반복된다는 점을 확인하고 `maxSum[i][j]`를 추가했다.
- 코드 개선 포인트: 현재 하향식 메모이제이션은 정확하고 `O(N²)`으로 충분하다. 다만 `n × n` 메모 배열 대신 마지막 행을 복사한 1차원 배열을 아래에서 위로 갱신하면 재귀 호출을 없애고 보조 공간을 `O(N)`으로 줄일 수 있다. 빅오는 같으며 메모리와 호출 오버헤드가 개선된다.
- 풀이 후 새로 배운 점: 단순 재귀의 중첩 호출 모양만 보지 말고 리프 경로 수를 계산해야 한다. 서로 다른 경로가 같은 상태에 도착하고 이후 결과가 같다면 그 상태 결과를 저장할 수 있다. 메모이제이션 후에는 삼각형의 칸 수만큼만 상태를 계산한다.
- 다음 문제에 적용할 한 문장 규칙: 선택 경로는 매우 많아도 같은 상태에 다시 도착한다면, 상태를 명확히 정의하고 그 결과를 한 번만 계산한다.
- 복습에 포함할 학습 포인트: `search(i, j)`의 의미, `triangle[i][j] + max(search(i+1,j), search(i+1,j+1))` 점화식, 완전 재귀 `O(2^N)`과 메모이제이션 `O(N²)`의 차이, `-1` 초기값이 안전한 입력 조건
- 오류 분류: 설계
- 시간복잡도: `O(N²)` — 실제 상태 수는 `1 + 2 + ... + N = N(N+1)/2`이고 각 상태를 한 번 계산한다.
- 공간복잡도: `O(N²)` — 메모 배열 `O(N²)`과 최대 재귀 깊이 `O(N)`

### 클린 코드 예시

원본 Java는 수정하지 않는다. 아래는 마지막 행의 결과를 재사용해 보조 공간을 `O(N)`으로 줄인 상향식 풀이 예시다.

```java
public int solution(int[][] triangle) {
    int lastRow = triangle.length - 1;
    int[] maxSum = triangle[lastRow].clone();

    for (int row = lastRow - 1; row >= 0; row--) {
        for (int col = 0; col <= row; col++) {
            maxSum[col] = triangle[row][col]
                    + Math.max(maxSum[col], maxSum[col + 1]);
        }
    }

    return maxSum[0];
}
```
