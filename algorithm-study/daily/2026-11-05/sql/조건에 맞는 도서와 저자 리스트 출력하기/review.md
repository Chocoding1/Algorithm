## Codex 분석

- 힌트 수준(Codex 판정): 없음
- 복습 등급: B
- 등급 판정 근거: 목표 25분 안인 8분에 올바른 JOIN 조건·필터·정렬을 완성했지만, 첫 제출에서 `WHERE`를 `JOIN ... ON`보다 앞에 배치해 문법 오류가 발생했다. 도움 없이 순서를 바로잡아 최종 통과했다.
- 목표 시간 달성: 예
- 첫 시도 성공: 아니오 — 첫 통과 전 문법 오류 1회
- 핵심 문법: `INNER JOIN`·`ON`·`WHERE`·`ORDER BY`
- 결과 한 행의 단위: 경제 카테고리에 속한 도서 한 권
- 쿼리 데이터 흐름: `BOOK`의 각 도서에 같은 `AUTHOR_ID`의 저자 한 명을 연결하고, `WHERE`에서 경제 도서만 남긴 뒤 필요한 세 컬럼을 선택해 출판일 오름차순으로 정렬한다.
- 중복·NULL·JOIN 카디널리티 확인: 한 저자가 여러 도서를 쓸 수 있어 `AUTHOR : BOOK`은 1:N이지만, `BOOK`에서 시작하면 도서마다 저자 한 명만 연결되므로 결과 한 행은 계속 도서 한 권이다. 사용한 키와 출력 컬럼은 모두 `NULL` 불가이며, 유효한 저자 정보가 있는 도서만 `INNER JOIN` 결과에 남는다.
- 코드 개선 포인트: 최종 쿼리는 이미 간결하고 정확해 구조 변경이 필요 없다. `JOIN` 대신 `INNER JOIN`, `ORDER BY B.PUBLISHED_DATE ASC`처럼 기본 동작을 명시하는 정도만 선택적으로 적용할 수 있다. `PUBLISHED_DATE`가 `DATE` 타입이라 MySQL에서는 현재 선택만으로도 요구된 `YYYY-MM-DD` 형식이 출력된다.
- 풀이 후 새로 배운 점: SQL의 작성 구문에서는 대상 테이블을 연결하는 `JOIN ... ON`을 먼저 완성한 뒤 `WHERE`로 연결 결과의 행을 거른다. 논리적 실행 순서도 `FROM → JOIN/ON → WHERE`다.
- 오류 분류: SQL 절 배치 순서
- 다음에 적용할 규칙: 여러 테이블을 조회할 때는 `FROM` 다음에 모든 `JOIN ... ON`을 작성하고, 그 뒤에 `WHERE` 필터를 작성한다.
