- 첫 시도 성공: 예 (첫 제출 통과)

- 공식 의도 일치 여부: 일치
- Codex 목표 일치 여부: 일치
- 실제 풀이와 의도 알고리즘 비교: 남은 피로도, 방문 배열, 현재 방문 수를 재귀 상태로 두고 탐험 가능한 미방문 던전을 하나 선택했다. 재귀가 끝나면 방문 표시를 되돌려 다른 순서를 탐색하므로 목표 방식과 같다.
- 풀이 전 사고와 실제 코드의 차이: 메모에서 계획한 재귀·방문 표시 흐름을 그대로 구현했다. 코드에는 메모에서 명시하지 않았던 `visited[i] = false` 복구가 정확히 들어가 있다. 이 복구가 없으면 한 분기에서 선택한 던전이 다른 분기에서도 계속 방문된 것으로 남아 가능한 순서를 누락한다.
- 의도 알고리즘 추가 학습 이유: 다른 알고리즘은 필요 없다. 이번에는 백트래킹의 `선택 → 탐색 → 복구` 불변식과 전역 상태의 재호출 안전성을 보완하면 된다.
- 풀이 직후 확인한 의도 알고리즘: 던전 수가 최대 8이라 가능한 순서를 전부 탐색할 수 있다. 각 깊이에서 미방문이면서 현재 피로도로 입장 가능한 던전을 선택하고, 소모 피로도를 뺀 상태로 재귀 호출한 뒤 방문 표시를 복구한다.
- 대안 학습 상태: 불필요
- 코드 개선 포인트: 알고리즘은 적절하다. 다만 `answer`가 인스턴스 필드이고 `solution()`에서 0으로 초기화되지 않아 같은 객체로 `solution()`을 다시 호출하면 이전 호출의 큰 값이 남을 수 있다. 재귀 함수가 현재 상태에서 추가로 방문할 수 있는 최댓값을 반환하게 만들면 전역 상태·`count`·별도 종료 조건을 모두 없앨 수 있다. 이는 빅오 개선이 아니라 안전성·가독성 개선이다.
- 클린 코드 예시:

```java
public int solution(int k, int[][] dungeons) {
    return explore(k, dungeons, new boolean[dungeons.length]);
}

private int explore(int fatigue, int[][] dungeons, boolean[] visited) {
    int maxCount = 0;

    for (int i = 0; i < dungeons.length; i++) {
        if (visited[i] || fatigue < dungeons[i][0]) {
            continue;
        }

        visited[i] = true;
        int count = 1 + explore(
                fatigue - dungeons[i][1],
                dungeons,
                visited
        );
        visited[i] = false;

        maxCount = Math.max(maxCount, count);
    }

    return maxCount;
}
```

- 풀이 후 새로 배운 점: 백트래킹에서 방문 배열은 현재 경로 안의 중복 선택만 막는다. 재귀 호출 뒤 상태를 복구해야 같은 깊이의 다음 선택이 원래 상태에서 출발하며, 그 결과 가능한 모든 순서를 탐색할 수 있다. 재귀가 스스로 최댓값을 반환하면 호출 사이에 남을 수 있는 전역 상태를 피할 수 있다.
- 다음 문제에 적용할 한 문장 규칙: 선택 순서에 따라 결과가 달라지고 `N`이 작다면, 현재 상태에서 가능한 대상을 하나 선택하고 재귀 후 상태를 복구해 모든 순서를 탐색한다.
- 복습에 포함할 학습 포인트: `visited`가 나타내는 범위, 복구가 필요한 이유, 모든 유효한 순서를 빠짐없이 탐색한다는 근거, 인스턴스 필드를 재사용할 때 생기는 문제를 회상한다.
- 오류 분류: 없음 (재호출 안전성은 클린 코드 보완점)
- 잘한 점: 최대 8개라는 제한에서 순열 탐색이 가능함을 바로 판단했고, 8분 만에 방문 배열 백트래킹을 설계해 첫 제출로 통과했다. 선택 전 표시와 재귀 후 복구 위치도 정확하다.
- 개선할 점: 복잡도나 중복 방지만 설명하지 말고, 복구로 각 분기가 독립되고 모든 선택 순서가 생성되므로 최댓값이 정답이라는 데까지 설명한다. 클래스 필드는 여러 호출 사이에 유지된다는 점도 확인한다.
- 유형 인식 신호: 입력 수가 매우 작고, 대상을 선택하는 순서에 따라 가능한 다음 선택과 최종 결과가 달라진다.
- 다음에 적용할 규칙: 재귀 상태·선택 가능 조건·선택 표시·재귀 호출·복구·정답 갱신을 코드 전에 각각 한 문장으로 정한다.
- 시간복잡도: `O(N × N!)` 상한 — 순열 탐색 트리의 각 상태에서 최대 `N`개의 던전을 검사하며 `N ≤ 8`이다.
- 공간복잡도: `O(N)` — 방문 배열과 최대 `N` 깊이의 재귀 호출 스택이 필요하다.
