## Codex 분석

- 힌트 수준(Codex 판정): 정답 코드 (`COUNT(DISTINCT NAME)` 완성 쿼리 제공)
- 복습 등급: C
- 등급 판정 근거: 25분 목표 내 10분에 최종 통과했지만, 요구한 결과가 이름별 여러 행이 아니라 중복·`NULL`을 제외한 이름 종류 수 하나임을 독립적으로 구분하지 못해 오답 3회 후 완성 쿼리를 확인함
- 목표 시간 달성: 예 (10분 / 25분)
- 첫 시도 성공: 아니오 (첫 통과 전 오답 3회)
- 핵심 문법: `COUNT(DISTINCT column)`, `COUNT` 집계의 `NULL` 제외
- 결과 한 행의 단위: 전체 입소 동물 중 `NULL`을 제외한 서로 다른 이름의 개수 하나를 나타내는 집계 행
- 쿼리 데이터 흐름: `FROM ANIMAL_INS`의 전체 행에서 `DISTINCT NAME`으로 중복을 제거하고, `COUNT`가 `NULL`을 제외한 값만 세어 하나의 결과로 축약함
- 중복·NULL·JOIN 카디널리티 확인: `DISTINCT`는 `Sam, Sam`을 하나로 보고, `COUNT(NAME)`은 `NAME IS NULL`인 값을 세지 않는다. 따라서 `NULL, Sam, Sam, Sweetie`는 2개다.
- 정답 검증: 프로그래머스에서 오답 3회 후 최종 통과
- 코드 개선 포인트: 현재 집계 로직은 최소·정확하다. 출력 열 이름을 명확하게 하려면 `AS count`를 붙일 수 있다.
- 클린 쿼리 예시:

```sql
SELECT COUNT(DISTINCT NAME) AS count
FROM ANIMAL_INS;
```

- 풀이 후 새로 배운 점: `GROUP BY NAME`은 이름별로 한 행씩 만들지만, `COUNT(DISTINCT NAME)`은 서로 다른 이름의 전체 개수를 하나의 행으로 만든다.
- 오류 분류: 결과 행 단위·중복·`NULL` 설계 오류
- 다음에 적용할 규칙: **“서로 다른 값이 몇 개인가”면 `COUNT(DISTINCT column)`, “값별로 몇 개인가”면 `GROUP BY column`을 검토한다.**
