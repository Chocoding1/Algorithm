- 실제 풀이와 의도 알고리즘 비교: 숫자를 왼쪽부터 순회하면서 현재 숫자가 덱의 마지막 숫자보다 크면 제거 횟수 안에서 마지막 숫자를 반복 제거하고 현재 숫자를 추가한다. 순회 후 제거 횟수가 남으면 뒤에서 제거해 정확히 `k`개를 없앤다.
- 풀이 전 사고와 실제 코드의 차이: 처음에는 인덱스별 제거 조합을 DFS로 탐색하려 했고 최소 `O(N²)` 이상이 되어 최대 길이 1,000,000을 처리할 수 없음을 발견했다. 이후 힌트로 앞자리 우선 그리디 기준을 확인하고 `O(N)` 구현으로 전환했다.
- 코드 개선 포인트: 현재 코드는 정답이고 `O(N)`이다. 다만 숫자 문자열을 `int[]`로 변환하고 `Deque<Integer>`에 다시 저장하는 중간 구조는 필요하지 않다. 원본 문자의 대소를 그대로 비교하면서 `char[]`을 스택처럼 사용하면 스트림·박싱·덱 순회 없이 결과 길이만큼 바로 문자열을 만들 수 있다. 빅오 변화는 없고 상수 비용과 메모리 사용을 줄이는 개선이다.
- 클린 코드 예시:

```java
// 프로그래머스 Lv.2
public class 큰_수_만들기 {
    public String solution(String number, int k) {
        char[] selected = new char[number.length()];
        int size = 0;
        int removed = 0;

        for (int i = 0; i < number.length(); i++) {
            char current = number.charAt(i);

            while (size > 0
                    && removed < k
                    && selected[size - 1] < current) {
                size--;
                removed++;
            }

            selected[size++] = current;
        }

        return new String(selected, 0, number.length() - k);
    }
}
```

- 풀이 후 새로 배운 점: 결과 길이가 같으면 첫 번째로 다른 앞자리의 크기가 전체 결과를 결정한다. 따라서 더 큰 현재 숫자를 앞으로 보낼 수 있을 때 앞의 작은 숫자를 제거하는 선택은 이후 숫자와 관계없이 유리하다. 모든 숫자가 내림차순이면 순회 중 제거되지 않으므로 결과의 뒤에서 남은 개수를 제거해야 한다.
- 다음 문제에 적용할 한 문장 규칙: 결과의 우선순위가 앞에서 결정되고 길이가 고정되어 있다면, 현재 선택으로 더 앞자리를 개선할 수 있는지 먼저 확인한다.
- 복습에 포함할 학습 포인트: 앞자리 우선 선택이 안전한 이유, 반복 제거 조건, 같은 숫자와 내림차순 입력, 각 원소가 한 번 추가·제거되어 `O(N)`인 이유
- 오류 분류: 인식·설계 — 완전탐색 병목은 찾았지만 그리디 선택 기준을 독립적으로 발견하지 못함
- 시간복잡도: `O(N)` — 각 숫자는 한 번 추가되고 최대 한 번 제거됨
- 공간복잡도: `O(N)` — 선택한 숫자를 덱에 저장
