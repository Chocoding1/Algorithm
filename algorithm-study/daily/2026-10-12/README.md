## MySQL SQL 2문제

오늘은 SQL 입문 2주차 첫날로, 집계 결과 한 행의 의미와 중복·`NULL`이 개수에 미치는 영향을 확인한다. 정답 쿼리의 형태는 풀이 전에 공개하지 않는다.

| 문제 | 플랫폼·난이도 | 목표 시간 | 역할 | 상태 |
|---|---:|---:|---|---|
| [동물 수 구하기](https://school.programmers.co.kr/learn/courses/30/lessons/59406) | SQL Lv.1 | 20분 | 기본형 | 5분·첫 제출 통과·힌트 없음·A |
| [중복 제거하기](https://school.programmers.co.kr/learn/courses/30/lessons/59408) | SQL Lv.2 | 25분 | 강화형 | 10분·오답 3회 후 통과·정답 쿼리 확인·C |

제출 전에는 출력값, 원본 한 행의 의미, 집계 후 결과 한 행의 의미, 중복과 `NULL` 포함 여부를 문제 요구사항과 대조한다.

## 짧은 복습 — 총 5분 이내

- `두 큐 합 같게 만들기` D+1 완료: `Arrays.stream(int[]).sum()`과 `asLongStream().sum()`의 중간 합산 자료형 차이 확인
- `게임 맵 최단거리` D+3 완료: BFS 최단거리 보장, 큐 삽입 시 방문 처리, `O(N×M)` 근거 회상

`네트워크` D+1은 오늘 짧은 복습 2개 제한과 겹치므로 2026-10-13으로 하루 이월한다.

## 현재 평가

- `큰 수 만들기`는 DFS 조합 탐색이 제한을 만족하지 못한다는 병목을 직접 발견한 뒤, 핵심 힌트로 앞의 작은 숫자를 제거하는 그리디 기준을 확인해 `O(N)`으로 구현하고 첫 제출로 통과했다.
- 실제 시간은 목표와 같은 35분이고 구현 실수는 없지만 핵심 선택 기준을 제공받았으므로 C등급이다. 2026-10-14에 현재 코드·회고 없이 동일 문제를 재도전한다.
- 현재 `Deque<Integer>` 구현은 정답이다. 중간 `int[]`과 덱 없이 `char[]`을 스택처럼 사용하는 클린 코드 예시는 문제별 `review.md`에 기록했으며 원본 Java는 수정하지 않았다.
- `단어 변환`은 10분 만에 DFS/BFS 설계를 확정하고 26분에 힌트·실수 없이 첫 제출로 통과해 A등급이다.
- 경로별 방문을 복구하는 DFS는 정답이지만 최악 경로 수가 팩토리얼 수준으로 커질 수 있다. 간선 비용이 같은 최소 변환 문제이므로 `O(N²×L)` BFS가 더 직접적인 대안이며, 전체 코드는 `review.md`에 기록했다.
- 2026-10-15에 DFS·BFS 방문 차이와 BFS 최단거리 근거를 짧게 회상하고, 2026-10-19에는 `네트워크`와 공유 가능한 그래프 변형으로 전이를 확인한다.
- SQL `동물 수 구하기`는 `COUNT(*)`로 전체 행 수를 5분에 독립 집계해 A등급이다.
- SQL `중복 제거하기`는 “이름별 개수”로 해석해 `GROUP BY`를 사용했지만, 요구한 결과는 중복과 `NULL`을 제외한 이름 종류 수 하나였다. 오답 3회 후 완성 쿼리를 확인했으므로 C등급이다.
- 2026-10-14에 SQL 두 자리 중 하나로 `중복 제거하기`를 이전 자료 없이 5분 이내 재도전하고, 나머지 한 자리에서 신규 SQL 진도를 유지한다.
