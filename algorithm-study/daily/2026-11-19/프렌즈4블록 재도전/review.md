- 힌트 수준(Codex 판정): 없음 — 재도전 중 추가 힌트·해설·이전 코드를 확인하지 않고 구현

- 등급 판정 근거: 최초 실패에서 배운 현재 보드 직접 갱신과 동시 삭제 구조를 독립 재현해 첫 공식 제출로 통과했다. 다만 실제 50분으로 목표 45분을 5분 초과했고, 중력 구현에서 이미 삭제된 블록을 건너뛰지 않는 로컬 구현 실수를 수정했으며 해당 로직에 많은 시간을 사용했다.
- 목표 시간 달성: 아니오 — 50분 / 45분
- 첫 시도 성공: 재도전 성공 — 첫 공식 제출 통과
- 공식 출제 의도 알고리즘: 시뮬레이션·구현 — 현재 보드에서 `탐색 → 동시 삭제 → 중력` 반복
- Codex 추천 목표 알고리즘: 수정 가능한 현재 보드와 삭제 표시 배열을 사용한 단계별 시뮬레이션
- 공식 의도 일치 여부: 일치
- Codex 목표 일치 여부: 일치
- 실제 풀이와 의도 알고리즘 비교: `boolean[][] removed`로 같은 턴의 삭제를 먼저 표시하고, 표시 완료 후 보드를 바꾸며, 중력 적용 후 같은 `result`를 다음 턴에 사용했다. 핵심 처리 순서는 표준 접근과 일치한다.
- 풀이 전 사고와 실제 코드의 차이: 풀이 중 문답은 비어 있지만 5분에 설계를 확정했고, 최초 풀이의 누적 삭제 좌표 방식 대신 현재 `char[][]`를 직접 갱신했다. 설계는 빠르게 회복했으나 연속된 빈칸 수를 찾고 여러 번 이동시키는 `down()` 구현이 복잡해지면서 구현 시간이 길어졌다.
- 의도 알고리즘 추가 학습 이유: 핵심 알고리즘은 독립 재현했다. 이제 같은 의미를 더 단순한 열별 쓰기 위치로 표현해 중력 로직의 중첩 탐색과 오류 가능성을 줄이는 것이 필요하다.
- 풀이 직후 확인한 의도 알고리즘: 한 턴마다 현재 보드에서 모든 2×2를 검사해 삭제 위치를 표시하고, 표시된 칸을 한 번만 세어 비운 뒤, 각 열을 아래에서 위로 읽어 생존 블록을 아래쪽부터 채운다. 삭제가 0개인 턴에서 종료한다.
- 대안 학습 상태: 완료 — 핵심 접근 독립 재현, 열 압축 개선안을 아래에 기록
- 코드 개선 포인트: **빅오·가독성·안전성 개선.** 현재 `down()`은 빈칸을 만날 때마다 위쪽 연속 빈칸을 다시 세고 `realDown()`으로 열 일부를 반복 이동해, 한 턴의 중력이 최악 `O(n × m²)`가 된다. 열마다 `writeRow` 하나를 두면 생존 블록을 각각 한 번만 읽고 써서 `O(m × n)`에 처리할 수 있다. 사용하지 않는 `removed` 매개변수도 제거할 수 있다.
- 풀이 후 새로 배운 점: 중력은 빈칸마다 위 블록들을 당기는 문제로 보면 구현이 복잡해진다. 반대로 각 열의 생존 블록만 아래부터 순서대로 다시 배치한다고 보면 쓰기 위치 하나로 처리할 수 있다.
- 다음 문제에 적용할 한 문장 규칙: 삭제 후 압축 문제에서는 빈칸을 하나씩 메우지 말고, 남길 원소를 한 번 순회하며 다음 쓰기 위치에 모은다.
- 복습에 포함할 학습 포인트: 실제 완료일 기준 11월 24일 D+1에 세 단계 처리 순서와 `writeRow` 중력을 설명하고, 11월 26일 D+3에 현재 중력과 열 압축의 복잡도를 비교한다.
- 오류 분류: 구현·시간 관리
- 잘한 점: 이전 실패의 핵심 원인이었던 원본 좌표와 현재 좌표 혼동을 제거했다. 겹치는 2×2는 `boolean[][]`로 중복 집계를 막았고, 빈칸 문자를 검사에서 제외해 삭제 후 상태에서도 정확하게 동작했다.
- 개선할 점: `canRemove()`는 비교 결과를 바로 반환할 수 있고, 중력은 빈칸 구간별 반복 이동 대신 열별 압축 한 번으로 끝낸다. `down()`의 사용하지 않는 `removed` 인자도 제거한다.
- 유형 인식 신호: 작은 격자에서 한 턴의 동시 사건을 모두 판정한 뒤 상태를 일괄 변경하고, 더 이상 변화가 없을 때까지 반복한다.
- 다음에 적용할 규칙: 같은 턴의 판정과 상태 변경을 분리하고, 다음 턴은 반드시 변경이 모두 끝난 현재 상태만 읽는다.
- 시간복잡도: 현재 코드는 턴 수를 `T`라 할 때 삭제 탐색 `O(Tmn)`, 중력 최악 `O(Tnm²)`. `writeRow` 개선안은 턴당 `O(mn)`, 전체 `O(Tmn)`이며 성공 턴마다 최소 4칸이 사라져 `T ≤ mn / 4`이다.
- 공간복잡도: 현재 보드와 턴별 삭제 표시 배열 `O(mn)`

### 클린 코드 전체

원본 Java는 재도전 과정을 보존하기 위해 수정하지 않는다. 아래 코드는 현재 풀이의 정확한 핵심 구조를 유지하면서 탐색·삭제·중력을 각각 한 가지 역할로 분리한 전체 예시다.

```java
// 프로그래머스 Lv.2
public class 프렌즈4블록_재도전 {

    private static final char EMPTY = ' ';

    public int solution(int m, int n, String[] board) {
        char[][] blocks = new char[m][n];
        for (int row = 0; row < m; row++) {
            blocks[row] = board[row].toCharArray();
        }

        int answer = 0;

        while (true) {
            boolean[][] toRemove = findBlocksToRemove(blocks);
            int removedCount = removeBlocks(blocks, toRemove);

            if (removedCount == 0) {
                break;
            }

            answer += removedCount;
            applyGravity(blocks);
        }

        return answer;
    }

    private boolean[][] findBlocksToRemove(char[][] blocks) {
        int m = blocks.length;
        int n = blocks[0].length;
        boolean[][] toRemove = new boolean[m][n];

        for (int row = 0; row < m - 1; row++) {
            for (int col = 0; col < n - 1; col++) {
                char block = blocks[row][col];

                if (block == EMPTY) {
                    continue;
                }

                if (blocks[row][col + 1] == block
                        && blocks[row + 1][col] == block
                        && blocks[row + 1][col + 1] == block) {
                    toRemove[row][col] = true;
                    toRemove[row][col + 1] = true;
                    toRemove[row + 1][col] = true;
                    toRemove[row + 1][col + 1] = true;
                }
            }
        }

        return toRemove;
    }

    private int removeBlocks(char[][] blocks, boolean[][] toRemove) {
        int removedCount = 0;

        for (int row = 0; row < blocks.length; row++) {
            for (int col = 0; col < blocks[0].length; col++) {
                if (toRemove[row][col]) {
                    blocks[row][col] = EMPTY;
                    removedCount++;
                }
            }
        }

        return removedCount;
    }

    private void applyGravity(char[][] blocks) {
        int m = blocks.length;
        int n = blocks[0].length;

        for (int col = 0; col < n; col++) {
            int writeRow = m - 1;

            for (int row = m - 1; row >= 0; row--) {
                if (blocks[row][col] != EMPTY) {
                    blocks[writeRow--][col] = blocks[row][col];
                }
            }

            while (writeRow >= 0) {
                blocks[writeRow--][col] = EMPTY;
            }
        }
    }

    public static void main(String[] args) {
        프렌즈4블록_재도전 solution = new 프렌즈4블록_재도전();

        System.out.println(solution.solution(
                4,
                5,
                new String[]{"CCBDE", "AAADE", "AAABF", "CCBBF"}
        )); // 14

        System.out.println(solution.solution(
                6,
                6,
                new String[]{"TTTANT", "RRFACC", "RRRFCC", "TRRRAA", "TTMMMF", "TMMTTJ"}
        )); // 15
    }
}
```

#### 원본과 달라진 부분

1. 빈칸 문자 `'*'`를 여러 메서드에 직접 쓰지 않고 `EMPTY` 상수로 이름을 붙였다.
2. 원본 `remove()`가 담당하던 탐색과 실제 삭제를 `findBlocksToRemove()`와 `removeBlocks()`로 분리했다. 같은 턴의 판정이 끝나기 전에 보드를 바꾸지 않는 규칙이 메서드 구조에 드러난다.
3. `canRemove()`의 단순 비교를 별도 호출로 감추지 않고 탐색 메서드 안에서 바로 표현했다. 빈칸 제외와 네 칸 비교를 한 위치에서 확인할 수 있다.
4. 중력에서 빈칸마다 연속 빈칸 수를 다시 세고 `realDown()`을 호출하던 방식을 제거했다. 각 열의 생존 블록을 아래부터 한 번씩 읽어 `writeRow`에 배치한다.
5. 중력 메서드에서 사용하지 않던 `removed` 매개변수와 별도의 `realDown()` 메서드가 사라졌다.
6. 각 보조 메서드는 `char[][]`의 길이에서 `m`, `n`을 얻어 불필요한 크기 매개변수를 줄였다.

각 열을 아래에서 위로 읽고 아래쪽부터 쓰기 때문에 생존 블록의 상대 순서가 유지된다. 현재 중력은 한 턴에 최악 `O(n × m²)`이지만 개선 코드는 모든 칸을 한 번씩 확인하므로 `O(m × n)`이다.
