## 풀이 후 결과 - 사용자 작성

- 실제 풀이 시간: 9분 (예: `15분`)
- 풀이 외 제외 시간: 0분 (예: `0분` / `5분, 식사`)
- 결과: 성공 (예: `성공` / `실패` / `부분 성공`)
- 제출 결과: 첫 통과 전 오답 2회 (예: `첫 제출 통과` / `첫 통과 전 오답 2회` / `미제출`)
- 문법·결과 오류: `CASE` 결과의 `RENT_TYPE` 별칭 누락, 기존 네 컬럼을 모두 출력해야 하는 요구사항 누락 (예: `없음` / `정렬 방향을 반대로 작성`)
- 막힌 지점·배운 점: CASE WHEN 배움, DATEDIFF 배움 (예: `없음` / `날짜 기간의 양끝 포함을 놓침`)

## Codex 분석

- 힌트 수준(Codex 판정): 핵심 힌트 — 조건에 따라 값을 만드는 `CASE WHEN` 문법과 이 문제의 `DATEDIFF(END_DATE, START_DATE) + 1 >= 30` 조건식을 풀이 중 확인
- 복습 등급: C
- 등급 판정 근거: 목표 20분 안인 9분에 최종 성공했지만 문제의 핵심 문법과 기간 판정식을 직접 확인했다. 또한 첫 통과 전 `RENT_TYPE` 별칭과 기존 출력 컬럼을 각각 누락해 오답 2회가 발생했으므로 독립 재작성으로 확인해야 한다.
- 목표 시간 달성: 예 — 9분 / 20분
- 첫 시도 성공: 아니오 — 첫 통과 전 오답 2회
- 핵심 문법: `CASE WHEN`, `DATEDIFF`, 날짜 반개방 범위, 계산 컬럼 별칭, `ORDER BY`
- 결과 한 행의 단위: 2022년 9월에 대여를 시작한 대여 기록 한 건. 원래 네 컬럼과 그 기록의 기간을 분류한 `RENT_TYPE`을 함께 출력한다.
- 쿼리 데이터 흐름: `FROM`에서 모든 대여 기록을 읽고 → `WHERE`에서 2022년 9월 시작 기록만 남기고 → `SELECT`에서 원본 컬럼과 기간별 분류값을 출력하고 → `ORDER BY`에서 `HISTORY_ID` 내림차순으로 정렬한다.
- 중복·NULL·JOIN 카디널리티 확인: 단일 테이블을 읽고 그룹화하지 않으므로 입력 대여 기록 한 행이 결과 한 행으로 유지된다. 문제의 날짜 컬럼은 `NULL` 불가이므로 기간 계산에서 `NULL`이 발생하지 않는다.
- 정답 검증: 프로그래머스 최종 제출 통과. 시작일과 종료일을 모두 대여일에 포함하기 위해 `DATEDIFF + 1`을 사용했고, 9월 범위는 `>= '2022-09-01' AND < '2022-10-01'`로 정확하게 제한했다.
- 코드 개선 포인트: `SELECT *`도 현재 스키마에서는 통과하지만, 문제에서 요구한 출력 열을 빠뜨리지 않았음을 코드에서 바로 확인할 수 있도록 네 컬럼을 명시하는 편이 안전하다. 계산 컬럼에는 반드시 `AS RENT_TYPE`을 붙여 출력 이름을 맞춘다.
- 풀이 후 새로 배운 점: `CASE WHEN`은 행을 제거하지 않고 조건에 따라 출력할 값을 만든다. 문자열 값은 작은따옴표를 사용하고, 한글·공백이 있는 컬럼명이나 별칭을 식별할 때만 백틱을 사용한다.
- 오류 분류: 정렬·출력 — 계산 컬럼 별칭 및 요구 출력 컬럼 누락
- 다음에 적용할 규칙: 제출 전 `출력 컬럼 수·순서·별칭 → 필터 → 정렬`을 문제 요구사항과 한 줄씩 대조한다.

### 클린 쿼리 예시

원본 쿼리는 수정하지 않고 출력 계약을 명시한 형태만 기록한다.

```sql
SELECT HISTORY_ID,
       CAR_ID,
       START_DATE,
       END_DATE,
       CASE
           WHEN DATEDIFF(END_DATE, START_DATE) + 1 >= 30 THEN '장기 대여'
           ELSE '단기 대여'
       END AS RENT_TYPE
FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY
WHERE START_DATE >= '2022-09-01'
  AND START_DATE < '2022-10-01'
ORDER BY HISTORY_ID DESC;
```
