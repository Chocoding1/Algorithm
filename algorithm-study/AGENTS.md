# Algorithm Study Instructions

이 폴더는 Java 알고리즘 학습 코드와 회고를 함께 관리한다.

하루 기본 학습량은 월요일~토요일 기준 `Java 알고리즘 2문제 + MySQL SQL 1문제`다. 알고리즘 복습 문제와 D+7 변형은 알고리즘 2문제 안에 포함하고, SQL 재도전은 그날의 SQL 1문제 자리를 사용한다.

## 필수 처리 규칙

- 사용자가 프로그래머스 당일 문제명과 링크를 전달하면 풀이 전에 `algorithm-study/daily/YYYY-MM-DD/문제명/` 폴더를 생성한다.
- SQL 문제는 `algorithm-study/daily/YYYY-MM-DD/sql/문제명/`에 `solution.sql`과 `review.md`를 생성한다. `solution.sql`에는 `-- 프로그래머스 SQL Lv.N`, `-- MySQL` 주석과 빈 작성 영역만 두며 정답 쿼리나 힌트는 넣지 않는다.
- SQL 입문 4주 동안은 학습 문법 범주를 미리 공개할 수 있지만, JOIN 순서·서브쿼리 구조 등 정답 쿼리의 골격은 풀이 전에 노출하지 않는다.
- 문제 폴더에는 `문제명.java`와 미작성 `review.md`를 두며, Java 파일은 상단의 `// 프로그래머스 Lv.N` 난이도 주석, 공식 초기 `solution` 메서드 시그니처, 파일명과 동일한 `public class 문제명`, 공개 예시를 실행할 `main`만 포함하고 풀이·힌트는 넣지 않는다. 문제명의 공백은 밑줄로 바꾼다.
- 문제 파일 생성 시 Codex가 문제 레벨·유형·구현량, 문제 순서의 역할, 학습자의 현재 실력과 최근 지표를 반영해 목표 풀이 시간을 정하고 `review.md`에 미리 기록한다. 목표 시간은 문제를 처음 읽기 시작한 시점부터 제출 성공까지로 계산한다.
- 목표 시간은 문제 이해·제한 20%, 단순 풀이·병목 20%, 접근 선택·풀이 흐름·정확성 20%, Java 구현 25%, 검증·제출 15%로 나눈다. 분 단위 반올림 후 합계가 목표 시간과 같도록 마지막 단계를 조정해 회고에 미리 채운다.
- `review.md`는 문제 정보·시간 배분, 풀이 전 핵심 기록, 풀이 후 결과, Codex 분석을 분리한다. 사용자는 핵심 항목을 한두 문장으로만 쓰고 Codex는 그 내용과 Java 코드를 토대로 상세 분석을 완성한다. 사용자가 적은 내용은 의미를 바꾸어 덮어쓰지 않는다.
- 2026-10-01부터 사용자의 풀이 전 필수 기록은 `문제와 제한·목표 복잡도`, `단순 풀이와 병목`, `확정한 설계와 처리 흐름`, `정답 근거와 핵심 엣지 케이스` 네 항목이다. 출제 의도 추측은 선택 항목이다. 2026-09-30까지의 기존 6항목 회고는 수정하지 않는다.
- 핵심 유형, 공식 출제 의도와 Codex 목표 알고리즘은 풀이 완료 후 기록한다. 풀이 전에는 보이는 회고나 추천 문구에 노출하지 않는다.
- 사용자의 풀이 후 필수 기록은 실제·제외 시간, 결과, 제출 결과, 힌트 수준, 설계 확정 시간, 구현 실수, 막힌 지점·배운 점이다. 상세 복잡도·오류 분류·등급·의도 비교·복습 일정은 Codex가 작성한다.
- IntelliJ에서는 `algorithm-study` Java 모듈 하나만 사용하고, 새 문제 폴더를 `.idea/algorithm-study.iml`의 소스 루트로 추가한다. 모듈은 프로젝트 SDK `temurin-21`을 상속한다.
- 같은 문제 폴더나 파일이 이미 있으면 덮어쓰거나 원본을 수정하지 않고 사용자에게 알린다.
- 사용자가 `오늘 기록해 줘`라고 요청하면 `daily/YYYY-MM-DD/` 아래 Java 코드를 먼저 확인한다.
- SQL 완료 시 `solution.sql`과 SQL 회고를 함께 확인한다. 플랫폼 제출 결과를 정답 검증의 기준으로 삼고, 로컬 DB 환경이 없는 경우 로컬 실행을 필수로 요구하지 않는다.
- 문제명, 링크, 난이도, 핵심 유형, 목표·실제 시간, 결과, 제출·힌트·설계·구현 기록, 핵심 사고 과정과 복습 결과를 기록한다.
- 코드나 기존 기록으로 확인 가능한 내용은 다시 묻지 않는다. 등급이나 객관 지표에 반드시 필요한 정보가 빠졌거나 모호할 때만 누락 질문을 한 번에 모아 확인하며, 선택 항목이나 Codex 분석란의 빈칸만으로 완료를 막지 않는다.
- 사용자의 답변을 받은 뒤에 회고, 지표, 대시보드와 ChatGPT 전달용 요약을 완성한다.
- 사용자가 요청하지 않는 한 Java 원본 코드를 수정하지 않는다.
- 사용자 회고 원문과 Codex 분석을 명확히 구분한다.
- 사용자가 문제를 풀었다고 알리면 풀이 전 메모, 최종 제출 코드와 제출 결과를 함께 비교한다. 메모에서 놓친 핵심 신호, 설계와 구현의 차이, 정답성 근거, 공식·추천 의도와의 차이, 더 나은 복잡도·자료구조·Java API·안전성 개선 중 실제 성장에 중요한 항목을 찾는다.
- 풀이 완료 피드백은 사소한 스타일 지적을 나열하지 않고 우선순위가 높은 학습점 1~3개를 `왜 필요한지 → 어떻게 동작하는지 → 복잡도·장단점 → 다음 문제에서 알아볼 신호` 순으로 가르친다. 의미 있는 추가 학습이 없으면 현재 풀이가 충분한 이유를 명시한다.
- 풀이 직후 새로 가르친 의도 알고리즘·최적화·API·정확성 근거는 `review.md`의 `풀이 후 새로 배운 점`과 `복습에 포함할 학습 포인트`에 기록하고 D+1·D+3·D+7 중 적절한 일정에 반드시 연결한다.
- 의미 있는 개선은 빅오 개선과 상수 비용·메모리·가독성·안전성 개선을 구분한다. 다른 유효한 알고리즘으로 풀었다는 이유만으로 등급을 낮추지 않는다.
- 의미 있는 클린 코드 개선점이 있으면 풀이 완료 피드백에서 개선된 `solution` 전체 또는 이해에 필요한 완결된 코드 예시를 직접 작성해 보여준다. 원본과 무엇이 달라졌는지, 빅오 개선인지 가독성·안전성 개선인지 구분해 설명한다.
- 개선 코드는 사용자의 요청 없이 원본 Java에 적용하지 않고 `review.md`와 피드백에 별도 예시로만 기록한다. 현재 코드가 이미 충분히 깔끔하거나 차이가 취향 수준이면 억지로 다시 작성하지 않는다.
- 같은 문제의 재도전은 기존 기록과 연결한다.
- 각 문제는 풀이 결과와 과정에 따라 A·B·C 등급으로 판정하고 등급별 복습 규칙을 적용한다.

## SQL 입문 운영 규칙

- 세부 진도는 `SQL_PLAN.md`를 따른다. 첫 4주는 프로그래머스 MySQL 문제를 사용하고 Lv.1에서 시작한다.
- SQL 풀이 전 사용자는 `출력해야 할 값`, `조회할 테이블과 한 행의 의미`, `행을 바꾸는 조건과 최종 정렬`을 각각 한 문장 이내로 적는다. 질문은 행 번호가 아니라 데이터 한 건의 의미와 SQL 절 전후의 행 변화를 묻는다는 점이 드러나게 작성한다.
- SQL 풀이 후 사용자는 실제·제외 시간, 결과, 제출 횟수, 힌트 수준, 오류와 배운 점만 적는다.
- Codex는 실행 순서 암기보다 `FROM/JOIN이 만든 행 → WHERE 필터 → GROUP BY 단위 → HAVING 필터 → SELECT 결과 → ORDER BY 정렬`의 데이터 흐름을 설명할 수 있는지 확인한다.
- SQL A등급은 목표 시간 안에 힌트 없이 첫 제출로 성공하고, 결과 행의 단위와 중복·NULL 영향을 설명할 수 있는 경우다.
- SQL B등급은 성공했지만 시간 초과, 작은 힌트, 오답 제출, 문법 오류 또는 결과 행의 근거가 불명확한 경우다. 2~3일 뒤 핵심 절을 5분 이내로 다시 작성하거나 설명한다.
- SQL C등급은 실패, 핵심 힌트·해설·정답 확인 또는 JOIN·그룹 단위를 독립적으로 완성하지 못한 경우다. 2~3일 뒤 그날의 SQL 1문제 슬롯에서 같은 문제를 다시 푼다.
- SQL의 A·B·C와 지표는 알고리즘 통계와 분리해서 관리한다. 초기 핵심 지표는 첫 제출 성공률, 목표 시간 달성률, 힌트 의존률, 문법 오류, 중복·NULL·JOIN·그룹 단위 오류와 재도전 성공률이다.
- SQL 쿼리가 정답이면 더 읽기 쉬운 조건, 불필요한 서브쿼리 제거, JOIN과 EXISTS 선택, NULL 안전성 등 실제 학습 가치가 있는 개선만 설명한다.

## 풀이 등급과 차등 복습

- A등급: 목표 시간 안에 힌트·해설 없이 성공했고, 알고리즘 선택 근거가 명확하며 중대한 구현 실수나 반복적인 오답 제출이 없다. 이 조건을 모두 만족해야 한다.
  - D+1은 생략한다.
  - D+3에 핵심 신호·복잡도·엣지 케이스와 풀이 직후 새로 배운 핵심 항목이 있으면 함께 2~3분 회상한다.
  - D+7은 핵심 유형이거나 최근 취약 유형일 때만 새로운 변형 문제로 편성한다.
  - 동일 문제는 다시 풀지 않는다.
- B등급: 성공했지만 목표 시간을 크게 넘겼거나, 접근을 오래 헤맸거나, 구현 실수·오답 제출이 있었거나, 작은 힌트를 확인했거나, 알고리즘 선택 근거나 정확성을 명확히 설명하지 못한 경우 중 하나 이상에 해당한다.
  - D+1에 사용한 알고리즘의 핵심 구조·풀이 흐름·정답 조건을 설명한다.
  - D+3에 핵심 신호·알고리즘·복잡도·엣지 케이스와 풀이 직후 새로 배운 의도 풀이·최적화·API·정확성 근거를 회상한다.
  - D+7에 같은 유형의 새로운 변형 문제를 푼다.
  - 중대한 구현 실수가 있었다면 동일 문제 재구현을 추가할 수 있다.
- C등급: 실패·부분 성공, 핵심 힌트나 해설 확인, 정답 코드 참고, 또는 유형을 알았더라도 상태나 설계를 완성하지 못한 경우 중 하나 이상에 해당한다.
  - 2~3일 뒤 동일 문제를 정답 코드 없이 처음부터 재도전한다.
  - 재도전 후 D+7에 같은 유형의 새로운 변형 문제를 푼다.
  - 같은 실패가 반복되면 더 쉬운 문제로 유형을 다시 학습한다.
- 동일 문제 재도전과 D+7 변형은 하루 2문제 안에 포함한다.
- 문제 2개 외의 짧은 회상 복습은 하루 최대 2개, 총 5~10분으로 제한한다.
- 복습 우선순위는 C등급 재도전 → B·C등급 D+7 변형 → B등급 D+3 → B등급 D+1 → A등급 D+3 순이다.
- 맞힌 문제를 모두 동일 문제로 다시 풀게 하지 않는다. A등급은 동일 문제 재도전 없이 짧은 회상과 필요한 변형 문제로만 복습한다.
- 등급 판단에 필요한 정보가 부족하거나 모호하면 임의 판정하지 말고, 누락된 질문을 한 번에 모아 사용자에게 확인한 뒤 확정한다.

## 객관적 판정 기준

- 실제 풀이 시간은 처음 읽기부터 제출 성공 또는 종료까지의 경과 시간에서 1분 이상의 휴식·환경 설정·다른 용무 시간을 뺀 값이다.
- 목표 시간을 넘긴 성공은 A등급이 될 수 없고, C등급 사유가 없으면 B등급이다. 초과분이 `목표 시간의 25%`와 `10분` 중 더 큰 값 이상이면 큰 시간 초과 및 시간 관리 오류로 기록한다.
- 신규 문제의 첫 공식 제출이 통과해야 첫 시도 성공이다. 첫 통과 전 오답·시간 초과·런타임 오류·컴파일 오류를 오답 제출 횟수로 센다.
- 실행 전에 바로 고친 단순 오타는 구현 실수에서 제외한다. 인덱스·조건·자료형·API·초기화·엣지 케이스 오류는 구현 실수이며, 핵심 흐름을 다시 작성했거나 오답·예외를 유발했다면 중대한 구현 실수다.
- 설계를 잡기 전에 목표 시간의 50% 이상을 썼거나 근거 없이 완성된 접근을 두 번 이상 폐기했다면 접근을 오래 헤맨 것으로 기록한다.
- 힌트는 `없음 / 작은 힌트 / 핵심 힌트 / 해설 / 정답 코드`로 구분한다. 알고리즘·상태·핵심 식을 노출하지 않는 사고 유도는 작은 힌트로서 B등급, 이를 직접 알려주는 핵심 힌트와 해설·정답 코드 확인은 C등급이다.
- 알고리즘 선택 근거는 입력 신호·제한·단순 풀이의 병목·선택한 방법이 제한을 만족하는 이유를 포함해야 한다. 정확성 설명은 알고리즘별로 자연스러운 근거를 사용한다. DP는 상태·점화식·초기값, 그래프는 방문·이동·종료 조건, 그리디는 선택의 안전성, 이분 탐색은 판정·범위 축소, 일반 반복은 불변식·반환 조건과 중요한 엣지 케이스를 확인한다.
- A 조건을 모두 충족하지 못한 성공은 C 사유가 없는 한 B로 판정해 미분류 구간을 만들지 않는다.
- D+7 변형 전이 성공은 같은 핵심 유형의 처음 보는 문제를 핵심 힌트·해설·정답 코드 없이 성공한 경우다. 작은 힌트를 쓴 성공은 전이 성공률의 성공 건수에서 제외한다.

## 출제 의도와 실제 풀이 비교

- A·B·C는 풀이 안정성 등급이고 의도 알고리즘 학습 여부는 별도 평가다. 다른 알고리즘을 사용했다는 이유만으로 등급을 낮추지 않는다.
- 풀이 전에는 공식 출제 의도와 Codex 추천 목표 알고리즘을 사용자에게 노출하거나 보이는 회고에 미리 채우지 않는다.
- 사용자가 피드백 전에 실제 사용 알고리즘과 자신이 생각한 출제 의도를 작성한 뒤, Codex가 공식 의도·추천 목표·실제 풀이를 비교한다.
- 플랫폼에 공식 분류나 의도 설명이 없으면 추측하지 않고 `공식 의도 명시 없음`으로 기록한다.
- 공식 의도 일치 여부와 Codex 목표 일치 여부를 각각 `일치 / 유효한 대안 / 보완 필요 / 의도·목표 명시 없음`, 대안 학습 상태를 `불필요 / 설명 필요 / 의사코드 필요 / 변형 문제 필요 / 완료`로 기록한다.
- 정확하고 제한을 충분히 만족하는 대안은 인정한다. 실제 풀이가 공식 의도나 Codex 목표와 다르면 풀이 완료 피드백에서 의도 알고리즘의 핵심 신호, 풀이 흐름 또는 의사코드, 복잡도와 실제 풀이와의 차이를 즉시 설명한다. D+3까지 설명을 미루지 않는다.
- D+3에는 풀이 완료 시 이미 설명한 의도 알고리즘을 새로 알려주는 대신, 사용자가 두 접근의 핵심 흐름·복잡도·장단점을 코드 없이 회상하고 비교하게 한다.
- 진도의 핵심 유형을 놓쳤다면 풀이 완료 시 의사코드와 예제 추적을 추가한다. 제한에 간신히 통과하거나 뚜렷하게 비효율적이면 즉시 차이를 설명하고 D+3 비교 회상과 필요한 D+7 새 변형을 편성한다.
- 풀이 직후 배운 내용은 설명으로 끝내지 않는다. 재사용 가능한 한 문장 규칙과 짧은 회상 질문으로 바꾸어 복습 일정에 넣고, 새로운 문제에 적용해야 확인되는 개념은 D+7 변형으로 전이 여부를 확인한다.
- A등급의 유효한 대안 풀이는 같은 문제로 다시 구현하지 않고 설명·의사코드 또는 새 변형으로 보완한다.
